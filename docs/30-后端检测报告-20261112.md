## 必须修复

### 1. 高：手机的旧快照会覆盖电脑刚保存的话题历史

- **作用**：`aiSessionsSave` 接收整个会话列表并保存；主聊 `study-main` 有消息合并保护，普通话题没有同等保护。
- **触发与证据**：手机和电脑读到同一话题；电脑新增一条消息并保存；手机随后提交自己较旧的列表。接口仍返回 `{ok:true}`，电脑新增的消息从文件中消失。隔离用例 `REPRO 1` 已复现。旧列表也可能缺少另一端新建的话题。
- **原因位置**：[ai-chat.ts:47](D:/project/coding_2/MiAiCoding-lite/src/main/features/ai-chat.ts:47)、[study-companion.ts:91](D:/project/coding_2/MiAiCoding-lite/src/shared/study-companion.ts:91)。`ensureMainSession` 只合并主聊，其他话题直接使用本次传入值。
- **最小修复方向**：给聊天保存增加版本检查；冲突时重读并重放本端操作。消息按稳定 ID 合并，删除话题采用明确删除操作，不能将旧列表里“没有某话题”直接解释为删除。可以复用项目已有的带版本写入思路，不需要换数据库。
- **不修的影响**：双端正常使用也可能静默丢失话题消息；仅靠保存后的广播无法阻止已经在途的旧快照。

### 2. 高：手机错过结束事件后，补到回复也无法继续发送

- **作用**：完整回复已由主进程保存；手机重连后会重新拉取聊天记录。
- **触发与证据**：手机发问后断线，回复在断线期间完成；手机重连读取到了这条回复，但错过了对应的 `done` 事件。复现中回复已显示，`isStreaming` 仍为 `true`，下一条 `sendDraft()` 返回 `false`。见 `REPRO 2`。
- **原因位置**：[server.ts:165](D:/project/coding_2/MiAiCoding-lite/src/main/remote/server.ts:165) 的事件只写给当时在线的连接，没有事件重放；[http-transport.ts:19](D:/project/coding_2/MiAiCoding-lite/src/renderer/src/remote/http-transport.ts:19) 重连只触发重读；[ai-assistant.ts:98](D:/project/coding_2/MiAiCoding-lite/src/renderer/src/stores/ai-assistant.ts:98) 更新会话时不恢复当前轮次状态。
- **最小修复方向**：重读到与当前 `turnId` 相同的最终回复时结束本端生成状态；同时让后端提供轮次完成/失败/取消状态，以覆盖“失败时没有最终回复”的情况。
- **不修的影响**：Wi-Fi 切换、手机锁屏或浏览器挂起后，可能出现“有回复但下一条发不出去”。刷新页面只能作为临时恢复方式。

### 3. 高：同一个 ACP 连接同时建立两个新话题时丢失输出

- **作用**：ACP 用于连接外部 AI 工具；同一个客户端只有一组当前监听器和当前会话状态。
- **触发与证据**：电脑与手机在不同新话题同时发送。两次调用都在 `session/new` 返回前通过了忙碌检查，之后相互覆盖监听器；A 的内容被忽略，A 完成时又清掉 B 的监听器，B 后续内容也丢失。用例 `REPRO 4` 用假协议应答精确复现，没有调用真实 CLI。
- **原因位置**：[acp.ts:108](D:/project/coding_2/MiAiCoding-lite/src/main/study/acp.ts:108)。忙碌检查发生在 `await session/new` 之前，真正占用监听器却发生在该等待之后；[acp.ts:71](D:/project/coding_2/MiAiCoding-lite/src/main/study/acp.ts:71) 又只接受当前会话的输出。
- **最小修复方向**：进入 `prompt()` 后、第一次 `await` 前占用该 ACP 客户端的忙碌标记，在最外层 `finally` 释放。后到请求明确返回忙碌，或按连接排队。
- **不修的影响**：使用 ACP 时可能看到空回复、回复不完整；这是新会话并发窗口的问题，不能以普通单聊测试通过替代验证。

### 4. 中：聊天总记录超过 1 MiB 后，电脑能保存、手机无法发送

- **作用**：手机每次发问前提交全部会话快照，HTTP 层对所有请求统一限制 1 MiB。
- **触发与证据**：构造 80 条、每条 15,000 个英文字符的合成历史，电脑保存接口成功；同样的列表通过真实回环 HTTP `/rpc` 提交，得到 **413**。见 `REPRO 3`。限制按 UTF-8 字节计算，中文历史更容易达到；即使当前话题很短，其他话题的历史也包含在提交中。
- **原因位置**：[server.ts:45](D:/project/coding_2/MiAiCoding-lite/src/main/remote/server.ts:45)、[server.ts:103](D:/project/coding_2/MiAiCoding-lite/src/main/remote/server.ts:103)、[ai-assistant.ts:325](D:/project/coding_2/MiAiCoding-lite/src/renderer/src/stores/ai-assistant.ts:325)。
- **最小修复方向**：聊天写入改为按消息/操作提交，历史按需读取；这也有助于解决问题 1。短期若单独调整聊天请求上限，必须保留服务端体积检查并明确提示超限，不能直接取消所有接口的大小限制。
- **不修的影响**：使用一段时间后可能出现电脑正常、手机所有话题都发不出去，用户难以判断是历史体积造成。

### 5. 中：旧明文密钥迁移后，备份可能仍保留旧明文

- **作用**：旧配置中的 `apiKey` 会迁入系统加密存储，并从主配置文件清空。
- **触发与证据**：用合成旧配置与合成密钥执行真实 `createMainContext().readConfig()`；主文件中密钥变为空串，但 `config.json.bak` 仍包含该合成密钥。见 `REPRO 5`。**没有读取你的真实配置密钥，也没有认定你的当前备份一定存在这个问题。**
- **原因位置**：[context.ts:162](D:/project/coding_2/MiAiCoding-lite/src/main/context.ts:162) 清理主配置时调用通用写入；[json-store.ts:49](D:/project/coding_2/MiAiCoding-lite/src/main/store/json-store.ts:49) 会先把旧主文件复制到备份。
- **最小修复方向**：加密写入确认成功后，用不含密钥的内容安全更新主、备份两份配置；失败时保留可恢复路径。普通 JSON 的备份机制应继续保留，不能为了清密钥而取消所有备份。
- **不修的影响**：迁移完成不一定意味着磁盘上再无明文；复制用户数据或支持包时可能把遗留备份一起带走。此项是本机文件风险，不代表手机配置接口直接返回了密钥。

## 应当修复或明确的边界

### 6. 中：手机禁止直接计算，但 AI 聊天仍可间接触发本地受限计算

- **作用**：手机白名单拒绝 `studyRunMath`，但允许 `aiChatSend`。聊天处理会执行模型返回的 `study-actions` 中的 `calculate` 动作。
- **触发与证据**：假 AI 返回合法的 `calculate` 动作时，真实聊天 handler 调用了 `runMathViaMcp`。用例 `REPRO 6` 只验证调用发生，计算实现已替换为假件，未运行 Node 子进程或 Octave。其调用路径未依据桌面/手机来源做区分。
- **原因位置**：[remote-channels.ts:27](D:/project/coding_2/MiAiCoding-lite/src/shared/remote-channels.ts:27)、[remote-channels.ts:47](D:/project/coding_2/MiAiCoding-lite/src/shared/remote-channels.ts:47)、[ai-chat.ts:80](D:/project/coding_2/MiAiCoding-lite/src/main/features/ai-chat.ts:80)。
- **最小修复方向**：如果“手机不执行本机计算”是产品边界，在后端按可信调用来源限制 `calculate`，不能只隐藏按钮或拦住直接 RPC；若受限数学计算本来允许，则应明确说明范围并补充测试。
- **不修的影响与限制**：手机功能说明和实际可达能力不一致。数学执行器有函数白名单、脚本校验和超时，**本次没有证明可以借此执行任意系统命令**，不能把它夸大成远程任意代码执行漏洞。

## 已验证有效的保护

以下结论来自本次源码核对与对应既有测试，不是对所有潜在攻击的保证：

- 未配对时，聊天 RPC、应用资源和事件流需要认证；非白名单接口被拒绝。
- 配对凭证和浏览器身份只保存摘要，Cookie 使用 HttpOnly、SameSite；重新配对与撤销会处理已有事件流。
- POST 有同源检查；静态资源有路径围栏；入口页不长期缓存，带哈希资源可缓存。
- 手机配置响应隐藏 API Key、本机工具路径；直接代码运行、改配置和远程管理接口不在手机白名单。
- HTML 预览通过独立沙箱及禁止网络请求的 CSP 限制能力。
- AI 流式 HTTP 层拒绝重定向，并处理超时、取消、流体积限制；未使用真实上游进行验证。
- 主聊有历史保护，学习状态存储有备份恢复与结构校验；这些不能替代普通话题的并发保护。

### 关于 IP 记录

本地手机服务的 `devices.ts` 持久化结构包含设备/浏览器摘要、令牌摘要和时间，不包含连接 IP；网卡地址用于运行时展示。本次也没有运行真实 IP/DNS 查询。

**独立云端账号服务是另一条链路**：`server/src/lib/audit.ts` 定义了带 `ip` 的认证审计记录，认证路由会传入 `request.ip`；这不等于本地手机配对功能记录 IP。本次未连接云服务、未读取其数据库，不能据源码断言你当前线上保存了哪些记录。
