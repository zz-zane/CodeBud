## Windows 打包与 GitHub Releases 发布（自动更新）

1. **本地打包（不自动上传）**：

   ```bash
   npm run package:win
   ```

   该命令会执行 `npm run build && electron-builder --win nsis --x64 --publish never`，在 `release/` 下生成：
   - `CodeBud-<版本>-setup.exe`
   - `CodeBud-<版本>-setup.exe.blockmap`
   - `latest.yml`

   > **打包策略说明**：当前 `build.files` 排除了 `node_modules`，`electron-updater`（及 `builder-util-runtime` / `fs-extra` / `js-yaml` 等运行时依赖）通过 [electron.vite.config.ts](../electron.vite.config.ts) 中的 `externalizeDepsPlugin({ exclude: ['unpdf', 'electron-updater'] })` 直接打进主进程产物 `out/main/app.js`，未修改 `build.files`；该方式已在 Windows NSIS 安装包中实测运行通过。

2. **创建正式版本 Release（供自动更新拉取）**：

   务必将 **`.exe`、`blockmap`、`latest.yml` 三个文件一起**传到同一个 GitHub Release（`zz-zane/CodeBud`），并使用 `--latest` 标记为最新正式版：

   ```bash
   gh release create v0.2.0 \
     release/CodeBud-0.2.0-setup.exe \
     release/CodeBud-0.2.0-setup.exe.blockmap \
     release/latest.yml \
     --title "v0.2.0" \
     --notes "更新说明..." \
     --latest
   ```

3. **上传非应用资源 Release（例如六级听力音频包）**：

   非应用发布（如 `cet6-audio-*`）**禁止**抢占 Latest 标签，否则可能影响发布页检查与自动化脚本；务必显式传 `--latest=false`：

   ```bash
   gh release create cet6-audio-v1 <音频压缩包> --latest=false
   ```
