## 0. 0.2.0 版错在哪

| 现象 | 原因（都是方案的错，不是实现的错） |
|---|---|
| 「只是文字 + 配音」 | 校验器强制 4 张纯文字卡（困惑 / 类比 / 易错 / 总结），一段视频大半是字 |

| 学员要先读思路再确认 | 把「先确认大纲」搬给了正在卡住的人 |
| 生成过程看不见 | 一个只有「取消」的弹窗 |
| 每课都有视频按钮 | 没有判断「这个问题适不适合用动画」 |

## 1. 重做后的原则

1. **只在有「看不见的状态在变」时才做动画**：内存、指针指向、调用栈、数据结构变形、执行跳转。问定义、问语法、问 API 的，用文字答，不做动画。
2. **没有文字页**。每一步都必须是一个在变化的画面；困惑、易错、总结都用「画面 + 一句字幕」表达（易错 = 把错的写法演一遍，看它坏在哪）。
3. **代码和内存同屏、同步**：左边代码走到哪一行，右边内存就在那一刻变化。
4. **类比是画出来的**：同一套格子换一层「皮」（柜子 / 草稿纸 / 车厢），再原地变回真实内存，让学员看见「门牌号 = 地址、纸条 = 指针」。
5. **看 → 走 → 猜**：先看类比动起来，再跟着真实代码走一遍，关键一步之前先让学员猜。
6. **一段只讲一个机制**，10–18 步，约 60–100 秒。
7. **卡住的人不做选择题**：不展示思路、不要确认，直接生成；不满意点「换一种讲法」。

## 2. 画面模型（`src/shared/video.ts`，整体替换旧的四种场景）

```ts
export const VIDEO_FILE_VERSION = 2
export type VideoSkin = 'memory' | 'locker' | 'sheet' | 'train'

export interface ExplainerVideo {
  id: string
  title: string              // ≤ 30 字，写「学员会发现什么」，不写章节名
  question: string
  concept: string            // 这段只讲的那一个机制，≤ 20 字
  lessonId?: string
  source: 'ai' | 'builtin'
  createdAt: number
  acts: VideoAct[]           // 1–3 幕
  codeVerified: boolean | null
}

export interface VideoAct {
  title: string              // ≤ 16 字，动宾短语：「顺着纸条找柜子」
  skin: VideoSkin
  code?: { lang: VideoLang; lines: string[]; expectedOutput: string }   // 有它 = 左侧显示代码
  steps: VideoStep[]         // 每步给完整画面状态
}

export interface VideoStep {
  say: string                // 字幕，8–60 字；代码与符号放在反引号里，写真实符号（`*p`），不写读法
  line?: number              // 高亮的代码行（1 起），本幕有 code 时必填
  groups: { id: string; title: string; kind: 'frame' | 'heap' | 'array' | 'plain' }[]   // 从左到右，≤ 4
  cells: { id: string; group: string; name?: string; addr?: string; value: string; dim?: boolean }[]   // ≤ 12
  arrows: { from: string; to: string }[]
  focus?: string[]           // 聚光：其余格子变暗
  fly?: { from: string; to: string; text: string }   // 一个值从 A 飞到 B（复制、传参、读出）；to 可为 'out'
  note?: { at: string; text: string }   // 贴在某个格子旁的短标注，≤ 20 字
  out?: string               // 程序到此为止的输出
  ask?: { stem: string; options: string[]; answer: number; why: string }   // 播放到这一步**之前**先停下让学员猜
}
```

**皮（`skin`）只改长相，不改结构**：

| skin | 用于 | 格子长什么样 | 箭头源头的格子 |
|---|---|---|---|
| `memory` | 真实内存 | 名字 / 地址 / 值 | 普通格子 |
| `locker` | 地址、指针、数组 | 带门牌号的柜子 | 一张纸条 |
| `sheet` | 调用栈、递归 | `frame` 组是一张张叠起来的草稿纸 | — |
| `train` | 链表、引用链 | 一节节车厢 | 车钩 |

相邻两幕里 `id` 相同的格子**位置不变、只换皮**（柜子原地变成内存格），这是「类比 → 真实」的关键镜头。

**引擎按 `id` 对比相邻两步，自动产生动画**（`prefers-reduced-motion` 或设置里关了动效时全部直接到位）：

| 变化 | 动画 | 时长 |
|---|---|---|
| 新增格子 / 组 | 淡入并从 0.9 放大；`frame` 组从上方滑入（入栈） | 300ms |
| 移除格子 / 组 | 淡出；`frame` 组向上滑出（出栈） | 250ms |
| 值变了 | 旧值上滑淡出、新值下滑淡入，格子闪一次强调色 | 400ms |
| 新增箭头 | 沿路径画出来 | 450ms |
| 箭头换了目标 | 箭头头部沿弧线摆到新目标 | 500ms |
| `fly` | 一个写着 `text` 的小标签从源格子飞到目标格子 | 600ms |
| `focus` | 其余格子降到 35% 不透明度 | 200ms |
| `line` 变了 | 高亮条滑到新的一行 | 200ms |
| 换皮 | 格子外观交叉淡化，位置不动 | 500ms |

同一步里先播动画、旁白同时开始；动画与旁白都结束后停 350ms 再进下一步。用仓库已有的 `animejs`，不加依赖。

## 3. 校验器 `validateVideo`（规则全部重写）

1. 1–3 幕；总步数 8–18；按 4.5 字/秒估算 40–110 秒。
2. **每一步至少有 1 个格子**（没有纯文字步）。
3. **相邻两步画面必须不同**（`line` / `groups` / `cells` / `arrows` / `focus` / `fly` / `note` / `out` 至少一项变化）。
4. 至少一幕带 `code`；带 `code` 的幕每步必须有 `line`，且在行号范围内；代码 ≤ 20 行、每行 ≤ 70 字符。
5. 全片至少 1 个、至多 3 个 `ask`；选项 3–4 个，`answer` 在范围内，`why` 非空。
6. 全片至少出现 1 次箭头或 `fly`（否则说明这个问题不需要动画）。
7. `cells[].group` 必须是当前步存在的组；`arrows` / `focus` / `fly` / `note.at` 引用的 `id` 必须存在（`fly.to` 可为 `'out'`）。
8. `say` 里不得出现「星号」「取地址符」「箭头」这类符号读法（见 §6 旁白）。
9. 字数、数量上限按 §2 注释；所有文本按纯文本渲染，禁止 `v-html`。

**旧数据迁移**（铁律 6）：`videos.json` version 1 → 2，新纯函数 `migrateVideoV1(v)`：`trace` 场景 → 带 `code` 的一幕，`vars` 变成 `frame` 组里的格子；`memory` → `stack` / `heap` 两组；`array` → 一个 `array` 组；`card` 的 `say` 并入下一幕第一步的字幕（没有下一幕则丢弃该卡并写日志）；`checks` 挂到最后一步的 `ask`。迁移后的旧视频不重新校验规则 1–6，只校验 7、9。未知版本只读不写（沿用 `docs/33` 审查后的规则）。`source: 'demo'` 与 `demoToVideo` 删除。

## 4. 内置概念动画（离线可用，不花 token）

位置 `content/animations/<id>.json`（内容唯一真源），`build:content` 打进 bundle。**这是「有用的视频」的主体**：数量少、逐个打磨、代码真跑过。

第一批 9 个，只覆盖初学者最容易卡住的抽象点：

| id | 讲什么 | 类比皮 | 语言 |
|---|---|---|---|
| `c-pointer-basics` | `&` 和 `*`：指针里存的是地址 | locker | C |
| `c-pointer-swap` | 传值换不了、传指针才换得了 | locker | C |
| `c-pointer-array` | `p + 1` 为什么是下一个元素 | locker | C |
| `call-stack` | 调用一次压一层，`return` 弹一层 | sheet | C |
| `recursion` | 递归先一路压栈、再一路返回 | sheet | Python |
| `py-names` | Python 变量是贴在对象上的名字（列表别名） | train | Python |
| `java-reference` | 传进方法的是引用的副本 | locker | Java |
| `linked-list-insert` | 链表插入为什么要先连后断 | train | C |
| `for-loop-order` | `for` 的四步到底谁先谁后 | memory | C |

## 5. 按需生成（在聊天里，直接生成）

**入口只有三个，全部进 AI 助教聊天**：聊天框模式选「动画讲解」后发送；课文划词菜单「用动画讲明白」；答错后的「用动画讲这道题」。后两个自动带上选区 / 题目作为上下文并直接发送。

**一个 IPC**：`videoGenerate({ requestId, question, lessonId?, excerpt?, lang?, avoid? })`，主进程内部两步，过程经 `videoProgress` 推送，**不向学员要任何确认**（代码运行确认除外，见下）：

1. **判断**（一次小请求，提示词附内置目录）→ `{ mode: 'builtin' | 'generate' | 'text', builtinId?, concept, misconception, scenario, skin }`
   - `builtin`：问题就是某个内置概念 → 直接返回它，零等待。
   - `text`：没有状态在变（问定义 / 语法 / 报错含义）→ 返回 `{ kind: 'text', reason }`，聊天自动改用「完整解释」回答，并在回答前加一行「这个问题用文字讲更清楚」。
   - `generate`：继续第 2 步。
2. **生成**：提示词含 §2 的字段契约 + `c-pointer-basics` 作范例；解析 → 形状归一化 → `validateVideo` → 真跑代码核对 → 不合格带错误清单修一次 → 仍不合格返回失败。

提示词硬要求：只讲 `concept` 一个机制；`scenario` 必须是带具体数字的小场景（「两个同学的分数想交换」），不许用 `foo` / `x` / `tmp1`；先用所选的皮演类比，再换 `memory` 皮跑真实代码；关键一步前放 `ask`；易错点用「演一遍错的写法」表达；输出必须确定（沿用禁止打印地址 / 时间 / 随机数的规则）。

**进度事件** `videoProgress: { requestId, stage: 'judge' | 'design' | 'verify' | 'done', status: 'running' | 'ok' | 'failed', detail? }`。

**安全边界不变**：手机不可调用 `videoGenerate`；核对运行沿用现有 runner 的确认策略，需要确认时在聊天里的进度卡内联显示代码与「运行并核对 / 跳过」；取消只结束本次任务的子进程。删除 `videoOutline` 通道与 `VideoGenerateDialog.vue`。

**聊天里的呈现**（画框 01–03）：
- 发送后，助手位置出现一张**进度卡**：三行阶段（判断适不适合用动画 → 设计分镜 → 在本机运行代码核对），当前行转圈并显示已用秒数，可取消。
- 完成后进度卡原地变成**动画卡**：首帧缩略图、标题、时长、「播放」。写入会话的是助手消息里的围栏 ` ```anim-card ` + `{"videoId": "…"}` 或 `{"builtinId": "…"}`，由 `ai-rich-blocks.ts` 解析。
- 失败：卡片显示原因与「重试」「改用文字讲」。
- 播放器结尾提供「换一种讲法」（带 `avoid` 重新生成，结果作为新的一条助手消息）。

## 6. 播放器与「这一步没懂」

- 布局（画框 04–06）：有代码的幕 = 左代码、右画面；没代码的幕 = 画面占满。下方一行字幕，底栏控件。左侧不再有场景列表，改为顶部的幕标题分段条。
- **猜一猜**：播到带 `ask` 的一步之前自动暂停，字幕区换成题目与选项；选对选错都给 `why`，然后播放这一步作为揭晓。答题结果在有 `lessonId` 时写入练习史（`mode: 'video-check'`）。
- **这一步没懂**（画框 07）：播放器收起，AI 面板打开并附上当前步的上下文标签，输入框**只填一次**「这一步我没看懂：」（现在会重复追加，要修）；输入框上方、上下文标签那一行出现**续播条**「▶ 继续播放 · 标题 · 第 6/14 步 ✕」。**删除右下角悬浮的「返回视频」按钮**（它盖住了发送键）。
- **旁白**：字幕显示真实符号；朗读前用纯函数 `speechText(say)` 把反引号里的符号换成读法（`*p` → 「星号 p」、`&a` → 「取地址 a」、`->` → 「箭头」、`==` → 「等于等于」等，一张小表，带单测）。旁白默认开，可关。
- 控件：播放 / 暂停、上一步 / 下一步、倍速（0.75 / 1 / 1.25 / 1.5，用自绘分段或弹出菜单，**不用原生下拉**）、旁白开关、「这一步没懂」、关闭。键盘同前。
- 手机（画框 10）：竖屏，代码在上、画面在中、字幕在下。

## 附录：`c-pointer-basics` 分镜（小样，也是生成提示词的范例）

标题「指针里存的是门牌号」，`concept`「指针存地址，`*` 顺着地址找值」。

**第一幕「顺着纸条找柜子」** `skin: locker`，无代码

| 步 | 画面 | 字幕 |
|---|---|---|
| 1 | 组「柜子」里两个柜子：门牌 100（值 5）、门牌 104（值 空） | 内存像一排带门牌号的柜子，每个柜子里放一个值。 |
| 2 | 100 号柜出现名字 `a`；聚光它；标注「门牌 100，里面是 5」 | 这个柜子门牌是 100，里面放着 5，它就是变量 `a`。 |
| 3 | 新增组「纸条」，纸条 `p` 写着 100；箭头 `p` → 100 号柜画出来 | 再拿一张纸条，上面只写门牌号 100。这张纸条就是指针 `p`。 |
| 4 | **猜**：「顺着纸条 `p` 找过去，拿到的是什么？」5 / 100 / 纸条本身（答 5）。揭晓：`fly` 5 从 100 号柜飞到 `out`，输出 `5` | 顺着纸条上的门牌找到柜子，打开拿到 5。这一步叫解引用。 |
| 5 | `fly` 9 从纸条飞到 100 号柜；柜里的值 5 → 9；纸条不变 | 也可以顺着纸条走到柜子前，把里面换成 9。纸条上的字没变。 |

**第二幕「换成真正的代码」** `skin: memory`，格子 `id` 与第一幕相同（原地换皮）

```c
#include <stdio.h>
int main(void) {
    int a = 5;
    int *p = &a;
    printf("%d\n", *p);
    *p = 9;
    printf("%d\n", a);
    return 0;
```
