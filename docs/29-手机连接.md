# 29 · 手机连接

> 2026-11-11 定稿。目标：电脑上的咪爱编程开着时，手机浏览器能学习电脑端的全部学习资料并使用 AI，进度与电脑是同一份。

## 1. 方案与取舍

**电脑端应用自己开一个本机 HTTP 服务，手机浏览器直接加载同一套界面。** 不做独立 App、不做第二套界面、不建任何外部服务器。

| 场景 | 怎么连 | 成本 |
|---|---|---|
| 同一个 Wi-Fi | 手机浏览器打开设置页显示的局域网地址 | 0 |
| 外出 | 电脑与手机各装一个**组网工具**（Tailscale / ZeroTier 这类，个人免费），两台设备进同一个虚拟局域网，手机打开设置页显示的那个虚拟网卡地址 | 0，流量走组网工具的加密隧道 |

外出访问**不由本应用实现**：应用只负责监听本机所有网卡，组网工具让手机「像在同一个局域网里」。这样不违反铁律 3（零自建服务器）、不把电脑暴露到公网、也没有持续费用。设置页列出本机所有 IPv4 地址，组网工具的虚拟网卡地址自然在其中。

**明确不做**：内网穿透 / 中继服务、HTTPS 证书、二维码（要新增依赖）、手机离线使用（电脑关了就不能用）、手机上运行代码、多用户。

## 2. 安全模型

服务默认**关闭**，在设置页由用户打开。打开 = 局域网与组网内的设备都能连到这个端口，所以：

1. **配对**：打开服务时生成一个 6 位数字配对码显示在电脑的设置页。手机第一次打开地址看到的是配对页，输对配对码后服务端下发一个 256 bit 随机设备令牌（`HttpOnly; SameSite=Strict` cookie，有效期 180 天），并**立刻换一个新配对码**。令牌只存哈希（SHA-256）在 `<数据目录>/remote-devices.json`。
2. **防猜**：配对码输错累计 5 次，配对入口锁 10 分钟（按全局计，不按 IP —— 局域网里 IP 不可信）。
3. **每个请求都验令牌**（静态资源、RPC、事件流、试卷与音频），未配对一律只给配对页。`POST` 另验 `Origin` 与 `Host` 同源。不开任何 CORS。
4. **通道白名单**（默认拒绝）：手机只能调用「学习 + AI」相关通道，名单在 `src/shared/remote-channels.ts`。**不在名单里的一律 403**：运行代码 / 取消运行、打开本机 IDE、导出文件、任何会弹系统对话框的通道（选音频目录、导入资料、导出）、`config:save`（含 API Key）、环境检测、研学的外部连接（ACP）管理、云结算。加新通道时默认手机不可用，要开放必须显式进名单。
5. 设置页将“已配对设备”与“最新登录”分开展示。设备条目显示浏览器/系统摘要、设备编号和首次配对时间；最新登录显示设备及登录时间（配对成功或已认证浏览器成功打开应用入口页），普通资源请求、RPC、SSE 重连不算登录。可逐个撤销设备；关闭服务不清配对，「撤销全部」才清。

   设备清单 v1 → v2：新增独立的浏览器身份哈希、令牌签发时间、最新登录快照。配对成功后另下发一年有效的 `miai_browser` HttpOnly Cookie，只用来识别重复配对，不能单独授权访问；访问令牌仍为 180 天。相同标识重复配对时更新原条目、轮换访问令牌并关闭原事件流，保留首次配对时间，令牌有效期从本次签发计算。旧设备持原访问令牌成功打开应用页时自动补发浏览器标识；持旧令牌重新配对也可沿用原条目。无法凭相同 User-Agent 断定两条旧记录来自同一硬件，因此不自动合并历史条目，只有经用户确认的重复记录才可合并。更换浏览器、访问地址或清除 Cookie 后可能重新登记；不采集硬件指纹。最新登录快照不因撤销设备而倒退到其他旧记录。
6. 请求体上限 1 MB；路径围栏复用 `file-protocol.ts` 的 `pathFence`。
7. 局域网内是明文 HTTP —— 同一 Wi-Fi 下的其他人能看到流量，这一点在设置页的说明里写明；经组网工具时由它加密。
8. **本应用从不修改防火墙或任何网络配置**。服务第一次监听所有网卡时，Windows 可能自己弹出防火墙提示，允许与否由用户决定，应用不替用户点、也不添加规则。验证与调试时可设环境变量 `MIAI_REMOTE_HOST`（字面 IP，如 `127.0.0.1`）让服务只绑定那一个地址，此时设置页的地址列表只显示该地址、不枚举网卡；未设置时默认 `0.0.0.0`，地址列表在设置页取状态且服务开着时才枚举网卡（不落盘、不写日志）。
9. **不保存连接 IP**：本机地址仅在内存中供设置页显示，不写入配对清单、最新登录或访问日志，不做公网出口 IP 查询。设备识别使用随机浏览器标识，不使用 IP。持久化只保留明确列出的设备字段，忽略请求中的 IP、转发地址头及旧数据中的额外 IP 字段。测试使用固定文档示例地址，不记录用户的实际网络地址。

### 3.1 一份 API 定义，两种传输

现在 `window.miai` 的形状写在 `src/preload/index.ts` 里，直接调 `ipcRenderer`。改为：

```ts
// src/shared/miai-api.ts
export interface MiaiTransport {
  invoke(channel: string, ...args: unknown[]): Promise<unknown>
  on(channel: string, listener: (payload: unknown) => void): () => void
  remote: boolean
}
export function createMiaiApi(t: MiaiTransport) { return { getProfile: () => t.invoke(IPC.profileGet), …, remote: t.remote } }
```

- preload：`contextBridge.exposeInMainWorld('miai', createMiaiApi(ipcTransport))`，行为与现在逐方法一致（含注释搬家）。`preload/index.d.ts` 已删除，`Window.miai` 的类型直接取 `miai-api.ts` 的 `MiaiApi`，不再手写第二份。
- 手机端：`createMiaiApi(httpTransport)`，`invoke` = `POST /rpc {channel, args}`，`on` = 订阅一条 `EventSource('/events')`。
- `window.miai.isRemote`（布尔）是渲染层判断「我在手机上」的唯一依据（原稿叫 `remote`，改名是为了不与管理口 `window.miai.remoteAdmin` 混淆）。渲染层统一经 `lib/asset-base.ts` 的 `isRemote()` 读它。
- 手机连接的管理口挂在 `window.miai.remoteAdmin`（`getStatus / setEnabled / setPort / revokeDevice / revokeAll / regenerateCode`），仅电脑端可用，不在白名单里。

### 3.2 主进程：handler 登记表

`features/*.ts` 里的 `ipcMain.handle(IPC.x, fn)` 全部换成 `handle(IPC.x, fn)`（`src/main/ipc.ts`，内部调 `ipcMain.handle` 并 `registry.set`）。docs/28 §2 规矩 1 与 IPC 契约闸门相应改为「`handle(` 只出现在 `features/` 下」。

远程调用 = 从登记表取 handler，传入一个**仿事件对象** `{ sender: { send(channel, payload), isDestroyed() } }`，`send` 把推送发到**发起这次调用的那台设备**的 SSE 连接（AI 对话的流式输出就是这样回到手机）。`broadcastPublicConfig` 额外向所有 SSE 连接广播，手机上的设置变化与电脑保持一致。

聊天保存后，主进程向桌面窗口与已配对手机推送不带聊天正文的 `ai:sessions-changed` 通知，各端重新读取共享聊天记录；手机事件流首次连上或重连后也会补读。接收端等待本地保存结束，并丢弃本地编辑期间返回的旧读取结果，保留当前对话、草稿、标签和流式状态，不因收到通知再次保存，避免同步循环。完整 AI 回复由主进程在发送 `done` 前落盘，即使发起手机关闭页面仍能在电脑读取；回复以本轮 `turnId` 作为消息 ID，发起端再保存时不会重复插入。逐字流式输出仍只送发起端，其它端显示保存后的完整回复。

局域网 HTTP 页面不提供 `crypto.randomUUID()`；消息、会话和附件编号统一由 `client-id.ts` 使用该环境可用的 `crypto.getRandomValues()` 生成 UUID v4，不降低随机数强度。`node scripts/phone-http-chat-qa.cjs` 使用隔离配置、真实构建页面和 HTTP 服务、模拟 AI 回复，验证普通 HTTP 手机界面点击发送后，另一端能显示问题与回复；不读取用户聊天、配对记录或 API Key。

RPC 的参数与返回值都是 JSON；handler 抛错时回 `{ ok: false, error: message }`，手机端传输层把它还原成 rejected Promise（与 `ipcRenderer.invoke` 的表现一致）。

### 3.3 资源地址

| 桌面 | 手机 |
|---|---|
| 界面：`file://…/out/renderer/index.html` | `GET /`（同一份构建产物，gzip，带缓存头；`index.html` 不缓存） |
| `miai-cet6://data/<路径>` | `GET /cet6/data/<路径>` |
| `miai-cet6://media/<路径>`（Range） | `GET /cet6/media/<路径>`（Range） |
| `miai-study://preview/<id>` | `GET /study/preview/<id>` |

服务端这三条路由复用现有协议 handler 的实现（抽出与传输无关的「给定路径 → Response」函数：`cet6AssetResponse`、`htmlPreviewById`，协议与 HTTP 各包一层），不复制逻辑；各功能在 `register` 里把自己的 HTTP 路由登记进 `ctx.httpAssets`（前缀 → handler），服务按前缀转发，所以服务本身不认识六级或研学。HTTP 版不发 CORS 头，Range 照常支持。渲染层只在几处生成这些地址（`shared/cet6.ts` 的 `mediaUrl(src, base)`、`stores/cet6.ts` 的两个 `fetch`、研学预览的 iframe 地址），统一经 `lib/asset-base.ts` 的 `assetBase()` / `studyPreviewUrl()` 取前缀。

**研学预览的隔离**：预览是用户 / AI 生成的 HTML，桌面端放在沙箱 iframe 里。经 HTTP 提供时用响应头 `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; …`（与桌面协议同一份 `STUDY_HTML_CSP`）：`sandbox` 指令不带 `allow-same-origin`，文档是不透明源，读不到应用源的任何状态、不能带令牌发同源请求；设备令牌 cookie 本身又是 HttpOnly，是第二道。选响应头而不是 iframe 属性，是因为属性在页面脚本侧，响应头对直接访问该 URL 同样生效。

### 3.4 配置与界面

- `AppConfig` 加 `remote: { enabled: boolean; port: number }`（默认关、端口 17600；`config-schema.ts` 条目 + 版本 22 + 版本表一行）。端口被占用时启动失败要在设置页如实显示，不静默换端口。
- 设置面板加一页「手机连接」（只在桌面端显示）：开关、端口、可用地址列表（每个地址一个复制按钮，标出哪些是局域网、哪些可能是组网工具）、当前配对码、已配对设备与撤销、三行使用说明（同 Wi-Fi / 外出用组网工具 / 明文提示）。
- 手机端：没有 preload 时先请求 `/session`；未配对 → 渲染配对页（一个数字输入框）；已配对 → 装 `window.miai` 后照常启动应用。

### 3.5 手机上隐藏什么

`window.miai.remote === true` 时，不渲染调用了非白名单通道的入口：运行代码与代码编辑相关的运行按钮、练习场、本机 IDE、环境检测、设置里的 AI Key 与手机连接页、音频目录选择、资料导入导出、Markdown 导出。代码阅读、判分不依赖运行的题目照常可用。入口隐藏是体验问题，**安全靠 §2 的白名单**，两者独立。

**入口清单（2026-11-11 复核，手机上全部不渲染）**：课文页底栏「运行代码」按钮、课文代码块的「运行」按钮（`lib/md.ts` 渲染时按 `isRemote()` 直接不生成，所有走 `renderMarkdown(…, true)` 的页面一并生效）、对比块的「运行试试」（`CompareGrid`）、练习页「代码练习场」卡片、练习场（`RunnerPanel`：运行 / 本地 IDE / 导出代码，只留一行「需要在电脑上使用」）、答题页代码题的「运行」按钮（`QuizCodeRun`，同样只留说明）、研学的导入 / 导出 / 数学计算 / 外部连接、备忘的 Markdown 导出、设置里的环境检测 / AI 密钥 / 手机连接页（`SettingsView` 挂载时也不再自动 `env:detect`）、六级音频目录选择、云结算（`challenge` store 直接跳过）。

**本机路径不给手机（显示 + 数据）**：六级目录页不再显示「听力音频目录：<路径>」，目录缺失时显示中性的「听力音频需在电脑上设置目录」，没有路径也没有选择按钮。数据侧在远程服务出口统一脱敏（`src/shared/remote-redact.ts`，`server.ts` 的 `/rpc` 返回值与 SSE 推送都经过它，桌面窗口不经过）：`cet6:get-state` 的 `media.root` → `null`（`ok` 保留）；`config:get` / `config:external` 的 `nativeIdePaths` 清空、`envCache.report[*].path` 去掉；`study:get-state` 的外部连接 `command` / `args` 清空。已核对：研学资料的 `StudyMaterial` 只有文件名没有路径；导出目录 / 导出文件路径只出现在手机上已隐藏的导出入口里。

## 4.1 手机操作体验

新页面、新浮层、新输入区都按下面的规则写。规则全部只在手机宽度（≤ 768px，`isPhone`）生效，桌面不受影响；样式一律写在 `styles/phone.css`。

### 页面切换

- **底部标签栏**（`PhoneTabBar.vue`）：取侧栏主导航（`lib/nav-items.ts` 的 `NAV_ITEMS`）的前五项，标签、图标、顺序与侧栏一致；放不下的（总览）和设置留在抽屉里。当前项由 `navGroupOf(path)` 决定，侧栏与标签栏共用这一份分组映射，不要另写。高度 56px + `env(safe-area-inset-bottom)`。页面区（`.claude-body-layout`）整体让出标签栏的高度，所以正文、悬浮球、课文底栏都在它上方，不用逐个页面补内距。**不显示**：六级做题页、考试锁开着、全屏浮层（答题层、全屏 AI 面板、设置）；键盘打开时只隐藏、占位保留（页面不跳）。
- **转场**（`App.vue`，方向与层级在 `lib/phone-nav.ts`）：标签 ↔ 标签即时切换、不动画；进入列表 → 详情（任何比顶层更深的页面）新页从右滑入约 220ms、旧页左移少许，后退反向。两页同时在 DOM 里，离开的页面在 `before-leave` 里量出位置后改成 `position: fixed`，布局不跳。方向取 `history.state.position`（变大前进、变小后退，相等 / 未知即时）。`prefers-reduced-motion` 下一律即时。桌面保持 `mi-route` + `out-in`。
- **滚动记忆**：真正的滚动容器是 `.claude-app-container .content`（不是 window）。离开路由时按 `fullPath` 记下 `scrollTop`（`lib/scroll-memory.ts`，有容量上限），后退回到该页恢复，前进进入的页面从顶部开始。自己管滚动的整页视图（`fullBleed`：`/ai`、六级做题页）不在这套里。
- **顶栏**：详情页（`routeDepth > 0`：课程目录、备忘、收藏、六级词汇、课文、六级试卷等）用返回键代替抽屉键；返回走历史，没有应用内历史（书签直接打开）时回到 `parentRouteOf(path)`。顶层页面显示抽屉键。手机不渲染「后退 / 前进」按钮（用系统返回）。
- **触摸手感**：去掉系统点按高亮，按钮 / 行 / 标签有 `:active` 按下态（令牌）；`touch-action: manipulation` 去掉双击缩放延迟（捏合缩放保留）；内部滚动容器 `overscroll-behavior: contain`，不带动整页、不触发下拉刷新。

### 系统返回先关浮层

`lib/phone-back-close.ts` 的 `usePhoneBackClose(isOpen, close)` 是唯一实现，已接在：导航抽屉、手机上的全屏 AI 面板、`/ai` 的学习上下文层、`MiModal`（设置对话框复用它）、`MiDrawer`、答题层（返回 = 点「退出」，弹确认而不是直接丢进度）、六级选词释义卡片、六级写作的「题目」浮层。新浮层要么复用 `MiModal` / `MiDrawer`，要么自己调这个函数，**不要**手写 `history.pushState`。

- 浮层打开压一条历史记录（沿用当前 `history.state` 的 vue-router 字段，只多一个标记）；系统返回在捕获阶段先于 vue-router 截住 `popstate`，改为关浮层。
- 自带关闭按钮关浮层时用 `history.back()` 把那条记录消费掉；历史里不累积。浮层拒绝关闭（不可关闭的弹窗、答题要先确认）则补回那条记录。
- 浮层开着时的路由跳转（抽屉里点导航等）由 `installOverlayRouterGuard` 先退掉浮层记录、等 `popstate` 回来再补做跳转，vue-router 不会在浮层记录之后 push；它排在六级离开确认守卫之后，不改那条守卫的行为。
- 多层浮层中下层先被关掉，它的记录留在栈里，等上层退出时一并回退。
- 桌面宽度下整个机制不动 `history`。

### 软键盘：布局永不因键盘而改变

这是硬规则：**软键盘弹出时，页面布局不重算**（窗格不减半、栏不跳）。只有「正在输入的那一块」自己让位。

- `index.html` 的 viewport 为 `interactive-widget=resizes-visual`，且不禁用用户缩放；壳层高度恒为 `100dvh`。
- `lib/keyboard-inset.ts` 订阅 `visualViewport` 的 `resize` / `scroll`（rAF 节流，iOS Safari 不认 `interactive-widget` 也靠它），把 `innerHeight − visualViewport.height − offsetTop` 写进根元素的 `--mi-kb-inset`（关闭时 0；双指放大不算键盘），超过 120px 时给根元素加 `kb-open`。
- 在容器上还有两个派生量：`--mi-tabbar-h`（标签栏占位）与 `--mi-kb-lift = max(0, kb-inset − tabbar-h)`。输入区抬升读 `--mi-kb-lift`；弹窗这类贴满视口的浮层读 `--mi-kb-inset` / `--mi-vh-avail`（`100dvh − kb-inset`），高度让到键盘上方。
- **AI 输入框**（课文页 AI 面板、`/ai` 工作区）：输入区整体 `translateY(-lift)`，对话列表底部内距加同样的量；对话贴底时保持贴底，不贴底的不动。发送 / 停止按钮 `pointerdown` 阻止默认行为，点它不会让输入框失焦，发送后键盘保持打开。
- **六级写作 / 翻译**：作答框聚焦且键盘打开时进入「专注作答」：作答区占满键盘上方，题目收成一条横栏，「查看题目」把它展开成浮层（下沿贴键盘），失焦还原分屏（比例与原文滚动位置不变）；字数统计一直可见。
- **其他输入**（备忘、研学笔记、搜索框、弹窗 / 抽屉 / 设置里的输入）：`lib/phone-focus.ts` 在聚焦后（键盘动画期间量两次）只滚输入框最近的那个滚动容器，让它落在键盘上方；滚动容器有 `scroll-padding-bottom: var(--mi-kb-inset)`。自己管键盘的区域加 `data-kb-managed` 即可跳过这套通用逻辑。
- 键盘开着时：标签栏、AI 悬浮球、课文底栏隐藏（占位不变），关闭后回来；顶栏等固定头部不动。
- 输入框 / 文本域 / 下拉框在手机上字号 ≥ 16px，iOS 聚焦时不缩放。
- 点非交互区域会让当前输入框失焦（收键盘）。

### 未在真机验证

以上在桌面 Chromium 里只有静态与单元测试覆盖，没有真机；真实软键盘、系统返回手势、iOS Safari 的 `visualViewport` 行为需要在手机上走一遍。

## 5. 第一期实现与定稿的差异

| 原稿 | 实际 | 原因 |
|---|---|---|
| `window.miai.remote` | `window.miai.isRemote` + 管理口 `window.miai.remoteAdmin` | 避免与管理口命名冲突 |
| 配对码 / 锁 / 设备清单等纯函数放 `remote-channels.ts` | 放 `remote-auth.ts`，`remote-channels.ts` 只放白名单 | 前者要 import `node:crypto`，渲染层会 import 后者，分开更干净 |
| `GET /session` 未配对返回配对状态 | 未配对返回 401 `{paired:false}` | 「未配对一律拿不到数据」 |
| 开发模式 | 若 `out/renderer/index.html` 存在就出最近一次生产构建，否则状态里报 `no-renderer` | 开发时渲染层在 Vite dev server 上，没有可直接出的目录 |
| 白名单之外的拒绝名单 | `remote-channels.ts` 同时导出 `REMOTE_DENIED_KEYS`，测试强制每个 IPC key 恰在两张名单之一 | 新增通道必须有意识地做决定 |
| 手机上的设置保存 | `config:save` 被拒，所以手机上的设置改动只在本次页面内生效（`stores/settings.ts` 在 `isRemote` 时不调保存） | 避免每次改布局都弹保存失败；API Key 不能从手机改 |
| 手机上的云结算 | 跳过（`cloud:challenge-settle` 被拒），留给电脑端 | 同上 |
| 研学数学计算 | 拒绝并隐藏标签页（`study:run-math` 会启动本机 Octave） | 等同运行本机程序 |
| `study:get-state` / `study:get-usage` / `ai:test-connection` | 前两者允许（只读）；`ai:test-connection` 拒绝（只属于设置页） | |
| `MIAI_REMOTE_HOST` | 新增：绑定地址覆盖（字面 IP），见 §2-8 | 回环验证，避免触发防火墙提示 |
