# 34 自动更新

> 状态：方案定稿，待实现。在 `feat/video-loop` 合入 `codebud` 之后，从 `codebud` 开分支 `feat/auto-update`。
> 界面稿：`docs/33-ui/update.html`、`u01.png`、`u02.png`（Figma 同一文件，页面「UI 定稿 v1」画框 15、16）。

## 0. 结论

- 用 **electron-updater**（electron-builder 官方配套，纯 JS，无原生依赖）+ **GitHub Releases** 作更新源。不建服务器。
- 启动后自动检查 → 后台自动下载 → 下载完提示「重启后生效」→ 退出应用时自动安装。全程不打断学习。
- 断网、被墙、源不可用：**静默失败，只写日志**，不弹窗、不阻塞（铁律 3）。
- 更新只换程序文件。`appId` 不变（`com.miai.biancheng`），用户数据目录不变，学习数据不受影响。
- 已安装的 0.1.1 没有更新器，**必须手动装一次带更新器的版本**，之后才会自动更新。

## 1. 更新源

`package.json` 的 `build` 增加：

```json
"publish": [{ "provider": "github", "owner": "zz-zane", "repo": "CodeBud" }]
```

打包后 `release/` 里会多出 `latest.yml` 和 `CodeBud-<版本>-setup.exe.blockmap`。**发版时三个文件都要上传到同一个 release**：`CodeBud-<版本>-setup.exe`、`.blockmap`、`latest.yml`。

**同仓库里还有听力音频的 release（`cet6-audio-v1`）**。更新器读的是 GitHub 标为「Latest」的那个 release，所以：
- 应用版本的 release 一律用 `gh release create v<版本> --latest` 创建；
- 以后再发音频类 release 一律加 `--latest=false`。
- 这两条写进 `docs/25` 的发版步骤。

打包命令只生成文件，不自动上传（`electron-builder --publish never`）。上传仍是人工确认后的单独一步。

## 2. 行为

新文件 `src/main/update/updater.ts`（逻辑）+ `src/main/features/update.ts`（IPC，登记进 `features/index.ts`）。

| 时机 | 做什么 |
|---|---|
| 启动后 15 秒，之后每 6 小时 | `config.update.auto` 为真且 `app.isPackaged` 时检查更新 |
| 发现新版本 | 后台下载（`autoDownload = true`），不提示 |
| 下载完成 | 推送状态给界面，显示更新条：「新版本 x.y.z 已下载，重启后生效」+「立即重启」「稍后」 |
| 点「立即重启」 | `quitAndInstall()` |
| 点「稍后」或不理会 | 下次退出应用时自动安装（`autoInstallOnAppQuit = true`） |
| 任何一步出错 | 状态置为 `error`，写日志；**不弹窗**。设置页手动检查时才显示错误原因 |

- 开发模式（`!app.isPackaged`）不检查；手动点「检查更新」时返回「开发模式不检查更新」。
- 只接受比当前版本新的正式版（`allowPrerelease = false`、`allowDowngrade = false`）。
- 更新包完整性由 electron-updater 用 `latest.yml` 里的 sha512 校验。应用目前未做代码签名，所以不配置发布者校验；这一点写进 `docs/12`。
- 正在答题 / 考试计时中不主动弹任何东西：更新条只出现在今天页和设置页顶部，不盖在练习、六级考试、视频播放器之上。

**状态**（`src/shared/update.ts`）：

```ts
export type UpdateStatus =
  | { state: 'idle' }
  | { state: 'checking' }
  | { state: 'latest'; checkedAt: number }
  | { state: 'downloading'; version: string; percent: number }
  | { state: 'ready'; version: string }
  | { state: 'error'; message: string }
  | { state: 'unsupported'; reason: 'dev' | 'platform' }
```

**IPC**（进 `ipc-channels.ts`、`miai-api.ts`；手机一律不可用，进 `REMOTE_DENIED_KEYS`）

| 通道 | 作用 |
|---|---|
| `updateGetStatus` | 取当前状态与当前版本号 |
| `updateCheck` | 手动检查（不受 `auto` 开关限制） |
| `updateInstall` | 立即重启安装（仅 `ready` 状态有效） |
| `updateStatus` | 主进程 → 界面的状态推送 |

## 3. 配置

`AppConfig` 新增 `update: { auto: boolean }`，默认 `true`。走 `CONFIG_FIELDS` 注册表 + `config-migrate.ts` 新增一步 + bump `CURRENT_CONFIG_VERSION`，带迁移测试。

## 4. 界面

- **设置页新增「关于与更新」分区**（画框 15）：当前版本号、「自动更新」开关、「检查更新」按钮、状态行（已是最新 / 正在下载 37% / 新版本已下载 / 检查失败及原因）、「查看更新说明」链接到 GitHub Releases 页面。
- **更新条**（画框 16）：今天页与设置页顶部的一行提示，可关闭；关闭后本次运行不再出现，退出时照常安装。
- 手机连接下不显示这两处。

## 5. 依赖与打包

- 新增依赖 `electron-updater`（先读 `docs/12`，并在其中记一条【可直接复用】，标注【实测】）。
- 当前 `build.files` 排除了 `node_modules`，主进程是整体打包的。先尝试把 `electron-updater` 打进主进程产物；若打包后运行报缺模块，再把它（及其运行时依赖）加入 `build.files`，并在回报里写明选了哪种。
- 版本号改为 `0.2.0`。

## 6. 验收（不发布任何东西）

1. `npm run typecheck`、`npm test`、`npm run validate:content` 全过；`updater.ts` 的状态流转用假的 autoUpdater 做单测；迁移测试覆盖旧配置读入后 `update.auto === true`。
2. **本机端到端**：打一个 `0.2.0` 安装包并安装到隔离目录；再把版本临时改成 `0.2.1` 打第二个包，把 `latest.yml` + 安装包 + blockmap 放进本机目录，用本机 HTTP 服务（`127.0.0.1`）提供；通过 electron-updater 支持的本地覆盖配置（`dev-app-update.yml` 或环境变量指定 generic 源，**仅测试用，不进发布包**）让已安装的 0.2.0 指向它。确认：自动发现 → 下载 → 更新条出现 → 重启后版本号变为 0.2.1 → 隔离目录里的学习数据原样保留。
3. 断网启动：无弹窗、无报错界面，日志里有一条检查失败记录。
4. 关掉「自动更新」：启动后不检查；手动「检查更新」仍可用。
5. 测试结束后把版本号改回 `0.2.0`，清理本机测试源与临时安装目录。**不 push、不建 release、不改 GitHub 上任何东西。**
