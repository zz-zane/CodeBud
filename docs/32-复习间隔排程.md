# 32 · 复习间隔排程

> 2026-11-13 定稿。把「复习到期」从「学过但今天没练的课」改成按遗忘曲线排程。不新增数据文件、不改任何 schema：排程**完全由现有数据推导**（`profile.learnedAt` + `practice.json` 的练习史）。

## 1. 为什么

现在的「到期」= 复习池里今天还没练过的课。学得越多数字越大、永远清不完，它不反映「哪些快忘了」，时间一长这个数字就没人看了。间隔重复的做法是：刚学的隔天复习，记住了就把间隔拉长，忘了就缩短。

## 2. 规则（课为单位）

### 2.1 常量（`src/shared/review-schedule.ts`）

| 常量 | 值 | 含义 |
|---|---|---|
| `REVIEW_INTERVALS_DAYS` | `[1, 3, 7, 14, 30, 60]` | 第 0–5 档的间隔（自然日）。最高档之后一直是 60 |
| `REVIEW_PASS` | `0.8` | 当天该课正确率 ≥ 0.8 算「记住」 |
| `REVIEW_FAIL` | `0.5` | 正确率 < 0.5 算「忘了」 |
| `REVIEW_DAILY_CAP` | `15` | 每天最多安排复习的课数，其余顺延 |

### 2.2 一课的排程怎么算

输入：这课的 `learnedAt`（ISO，可能缺失或是回填的 epoch 0）、练习史里所有包含这课题目的作答、今天的日键。日键一律用项目现有的本地日键函数（`shared/dates.ts`），不自己算时区。

1. **起点**：`anchor` = `learnedAt` 的日键；`learnedAt` 缺失或早于 2000 年（回填值）时，`anchor` = 这课最早一次练习的日键；连练习都没有时 `anchor` = 今天。初始 `stage = 0`，`due = anchor + 1 天`。
2. **复习事件**：把练习史按本地日分组，每一天里这课的所有作答合成一个事件 `{ day, ok, total }`（`total ≥ 1`），正确率 `acc = ok / total`。事件按日期升序依次处理，`day < anchor` 的事件忽略。学课当天（`day == anchor`）的作答也算事件。
3. **每个事件的处理**：
   - `acc < REVIEW_FAIL`（忘了）：`stage = max(0, stage − 1)`，`due = day + INTERVALS[stage]`。**无论是否到期都生效** —— 提前练也能暴露遗忘。
   - 否则，若 `day < due`（提前练）：`stage` 与 `due` 都不变。提前练对了不加分，防止靠同一天反复刷把间隔刷长。
   - 否则（到期或逾期后练的）：`acc ≥ REVIEW_PASS` → `stage = min(5, stage + 1)`；`REVIEW_FAIL ≤ acc < REVIEW_PASS` → `stage` 不变。两种情况都 `due = day + INTERVALS[stage]`。
4. **输出**：`{ lessonId, stage, due, lastDay | null, overdueDays }`，`overdueDays = max(0, today − due)`（自然日差）。`due ≤ today` 即到期。

### 2.3 今天复习哪些

- **到期集合**：复习池（`poolLessonsOf` 的结果，即学过且有题的课）里 `due ≤ today` 的课。
- **排序**：`overdueDays` 降序 → `stage` 升序 → `lessonId` 升序（稳定、可测）。
- **今日份** = 排序后的前 `REVIEW_DAILY_CAP` 课，其余留到明天（它们仍是到期的，明天会排在更前面）。
- 今天已经处理过的课（今天有事件且处理后 `due > today`）自然不在到期集合里；今天练了但因为答错仍 `due ≤ today` 的不会出现（答错后 `due = today + INTERVALS[stage] ≥ today + 1`）。

## 3. 界面

### 3.1 「今天」页与侧栏徽标

- 「复习到期」一行的数字、侧栏「复习」徽标、手机标签栏的徽标 = **今日份的课数**（≤ 15）。
- 该行说明仍是到期最多的两个模块（按今日份统计）。到期总数超过今日份时，这一行的 `title` 写 `共 N 课到期，今天先复习 15 课`。
- 预计分钟：复习项的系数从每项 40 秒改为每课 60 秒（一课通常抽到 1–2 题），即 `ceil((复习课数×60 + 错题数×60 + 生词数×15) / 60 / 5) × 5`。
- 数量为 0 时该行与徽标不渲染（规则不变）。

### 3.2 复习页（`ReviewView.vue`）

- 标题下原来的池子数字改为一行状态（`--mi-fs-label`，`--mi-text-2`）：
  - 有到期：`今天到期 12 课`；总数超过今日份时 `今天到期 15 课 · 共 37 课到期`。
  - 无到期：`今天没有到期的课`。
- 模块筛选页签（全部 / 通用知识 / C / …）上的数字改为**该范围内今日份的课数**；为 0 时显示 `0`。
- 开始按钮：有到期时文案 `开始复习`，试卷**只从当前范围的今日份课里抽题**（把今日份课列表作为 `buildReviewPaper` 的 `lessons` 传入，题量、加权、错题加成等现有规则全部不变）；无到期时按钮文案 `自由复习`，行为与现在完全一样（从整个复习池抽）。
- 一次复习做完后回到复习页，数字立即按新的排程刷新（练过且达标的课已不在今日份里）。一张卷覆盖不完今日份时，学生再点一次「开始复习」即可继续，直到今日份清零。
- 空池（一课都没学）的现有空状态不变。

### 3.3 不做

逐题排程（仍以课为单位）、在课程目录或课文页显示下次复习日期、可调的间隔或每日上限设置、把排程结果落盘缓存（每次从练习史重算；5000 条练习史的量级重算是毫秒级，需要时再加缓存）。

## 4. 实现约束

- 纯函数全部在 `src/shared/review-schedule.ts`：`lessonEvents(history, lessonIds)`（一次遍历练习史，按课、按日聚合）、`scheduleLesson(...)`、`buildSchedule(...)`、`pickDueToday(schedule, todayKey, cap)`。不 import Vue / Electron。
- `src/shared/today.ts` 里现有的 `dueLessons`、`lessonsPracticedOn` 删除，调用点改用新函数；`estimateMinutes` 的复习系数按 §3.1 改。
- `lib/use-today-counts.ts` 与复习页共用同一个取数入口，不各算一遍。
- 主进程、IPC、`practice.json` / `profile.json` 的结构都不动。
