## 0. 用户要的是什么

| 要 | 不要 |
|---|---|
| **真的视频文件**（mp4/webm），能存、能重播、标好属于哪一课 | 现在那种「步进 + 猜一猜 + 点下一步」的交互播放器（docs/35） |
| 用户在设置里选的 AI，按**内置 skill** 直接生成 | 每课预先生成配套视频（只在用户要的时候生成） |
| 把**抽象概念一步步变成现实**：先看懂类比，再看类比原地变成真实内存/代码 | 文字页、只换皮不变形的类比 |
| 生成过程看得见（分镜 → 校验 → 逐帧渲染 → 保存） | 一个只有「取消」的转圈弹窗 |
| **无配音**（2026-11-21 用户明确：不需要语言解释），靠画面 + 字幕讲清 | TTS / 语音 |

## 1. 架构（一句话）

**AI 写 spec（JSON）→ 本机校验（结构 + 代码真编译真跑）→ Canvas 引擎按时间 `t` 逐帧确定性绘制 → WebCodecs 编码 + 纯 JS 封装 → 存 `<数据目录>/videos/<lessonId>/<id>.mp4` + 同名 `.json` 元数据。**

- 零原生依赖、离线可重播、不装 ffmpeg：Electron 自带 Chromium 的 `VideoEncoder`（H.264 优先，回退 VP9）+ 纯 JS 封装库（候选 `mediabunny`，MIT；引入前按 docs/12 记录【调研/实测】）。
- AI 只写**封闭词汇**的 spec，不写自由代码 —— 弱模型（DeepSeek）也能稳定产出，画面质量由引擎保证。
- 确定性：同一 spec、同一 `t` 两次渲染逐像素一致（所有随机带种子，不读 `Date.now()`）。

## 2. 样板要求：C 语言指针（`c-stage1-14 初识指针`）

**规格**：1920×1080，30fps，无声，60–120 秒，H.264 mp4。浅色底（与 app 一致的米白 `#f5f4ef` 系），一种强调色。

**叙事结构（抽象 → 现实，六幕，顺序固定）**：

| 幕 | 讲什么 | 画面（必须是动的） |
|---|---|---|
| 1 现象 | 抛出困惑：`int a = 5; int *p = &a; *p = 10;` 之后 `a` 为什么变成 10？ | 代码逐行写出；最后一行写完，`a` 的值打问号闪一下 |
| 2 类比 | 一排柜子，每个柜门有门牌号；一张纸条上写着门牌号 | 柜子从左依次入场；纸条飞入，上面写 `100`；纸条连一条线到 100 号柜 |
| 3 **变形（核心）** | 类比原地变成真实内存 | **同一位置连续形变**：柜子 → 内存格子，门牌号 `100` → 地址 `0x7ffd…10`，纸条 → 变量 `p`，柜里的 5 → `a` 的值 5。形变过程中左上角对照表逐行点亮：柜子=内存单元、门牌号=地址、纸条=指针 |
| 4 走真实代码 | 左代码右内存，同步 | 当前行高亮；`int a = 5` 内存出现格子；`&a` 地址从格子上「取下来」飞到 `p` 里；`*p = 10` 箭头顺着走过去，格子里 5 → 10（数字滚动 + 格子闪一下） |
| 5 易错 | 未初始化指针 / `p = 10` 与 `*p = 10` 的区别 | 把错的写法演一遍：箭头指向一片「未知区域」，格子碎裂/画红叉；对比正确写法 |
| 6 收束 | 一屏总结 | 对照表定格：类比 ↔ 真实 ↔ 代码（纸条 ↔ 指针 ↔ `p`，门牌号 ↔ 地址 ↔ `&a`，顺着纸条开柜 ↔ 解引用 ↔ `*p`） |

**画面规矩**（来自 huashu 09 §三，按本项目改）：
1. 一屏一个焦点：同一时刻只让一个东西入场，其余静止或变淡。
2. 颜色 = 概念，全片不换：地址一种颜色、值一种颜色、指针一种颜色，超过 3 种语义色就记不住。
3. 入场慢（0.3–0.5s）退场快（≈0.2s），落定后停 ≥0.8s；缓动用 `smooth = 6t⁵−15t⁴+10t³`。
4. 形变是**同一个对象连续插值**（位置、尺寸、圆角、颜色、文字交叉淡化），不是淡出再淡入新东西。
5. **字幕**代替配音：底部字幕带（不与画面元素重叠，留 `safe.bottom ≈ 180px`），一次一句 ≤ 24 字，停留时长 ≥ 字数/6 秒 + 1 秒。代码与符号用等宽字体并上色。
6. 文字可读：正文 ≥ 32px，代码 ≥ 30px；中文字体用系统自带（微软雅黑）或打包字体，不依赖 macOS 字体。
7. 每一步都有东西在变（除落定停顿外，连续 3 秒以上完全静止算缺陷）。

**代码必须真跑**：幕 1/4 的程序用本机 gcc 编译运行，输出与画面上写的一致（`printf("%d\n", a);` 输出 `10`）。

## 3. spec 草案（v1，样板做完后由 Claude 定稿进 skill）

```jsonc
{
  "version": 1,
  "lessonId": "c-stage1-14",
  "title": "指针里存的是门牌号",          // ≤ 20 字，写「学员会发现什么」
  "concept": "指针 = 存地址的变量",
  "fps": 30, "width": 1920, "height": 1080,
  "palette": { "address": "#2f6fd6", "value": "#c96a2b", "pointer": "#1f9d8b" },
  "code": { "lang": "c", "lines": ["#include <stdio.h>", "..."], "expectedOutput": "10\n" },
  "acts": [
    {
      "id": "analogy", "title": "柜子和纸条",
      "steps": [
        { "caption": "内存像一排柜子，每个柜子都有门牌号", "hold": 2.5,
          "do": [ { "op": "enter", "id": "cell-a", "type": "cell", "skin": "locker", "addr": "100", "value": "5" } ] },
        { "caption": "纸条上只写了一个门牌号", "hold": 2,
          "do": [ { "op": "enter", "id": "p", "type": "cell", "skin": "note", "value": "100" },
                  { "op": "arrow", "from": "p", "to": "cell-a" } ] }
      ]
    },
    {
      "id": "reveal", "title": "柜子就是内存",
      "steps": [
        { "caption": "柜子其实就是内存格子，门牌号就是地址", "hold": 3,
          "do": [ { "op": "morph", "id": "cell-a", "skin": "memory", "addr": "0x7ffd10" },
                  { "op": "morph", "id": "p", "skin": "memory", "label": "p", "value": "0x7ffd10" },
                  { "op": "map", "row": ["柜子", "内存单元"] } ] }
      ]
    }
  ]
}
```

- `op` 封闭词汇（样板实现时可增删，最后以引擎实际支持为准）：`enter` `exit` `morph` `set`（改值，数字滚动）`arrow` `unarrow` `focus` `line`（高亮代码行）`write`（逐字写出代码/文字）`break`（错误演示：碎裂/红叉）`map`（对照表加一行）`title`。
- `type`：`cell`（带 `skin`: `locker` | `note` | `memory` | `box`）、`code`、`text`、`table`。
- 时间轴由 `steps[].hold` 累加得出，AI 不写绝对秒数（避免算错）；引擎给每个 `op` 分配入场时长。

## 5. 生成过程可视化（进 app 时实现）

六个阶段一条横向流水线，每段有真实进度，不做假进度条：
1. 读取课程（标题 + 大纲 + 课文要点）
2. AI 写分镜：流式显示，每解析出一幕就长出一张幕卡（幕名 + 步数）
3. 校验：结构校验逐条打勾；代码真编译真跑，显示实际输出与预期对比
4. 逐帧渲染：左边实时预览画布（正在渲染的那一帧），下面帧计数 `412 / 2160`，胶片条每秒抽一张缩略图长出来
5. 编码封装：已写入 MB
6. 保存：显示存到哪一课，按钮「播放」「打开所在章节」
