## 学习目标

本课学习高级宏技巧与条件编译。重点包括宏的边界、条件编译、调试开关。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 宏的第一种：不带传入的条子

最老实的宏就是给一个数起个名字：

```c
#include <stdio.h>

#define FISH_PER_CAT 3

int main(void) {
    int cats = 4;
    printf("%d 个对象，一共要 %d 条数据\n", cats, cats * FISH_PER_CAT);
    return 0;
}
```

```text
4 个对象，一共要 12 条数据
```

`#define FISH_PER_CAT 3` 这一行没有分号，也不占内存 —— 它只是墙上的条子。源代码里写 `FISH_PER_CAT` 的地方，编译器开工前统统换成 `3`，所以最后算的是 `4 * 3`。

好处是「只改一处」：哪天想让每个对象多分一条，只动墙上那张卡就行，源代码里一个字都不用找。往后你会看到，大写字母加下划线的名字（`FISH_PER_CAT`）是给宏起名的老规矩，为的是让读源代码的对象一眼认出「这是照抄的条子，不是函数」。

## 边界一：传入和整体，都要穿小括号

带传入的宏，长得像函数：

```c
#define DOUBLE(x) x * 2
```

它抄的时候是**连传入一起照抄**的。所以要是你传入的不是一个数、而是一个式子，事情就热闹了：

```c
#include <stdio.h>

#define DOUBLE_BAD(x) x * 2
#define DOUBLE_GOOD(x) ((x) * 2)

int main(void) {
    printf("不带括号：%d\n", DOUBLE_BAD(1 + 2));
    printf("带括号：%d\n", DOUBLE_GOOD(1 + 2));
    return 0;
}
```

```text
不带括号：5
带括号：6
```

`DOUBLE_BAD(1 + 2)` 抄出来是 `1 + 2 * 2` —— 乘号先算，成了 `1 + 4 = 5`，而我们明明是想要 `(1 + 2) * 2 = 6`。`DOUBLE_GOOD` 抄出来是 `((1 + 2) * 2)`，括号把它夹住了，答案才对。

这里头其实有**两层**括号，少一层都会漏：

- **传入各穿一层**：`(x)` —— 管住「传入的式子别被扯开」。
- **整体再穿一层**：`( ... )` —— 管住「整个结果别被外面的运算消耗」。

整体那一层最容易被忘。看这段：

```c
#include <stdio.h>

#define HALF_BAD(x) (x) / 2
#define HALF_GOOD(x) ((x) / 2)

int main(void) {
    printf("不带括号：%d\n", 100 / HALF_BAD(4));
    printf("带括号：%d\n", 100 / HALF_GOOD(4));
    return 0;
}
```

```text
不带括号：12
带括号：50
```

`HALF_BAD` 的传入穿了括号，看着挺像样，可整体光着 —— `100 / (4) / 2` 从左往右算成了 `12`。`HALF_GOOD` 才是我们要的 `100 / 2 = 50`。

::: warn 注意
带传入的宏，**每个传入都穿衣、整体再穿衣**，这是死规矩。少穿一层，编译器不会报错、不会警告，它只会照抄出一句你没写过的式子，然后安安静静地算错。上面两个例子里，不带括号的版本都印出了一个**看着很像那么回事**的数（5、12）—— 这才是它最坏的地方。
:::

## 边界二：宏会把传入算两遍

函数是**先算好传入再进门**；宏是**照抄**，抄几遍就写几遍。要是一个宏里某个传入出现了两次，那个传入就会被算两遍：

```c
#include <stdio.h>

int fish = 5;
int take_one(void) {
    fish = fish + 1;
    return fish;
}

#define BIGGER(a, b) ((a) > (b) ? (a) : (b))

int main(void) {
    int biggest = BIGGER(take_one(), 3);
    printf("最大的是 %d，容器里现在是 %d\n", biggest, fish);
    return 0;
}
```

```text
最大的是 7，容器里现在是 7
```

`BIGGER` 的条子上，`a` 出现了两次。抄完以后成了「先比一比、再挑一个」，于是 `take_one()` 被调用了**两遍**：容器从 5 变成 6、又变成 7，`biggest` 拿到的是第二遍的 7。我们只想喂一条数据，结果喂掉了两条。

换成真函数就没事了 —— 函数**进门之前**传入只算一次：

```c
#include <stdio.h>

int fish = 5;
int take_one(void) {
    fish = fish + 1;
    return fish;
}

int bigger(int a, int b) {
    return a > b ? a : b;
}

int main(void) {
    int biggest = bigger(take_one(), 3);
    printf("最大的是 %d，容器里现在是 %d\n", biggest, fish);
    return 0;
}
```

```text
最大的是 6，容器里现在是 6
```

同样是「挑大的那个」，喂一条就是一条。**所以：带传入的条子，传入里别放「算一次就会变一点」的东西**（自增、收输入、调用函数都属于这一类）。真要放，就老老实实改成函数写。

## 边界三：好几句话的宏，要用 `do { ... } while (0)` 包起来

宏还能一次抄好几句话。可它一旦被塞进 `if` 后面，就会出事。我们真写了这么一段，编译器当场翻不下去：

```c
#include <stdio.h>

#define REPORT(msg) { printf("收货：%s\n", msg); printf("记账完毕\n"); }

int main(void) {
    int fish = 7;
    if (fish > 3)
        REPORT("数据");
    else
        printf("今天没收到\n");
    return 0;
}
```

```text
main.c: In function 'main':
main.c:9:5: error: 'else' without a previous 'if'
```

抄出来的样子是 `if (fish > 3) { ... }; else ...` —— **花括号后面那个分号把 `if` 收尾了**，后面的 `else` 就没了主，编译器不干了。

规矩的写法是拿一对「跑一次的圈」把它包住：

```c
#include <stdio.h>

#define REPORT(msg) do { printf("收货：%s\n", msg); printf("记账完毕\n"); } while (0)

static void deliver(int fish) {
    if (fish > 3)
        REPORT("数据");
    else
        printf("今天没收到\n");
}

int main(void) {
    deliver(7);
    deliver(2);
    return 0;
}
```

```text
收货：数据
记账完毕
今天没收到
```

`do { ... } while (0)` 外加一个分号，整段就成了**一句话**：它既能顶在 `if` 后面不散架，自己也算收过尾了。那个 `while (0)` 的意思是「这圈只跑一次」—— 它的用处不是转圈，是**把一摊子话绑成一句**。

## 条件编译：开工前就定下来的岔路口

有些岔路，是编译器**开工之前**就要选好的 —— 选完的那一半源代码根本不会被翻译。这就是条件编译。

最常用的是调试开关：

```c
#include <stdio.h>

#define DEBUG 1

int main(void) {
#if DEBUG
    printf("[调试] 元素里的数现在是 %d\n", 7);
#endif
    printf("处理完成\n");
    return 0;
}
```

```text
[调试] 元素里的数现在是 7
处理完成
```

把墙上那张卡改成 `#define DEBUG 0`，同一个源代码就变成：

```c
#include <stdio.h>

#define DEBUG 0

int main(void) {
#if DEBUG
    printf("[调试] 元素里的数现在是 %d\n", 7);
#endif
    printf("处理完成\n");
    return 0;
}
```

```text
处理完成
```

开关一关，那行调试用的字**在翻译之前就被扔掉了** —— 不是「跑了但不印」，是**压根没进源代码**。所以正式版里它连一点点影子都不留，这也是它比 `if` 强的地方。

⚠️ 这里最容易踩的是**两个开关长得像、判的东西不一样**：

| 写法 | 判的是 |
|---|---|
| `#if DEBUG` | `DEBUG` 的**值**：`0` 就是关 |
| `#ifdef DEBUG` | `DEBUG` **有没有定义过** —— 哪怕写成 `0`，在它眼里也算「有」 |

所以 `#define DEBUG 0` 配 `#ifdef`，开关是**关不掉的** —— 关了也照样印。想判值就用 `#if`，想判「这条卡贴没贴」才用 `#ifdef`。老已有实现的源代码里常写 `#ifndef NDEBUG`，读作「没贴 `NDEBUG` 这张卡的时候就干活」，正式发布时只要在翻译命令里塞一个 `-DNDEBUG`（等于从外面贴一张卡上去），所有调试的话就一起消失了。

::: tip 提示
今天记三件事：**宏是开工前照抄的条子**，抄的是字不是意思；**传入和整体都要穿小括号**，少一层就静悄悄算错；**条件编译是开工前定下的岔路**，`#if` 判值、`#ifdef` 判有没有定义。最要紧的一句：宏出错时编译器**往往一次不吭**，所以别指望它替你抓，自己把括号数清楚。
:::
