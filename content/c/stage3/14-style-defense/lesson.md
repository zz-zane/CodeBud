## 学习目标

本课学习代码风格与防御性编程。重点包括命名与格式、防御检查、边界条件、可读性。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 起名与格式：让别人一眼看懂

```c
#include <stdio.h>

int main(void) {
    int fish[3] = {2, 3, 4};
    int total = 0;
    int biggest = fish[0];
    for (int i = 0; i < 3; i++) {
        total += fish[i];
        if (fish[i] > biggest) {
            biggest = fish[i];
        }
    }
    printf("一共 %d 条，最多的一元素 %d 条\n", total, biggest);
    return 0;
}
```

```text
一共 9 条，最多的一元素 4 条
```

这段没什么花招，可它**读得下去**。起名三条口诀：

1. **名字要说清里头保存的是什么**：`total` 是「合计」、`fish` 是「那一排元素」、`i` 是「这一圈的编号」。写成 `a`、`b`、`x1` 省不了几个字，三天后连你自己都不认识。
2. **一个名字只担一件事**：`total` 就一直当合计用，别一会儿又拿它去装别的数 —— 那是最容易出「看着对、其实错」的地方。
3. **别起只差一两个字母的名字**：`total` 和 `totals`、`fish` 和 `fisn`，读起来像双胞胎，认错只是迟早。

格式是同一件事的另一面：缩进**一个样**、一行**只干一件事**、该空行的地方空一行。编译器不看格式脸色，可**读的人**会 —— 格式乱的地方，虫最爱躲。

## 防御检查：进门先验货

先看这一段**没验货**的源代码：

```c
#include <stdio.h>

int biggest(int fish[], int count) {
    int best = fish[0];
    for (int i = 1; i < count; i++) {
        if (fish[i] > best) {
            best = fish[i];
        }
    }
    return best;
}

int main(void) {
    int fish[3] = {7, 2, 5};
    printf("三元素：%d\n", biggest(fish, 3));
    printf("一元素都没有：%d\n", biggest(fish, 0));
    return 0;
}
```

```text
三元素：7
一元素都没有：7
```

看第二行：「一元素都没有」的时候，它印的是 `7` —— 那是**第一元素里的数**（这一格确实存在，上面刚放进去 `7`），可**这一排按说压根是空的**哇！问题不在「读坏了地方」：函数开头写的是 `int m = fish[0];`，**它压根没问 `count` 是几**，张嘴就掏第一格。所以这不是内存脏了，是**函数自己没把规矩讲清楚**：「一个都没有的时候，答案该是什么？」它没答，就顺手把第一格端出来了。

（这种错比印错更吓人：它不报错、不崩，**换台机器也照样印 `7`** —— 稳定地给你一个没人规定过的答案。规矩得自己立：进门先验货。）

改法就是**进门先验货**：

```c
#include <stdio.h>

int biggest(int fish[], int count) {
    if (count <= 0) {
        return -1;
    }
    int best = fish[0];
    for (int i = 1; i < count; i++) {
        if (fish[i] > best) {
            best = fish[i];
        }
    }
    return best;
}

int main(void) {
    int fish[3] = {-2, -3, -4};
    printf("三元素全是负数：%d\n", biggest(fish, 3));
    printf("只有一元素：%d\n", biggest(fish, 1));
    printf("一元素都没有：%d\n", biggest(fish, 0));
    return 0;
}
```

```text
三元素全是负数：-2
只有一元素：-2
一元素都没有：-1
```

门口那三行是**守卫**：`count <= 0` 的时候，压根不往后走。`-1` 是我们跟称呼它的人约好的暗号 —— **条数不可能是负数**，所以看见 `-1` 就是「这活儿干不了」。有了守卫，空的一排元素也印得出话，而且印的是**约好的那句话**。

守卫就摆在函数**刚进门的地方**，一眼能看见。摆在中间、藏在跑圈里，读的人不知道你到底验没验。

## 边界条件：空、一个、还有「全是最边上的值」

「边界」就是**最边上那几种情形**：一排元素是空的（`0` 只）、只有一个、全是最边上的数（比如全是欠账）。这些情形平时不出现，写源代码的人最容易想不到 —— 一出现就出洋相。

我们的必查清单：

- **一个都没有**：空的时候该印什么、该返回什么回去？（先验货，再干活）
- **只有一个**：跑圈从第二元素起（`i = 1`）的写法，遇上一个元素会不会一圈都不跑、把结果漏了？
- **全是最边上的值**：这条最阴。求「最多的一元素」时，我们一开始把王座上的**初始值写成了 `0`**：

```c
#include <stdio.h>

int main(void) {
    int fish[3] = {-2, -3, -4};
    int best = 0;
    for (int i = 0; i < 3; i++) {
        if (fish[i] > best) {
            best = fish[i];
        }
    }
    printf("最多的一元素：%d\n", best);
    return 0;
}
```

```text
最多的一元素：0
```

这一排里压根**没有 `0`** 这位客人，它却坐了整场。改法是：初始值就取这一排里**真实存在的第一元素**（上面守卫版里那句 `int best = fish[0];` 就是这一手），再从第二元素开始比。记住这句：**初始值要从真实存在的数里挑**，别凭空写一个「觉得差不多」的。

## 可读性：出了问题要「说得出话」

```c
#include <stdio.h>

int average(int total, int count) {
    if (count <= 0) {
        return -1;
    }
    return total / count;
}

int main(void) {
    int total = 9;
    int avg = average(total, 3);
    printf("平均一元素 %d 条\n", avg);
    avg = average(total, 0);
    if (avg < 0) {
        printf("这组数不对，我们算不出来\n");
    }
    return 0;
}
```

```text
平均一元素 3 条
这组数不对，我们算不出来
```

注意分工：

- **函数**：干不了就返回暗号回去（`-1`），别自作主张印一堆东西 —— 万一称呼它的人正指望着印在别处呢；
- **门口**：看见暗号，负责**跟主人说一句话**。上面那句「这组数不对，我们算不出来」是 `main` 说的。

注释也照这个分工写：写**为什么**这么办（「条数不可能是负数，所以拿 `-1` 当暗号」），别写「这是一行加法」—— 那行代码自己会说。

还有一条容易忘的：**临时的打印**、试完不用的旧写法，交稿之前收走。它们不吭声，可下一个读源代码的对象会被绊一跤。

::: tip 提示
交稿之前，我们会挨着问自己这四句：

1. **名字**能不能让三天后的自己看懂？（`total`、`fish`、`i` 这种，比 `a`、`x1` 省下的时间多得多）
2. 进门**验货**了吗？（传入不合法、变量租不到、一排元素是空的 —— 不合格就别往下走）
3. **边上**的情形试过了吗？（`0` 只、`1` 只、全是负数、比预想的多一个）
4. 出了岔子，**谁负责说话**？（函数返回暗号、门口跟主人交代）

四条全过，这份源代码就不只是「跑得对」，而是**别人也敢动**。
:::
