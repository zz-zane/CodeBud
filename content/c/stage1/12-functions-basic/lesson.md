## 一、把自己的第一个方法记下来

C 里登记一个方法，得在名字前面**先把两件事说清楚**：这招返回不返回东西回来、要不要喂东西进去。先看一个最小的：

```c
#include <stdio.h>

void greet(void) {
    printf("你好\n");
}

int main(void) {
    printf("上课前\n");
    greet();
    printf("下课后\n");
    return 0;
}
```

```text
上课前
你好
下课后
```

咦，屏幕上第一条怎么是「上课前」？我们明明把 `greet` 写在最上面呀。把函数头从左往右拆开读一遍，就明白了：

- **第一个 `void`** —— 这是**结果的类型**。写 `void` 的意思是：「这一个方法只管干活，不返回任何东西回来。」
- **`greet`** —— 函数的名字，随你起。起好之后要**一个字母都不差**地称呼它，写成 `Greet` 或 `gree` 它都认不出来。
- **括号里的 `void`** —— 这是**空元素位**。写 `void` 的意思是：「这一个方法什么都不用喂。」
- **后面那对花括号 `{ }`** —— 函数身体。缩进的那一句就是它要干的活儿。
- **`greet();`** —— 这才叫**施展**（调用一次）。函数名后面跟一对小括号、一个分号，函数簿上包着的活儿就从第一句跑到最后一句。

**「登记」和「施展」是两件事** —— 这是今天的第一个坑，也是最容易摔的那个：**登记函数的时候，它一步都不会动**，编译器只是把它记在本子上。真正开动，是在 `main` 里称呼它那一下。

光登记不调用会怎样？我们真跑给你看：

```c
#include <stdio.h>

void greet(void) {
    printf("你好\n");
}

int main(void) {
    printf("我们把 greet 记在函数簿上了\n");
    return 0;
}
```

```text
我们把 greet 记在函数簿上了
```

看清楚：`你好` **一个字都没出现**。编译器心里想的是「你让我记下来，我记下来了；你又没调用我，我干嘛要动」—— 它一点毛病都没有，你也**没法从报错里看出问题**，屏幕上就是安安静静。

::: warn 注意
「忘了调用一次」是零基础最容易摔、而且**最查不出来**的坑：不报错、不警告、屏幕上什么都没有。我们教你一句自检口诀：

**屏幕上一片安静的时候，先回头看函数簿 —— 我真的调用过它吗？**

往后写的函数越多，这一条越要记牢。
:::

## 二、函数头上的第一个词：返回不返回东西回来

上一个方法的头上写着 `void`，意思是**不返回结果**。要是这招算完还有东西要交给你，那个位置就得换成**结果的类型**：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int total = add(3, 5);
    printf("%d\n", total);
    printf("%d\n", add(10, 1));
    return 0;
}
```

```text
8
11
```

- **`int add(...)`** —— 最前面那个 `int` 说的是：「这招会返回一个整数。」**它和函数里 `return` 的东西必须对得上**，这是 C 的硬规矩。
- **`return a + b;`** —— 算完 `3 + 5`，把 `8` **返回**到称呼它的那个地方。术语表里管它叫**返回值**（原文叫返回值）。
- **`int total = add(3, 5);`** —— 结果直接落进 `total` 这个元素。它和普通的数一样：**能存进变量、能接着算、能再传给别的函数**。
- **`printf("%d\n", add(10, 1));`** —— 这一趟调用函数的地方直接就是打印的输入接口，`11` 一被返回就顺手印了出去。

一句话分清楚：**头上写 `void` = 我们只干活，不带东西回来；头上写 `int` = 这招会返回一个整数给你。**

### 不返回东西的函数，你接不到

头上写了 `void`，你却伸手去接，编译器当场拦下：

```c
#include <stdio.h>

void greet(void) {
    printf("你好\n");
}

int main(void) {
    int x = greet();
    printf("%d\n", x);
    return 0;
}
```

这是它的原话：

```text
main.c:8:13: error: void value not ignored as it ought to be
    8 |     int x = greet();
```

用自然语言解释：**「这一个方法压根不返回东西回来，你怎么还伸手去接？」** —— 它连编译都不肯往下走，直接把单子退回来了。

### `return` 一执行，函数当场收工

`return` 除了返回东西，还有个脾气：**它一跑，这一个方法就结束了** —— 后面就算还排着活儿也不干了。

```c
#include <stdio.h>

void check(int n) {
    if (n > 0) {
        printf("还有数据\n");
        return;
    }
    printf("元素空了\n");
}

int main(void) {
    check(5);
    check(0);
    return 0;
}
```

```text
还有数据
元素空了
```

- 第一次调用 `check(5)`：眼色答「真」，`return` 当场收工，**下面那句打印根本没轮到**。
- 第二次调用 `check(0)`：眼色答「假」，先印那句话，再走到末尾收工。
- 注意这一个方法头上写的是 `void`，所以这里的 `return` **后面什么都不带**，光溜溜一个 `return;` —— 意思是「不返回东西，就地收工」。

所以 `return` 还有个别名：**提前收工**。想让它别急着走，就把 `return` 挪到函数的最末尾。

三个位置各司其职，一个都不能少。C 比别的语言啰嗦的地方就在这儿 —— 它**什么都要你亲口说清楚**。

## 三、参数：让函数别再写死

刚才那一个方法太死板 —— 想让三个对象各听各的那一句，就得写三个方法。我们换个写法：在函数头上先摆几个**空元素**，每个元素写个名字，施展的时候往里放东西。

```c
#include <stdio.h>

void greet(char name[]) {
    printf("你好，%s\n", name);
}

int main(void) {
    greet("张三");
    greet("李四");
    return 0;
}
```

```text
你好，张三
你好，李四
```

- **`void greet(char name[])`** —— 括号里摆了一个元素，元素上写着 `name`，前面那个 `char name[]` 说好它保存的是**字符串**。
- **`greet("张三")`** —— 施展时把 `"张三"` 这条数据**传入元素里**。这一趟跑起来，函数里的 `name` 就当作 `"张三"` 用。
- **`greet("李四")`** —— 同一个方法，第二次喂的是 `"李四"`。所以屏幕上多了一行，两行只差名字。
- 函数里的 `name` 是**函数自己内部的叫法**，和你外头建的变量互不打扰：函数跑完，这个元素也就收起来了。

**一次登记，喂什么都行** —— 这才是「打包」最值钱的地方：重复的话只写一遍，剩下的交给传入的数据。术语表里管这叫**参数**（原文叫参数）。

::: warn 注意
这里藏着一个**很大的古怪**，我们必须提前打招呼：

上面这一个方法，函数里拿到的**不是抄件** —— 字符串的元素是摊在外头的，函数伸手就能摸到原件。而普通的数字元素不一样：函数拿到的是**抄的一份**，在函数里怎么改都动不了外面那个原元素。

这两种传入**脾气完全不同**，是 C 里最要紧的一件事之一。我们下一课专门讲它，今天你只要先见一面、知道「有这么回事」就够了。
:::

### 好几个元素：按顺序一一对应

要喂两样东西，就在括号里摆两个元素，用逗号隔开：

```c
#include <stdio.h>

void report(int a, int b) {
    printf("第一位是 %d，第二位是 %d\n", a, b);
}

int main(void) {
    report(3, 5);
    report(5, 3);
    return 0;
}
```

```text
第一位是 3，第二位是 5
第一位是 5，第二位是 3
```

- 登记时 `(int a, int b)` 摆了两个元素，施展时就得喂两样，**按顺序一一对应**：第一位传给 `a`，第二位传给 `b`。
- 喂反了会怎样？写 `report(5, 3)`，编译器**不会拦你** —— 它老实照做，印出「第一位是 5，第二位是 3」。元素是照名牌收东西的，它不检查你传入的到底是不是那个意思。
- 想把名字和条数一起传入也行，摆两个元素、各写各的类型就可以：

```c
#include <stdio.h>

void greet(char name[], int count) {
    printf("%s，今天有 %d 条数据\n", name, count);
}

int main(void) {
    greet("张三", 3);
    greet("李四", 5);
    return 0;
}
```

```text
张三，今天有 3 条数据
李四，今天有 5 条数据
```

## 四、C 独有的一条硬规矩：每个元素都要写类型

这是 C 和别的语言最不一样的地方，也是最容易摔的一跤。我们故意少写一个类型给你看：

```c
#include <stdio.h>

int add(int a, b) {
    return a + b;
}

int main(void) {
    printf("%d\n", add(3, 5));
    return 0;
}
```

编译器当场拦住，这是它的原话：

```text
main.c:3:16: error: unknown type name 'b'
    3 | int add(int a, b) {
```

它说的是：**「`b` 是什么东西？我们没听说过这个名字。」** —— C 的规矩是**每摆一个元素，都要在元素前面写清楚它装什么**，一个都不能省。写成 `int add(int a, int b)` 就对了。

### 少喂一样、多喂一样，都拦住

摆了几个元素，就得喂几样。少喂一样：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    printf("%d\n", add(3));
    return 0;
}
```

```text
main.c:8:20: error: too few arguments to function 'add'; expected 2, have 1
    8 |     printf("%d\n", add(3));
```

多喂一样，它也照样翻脸：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    printf("%d\n", add(3, 5, 7));
    return 0;
}
```

```text
main.c:8:20: error: too many arguments to function 'add'; expected 2, have 3
    8 |     printf("%d\n", add(3, 5, 7));
```

两句原话里都带着 **`expected 2, have ...`** —— 编译器把「说好几样」和「你实际喂了几样」都报了出来，照着它改就行。

**摆了几个元素就喂几样：一样不多、一样不少、顺序不错。**

::: tip 提示
今天五样东西，一句话串起来：

**函数头登记（先说清返回什么、喂什么）→ 报名字带 `()` 施展 → 括号里的空元素接住参数 → `return` 把结果返回称呼它的地方、顺便收工。**

再补两条 C 的硬规矩：**每个元素前面都要写类型**；**摆几个元素就喂几样**。这两条错了编译器都会在翻译阶段就拦下你，程序根本生不出来 —— 报错看着吓人，其实是它在帮你挡刀。
:::

| 写什么 | 我们的说法 | 干什么用的 |
|---|---|---|
| `void greet(void) { }` | 函数头 | 登记一个方法。前面的 `void` = 不返回结果；括号里的 `void` = 不用喂 |
| `int add(int a, int b)` | 函数头 + 两个元素 | 前面的 `int` = 会返回一个整数；括号里摆好元素和类型 |
| `greet();` | 调用一次施展 | 让函数真的跑一遍 |
| `int a` | 参数 | 函数内部对「传入那样东西」的叫法，**前面必须写类型** |
| `return a + b;` | 返回值 | 把结果交回称呼它的地方，**同时当场收工** |
