## 学习目标

本课学习指针与字符串。重点包括字符指针、字符串常量、指针操作字符串。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、字符串的名字，也是一块名称

先看最省事的写法：

```c
#include <stdio.h>

int main(void) {
    char *s = "cat";

    printf("%s\n", s);
    printf("%c\n", *s);
    return 0;
}
```

```text
cat
c
```

逐行看：

- **`char *s = "cat";`** —— 名称 `s` 上写的是「指着一个字符元素的位置」，它初始化就指着这条字符串的**第一颗字符**。和上一课 `int *p = bowls;` 是同一个道理：字符串的名字，就是第一颗字符的地址。
- **`printf("%s\n", s);`** —— `%s` 要的口子就是**一块名称**，不是一整条字符串。它顺着名称一颗一颗往外念，念到暗号 `\0` 就闭嘴。所以印出来的正是 `cat`。
- **`printf("%c\n", *s);`** —— 顺着头一颗，`%c` 只念一颗，印出 `c`。

上一课那个「一排元素交出去是一块名称」的谜底，在这里更直白：**`%s` 从头到尾拿的就是一块名称**。字符串这条规矩你早就用着了，只是今天才知道它叫什么。

## 二、名称的加一，跨的是一颗字符

本阶段第一课「指针深入」的提示框里，我们埋过一句：写着字符的名称，加一个跨 1 格。今天兑现：

```c
#include <stdio.h>

int main(void) {
    char *s = "cat";

    printf("%s\n", s);
    printf("%s\n", s + 1);
    printf("%s\n", s + 2);
    return 0;
}
```

```text
cat
at
t
```

- `s` 从第一颗字符开始念：`cat`。
- `s + 1` 让名称往后挪**一颗字符**，从 `a` 开始念到暗号：`at`。
- `s + 2` 再挪一颗，从 `t` 开始：`t`。

和上一课一模一样：**加一是「挪名称」，不是一个一个数字符**。`*s` 是「拿当下这颗」，`s + 1` 是「挪到下一颗」—— 两件事，别混。

也正因为加一跨的是**一颗**，名称在这条字符串上特别好使：挪一格就正好是一颗字符，不用像整数元素那样跨一大步。

## 三、名称走一遍整串

既然挪一格就是下一颗，那整条字符串走一遍只要一块名称：

```c
#include <stdio.h>

int main(void) {
    char *s = "cat";

    for (char *p = s; *p != '\0'; p++) {
        printf("%c", *p);
    }
    printf("\n");
    return 0;
}
```

```text
cat
```

读法是：「**名称从第一颗字符初始化；只要它当下那颗字符不是暗号就进圈；每圈把名称往后挪一颗。**」

眼色那句 `*p != '\0'` 就是字符串的刹车：`\0` 是字符串末尾那颗看不见的暗号，念到它就该停。这也是 `%s` 自己偷偷在干的事 —— 只不过它替你干了，所以你从来看不见。

**暗号在这门手艺里的角色，你该认准了**：它是**刹车**，是「到这儿为止」的意思。没有它，名称会一路往下念，念到你根本没摆元素的地方去。

这块名称一颗一颗走完字符串、又是被谁叫停的，我们拆成一步一步给你看：

## 四、亲手数一数字符

`%s` 会自己停下，是因为它在替你找暗号。想知道这条字符串到底有几颗字符，你也可以自己拿名称走一遍：

```c
#include <stdio.h>

int main(void) {
    char *s = "cat";
    int n = 0;

    while (*(s + n) != '\0') {
        n++;
    }
    printf("%d\n", n);
    return 0;
}
```

```text
3
```

`n` 从 `0` 开始，每数一颗加一，数到暗号就停 —— 所以它是**真正的字符数**（暗号不算）。这也是 `strlen` 那位档案管理员的干活方式，只不过我们今天让你亲手跑一遍，看看它到底在忙什么。

## 五、字符串能不能动刀？

这个问题得分开答，因为它有两个完全不同的答案。

**第一种：把字符串摆在**一排自己的元素**里，那就可以动刀。**

```c
#include <stdio.h>

int main(void) {
    char word[] = "cat";

    word[0] = 'C';
    printf("%s\n", word);
    return 0;
}
```

```text
Cat
```

`char word[] = "cat";` 是我们亲手摆了四个元素（三颗字符 + 一颗暗号），把字符一颗颗放了进去。既然元素是自己的，当然想换就换：`word[0] = 'C';` 把第一颗字符换成了大写的 `C`。上一课的方括号照样好使 —— 字符串也是一排元素。

**第二种：只拿名称指着一条**写死在程序里的**字符串，那就千万别动它。**

要是你把那两句写成 `char *s = "cat";` 加上 `s[0] = 'C';`，也会发创建一件很吓人的事：**编译器一个字都不说**（我们真跑过，连一句 `warning:` 都没有），程序照样生得出来。可一跑起来它会**当场断气** —— 屏幕上 stdout、stderr 都是空的，一个字都不印，进程就这么没了。

原因：`"cat"` 这种写死在程序里的字符串，住在**只读**的地方，是给你**念**的，不是给你改的。名称能指着它，但顺着名称往里写，就是往墙上刻字。

::: warn 注意
这两句长得只差一对方括号，脾气却差着十万八千里：

- **`char word[] = "cat";`** —— 摆了四个元素、把字符放进去，**可以改**。
- **`char *s = "cat";`** —— 只是一块名称指着只读的地方，**不能改**。

而且第二种摔得特别隐蔽：翻译阶段**一次不吭**，编译的时候连嘀咕都没有，你压根看不出哪儿不对 —— 直到它当场断气。**所以我们的死规矩是：想改的字符串，一律用有方括号的那种写法摆出来。**

另外提一句：名称本身倒是随便改 —— 让它改指另一条字符串一点问题都没有：

```c
#include <stdio.h>

int main(void) {
    char *s = "cat";

    s = "dog";
    printf("%s\n", s);
    return 0;
}
```

```text
dog
```

名称改指是「换一条字符串念」，动的是名称；`s[0] = 'C'` 是「往字符串上刻字」，动的是那条字符串。这两件事差着辈分。（还记得上一课吗？一排元素的名字**不能**挪，名称**能**挪 —— 一条字符串一个脾气。）
:::

## 六、一颗字符的元素里塞不下整条字符串

最后来一个一定能被拦下的错，让我们听着编译器说话：

```c
#include <stdio.h>

int main(void) {
    char c = "cat";

    printf("%c\n", c);
    return 0;
}
```

```text
main.c:4:14: error: initialization of 'char' from 'char *' makes integer from pointer without a cast [-Wint-conversion]
    4 |     char c = "cat";
```

编译器的原话意思是：**「你把一整条字符串塞进了一个只装一颗字符的元素。」**

看出来了吗：`char c` 是一个**单颗字符**的元素，而 `"cat"` 是**一整条字符串**（真身是「第一颗字符的地址」，也就是一块名称）。拿名称去填一个只装一颗字符的元素，编译器当场拦住。

**记号分清楚就不会摔**：`'c'` 是**单引号、一颗字符**；`"cat"` 是**双引号、一整条字符串**。差一层引号，差着一块名称。

::: tip 提示
今天四句话：

1. **`char *s = "cat";`** 里的 `s` 是一块名称，指着第一颗字符；`%s` 要的就是这块名称。
2. **名称加一 = 挪一颗字符**：`s + 1` 是从第二颗字符开始念的整条末尾 `at`。
3. **`*p != '\0'` 是字符串的刹车** —— 暗号 `\0` 就写在末尾那颗看不见的字符里；想自己数字符也靠它。
4. **想改的字符串，用 `char word[] = "cat";` 摆出来**；只拿名称指着写死的字符串还去刻字，翻译阶段一次不吭、跑起来当场断气。
:::
