## 学习目标

本课学习递归函数。重点包括递归思想、基线条件、阶乘/斐波那契。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、函数里调用自身：先数个数

```c
#include <stdio.h>

void countdown(int n) {
    if (n == 0) {
        printf("到站\n");
        return;
    }
    printf("%d\n", n);
    countdown(n - 1);
}

int main(void) {
    countdown(3);
    return 0;
}
```

```text
3
2
1
到站
```

拆开看这个函数：传入一个数据 `n` 进去，然后它干三件事 ——

1. **先看要不要停。** `if (n == 0)` 成立的时候，印一句「到站」就 `return` 收工，**不再调用自身**。
2. **干自己的那点活。** `printf("%d\n", n);` 把当前这个数印出来。
3. **调用自身，并且把传入的数目减一。** `countdown(n - 1);` —— 这就是「咬住自己末尾」的那一口。

走一遍就明白了：进去时 `n` 是 3，它印 3、调用 `countdown(2)`；那一位印 2、调用 `countdown(1)`；再一位印 1、调用 `countdown(0)`；最后一位看到 `n == 0`，印「到站」，收工。一共四位，一层层到底，再一层层结束。

## 二、基线条件：那句「什么时候停」

上面那句 `if (n == 0)`，我们管它叫**基线条件（刹车）**。

那把刹车拆了会怎样？我们在跑台上真跑过这么一段（我们故意把刹车拿掉，所以只放在这里给你看）：

```text
#include <stdio.h>

void countdown(int n) {
    printf("%d\n", n);
    countdown(n - 1);
}

int main(void) {
    countdown(3);
    return 0;
}
```

编译器**出声了** —— 它给我们留下这么一句：

```text
main.c:3:6: warning: infinite recursion detected [-Winfinite-recursion]
main.c:5:5: note: recursive call
```

它甚至一眼就看出来了（`infinite recursion detected` 就是「发现有个停不下来的自己调用自身」）。

**可它只是出声，没把我们拦下** —— 程序照样被编了出来，交到我们手里。**「警告」不是「错误」**：错误是拦下的那个手，警告只是它顺口提醒的一句，而这一句最容易被一眼扫过去。

真正没辙的在后面那一下：**一跑起来，它先一路往下数** —— 3、2、1、0、-1、-2……一直数到把「记着待会儿要回到哪儿」的那一摞元素摞爆，这才「啪」地一下没了：我们这边收到的，是刷了一大片数字之后**突然断掉**，加上一个异常的退出状态（`3221225725` —— 那正是「记东西的地方被撑爆了」的记号）。

道理不复杂：每一位都在调用下一位，永远没人调用停，于是「记着待会儿要回到哪儿」的那一摞元素越摞越高，最后把地方撑爆了。

**写递归函数，第一件事就是先想清楚「什么时候停」。** 这里还有两条硬要求：

1. **停的那一句，得真有可能轮到。** `if (n == 0)` 配 `countdown(n - 1)` 是好的；配 `countdown(n + 1)` 就永远轮不到。
2. **每一步都要离停更近一点。** 这里每次都把 `n` 减一，所以一定走得到 0。

::: warn 注意
**别指望编译器每次都出声。** 上面那一段它确实看出来了（「一直在调用自身」这件事摆在明面上）；可只要换个形状 —— 刹车写对了、但**每一步都往反方向挪**（`countdown(n + 1)` 那样），它就**一个字都不说**：那一版我们也真跑过，编译器安安静静地把它编了出来，而跑起来照样收不了场（数字一路往上数，最后撑爆）。

所以「忘了写刹车、或者刹车够不着」是本课最贵的坑：**它可能一次不响，也可能只出声不拦你** —— 等到跑起来，它已经救不回来了。

还有一条：**每一次调用自身，传入的东西都要往停的方向挪。** 挪反了方向，等于踩了油门去撞刹车，效果和没写刹车一样。
:::

## 三、去的时候一路往下，回来的时候一路收尾

再看一段更能看出「往返」的：

```c
#include <stdio.h>

void down(int n) {
    int mine = n * 10;
    if (n == 0) {
        printf("到底了，我们元素里是 %d\n", mine);
        return;
    }
    printf("往下走之前，我们元素里是 %d\n", mine);
    down(n - 1);
    printf("回来之后，我们元素里还是 %d\n", mine);
}

int main(void) {
    down(2);
    return 0;
}
```

```text
往下走之前，我们元素里是 20
往下走之前，我们元素里是 10
到底了，我们元素里是 0
回来之后，我们元素里还是 10
回来之后，我们元素里还是 20
```

`mine` 是每一位自己的变量（`int mine = n * 10;`），**每一位都有新的一个**。所以：

- **往下走的那一趟**（在 `down(n - 1)` 之前）：印 20、印 10；
- **到底折回来之后**（在 `down(n - 1)` 之后）：印 10、印 20。

要紧的是这一句：`down(2)` 里那个元素保存的是 20，它调用结束 `down(1)`、等那一位全部收工回来之后，自己那个元素**还在，还是 20**。一层一层的元素不会互相覆盖 —— 「每个自己都有一套自己的变量」就是这套写法能立住的地基。

「往下走」和「折回来」这两趟，是这一课最看不见的东西 —— 屏幕上印出来的六行里面，藏着一次**没印出来**的下钻和一次**没印出来**的回程。下面这段把它俩摊开给你看。注意「停在半路的层」这一栏：它就是从第 5 步开始一层层摞起来的**那一摞元素**，摞到顶再一层层收回去。

## 四、阶乘：数学书上的老例子

一说到递归调用，书上都爱举这个例子：`5!`（读作「5 的阶乘」）等于 `5 × 4 × 3 × 2 × 1`。

换个角度念：**`5!` 就是 `5 × 4!`**，而 `4!` 就是 `4 × 3!` —— 又是同一道题、小一圈。什么时候停？**`0!` 规定等于 1**，那就是它的刹车。

```c
#include <stdio.h>

long long fact(int n) {
    if (n == 0) {
        return 1;
    }
    return n * fact(n - 1);
}

int main(void) {
    printf("%lld\n", fact(5));
    printf("%lld\n", fact(10));
    return 0;
}
```

```text
120
3628800
```

看第二行那句 `return n * fact(n - 1);` 里的 `return`：它**不是**先算完再回来 —— 是「调用结束那一位、等它把结果返回，我们再拿它跟自己乘」。所以每一位都要**等**下一位，一层层等到底，再一层层把结果返回上来。

::: tip 提示
`long long` 是「更宽的变量」，装得下更大的整数（`%lld` 是它的格式符）。`12!` 已经上亿了，用窄的那种变量会装不下、印出一堆怪数字 —— 我们这里给它留宽一点，你就不用操心了。
:::

## 五、一次调用自身两次：斐波那契

斐波那契数列是这样的：头两个数是 0 和 1，**后面每一个数都是前面两个相加**。

0、1、1、2、3、5、8、13……

递归调用的写法几乎是照抄这句话：

```c
#include <stdio.h>

int fib(int n) {
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main(void) {
    for (int i = 0; i < 8; i++) {
        printf("%d ", fib(i));
    }
    printf("\n");
    return 0;
}
```

```text
0 1 1 2 3 5 8 13 
```

注意这句 `return fib(n - 1) + fib(n - 2);` —— **一次调用了两个自己**。这是允许的，一位调用两位、两位各调用四位，像树一样岔开。

**可这份好看是有代价的。** 我们给这段程序加了个计数器，数了数它一共调用了多少次：

```c
#include <stdio.h>

int calls = 0;

int fib(int n) {
    calls = calls + 1;
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main(void) {
    printf("fib(6)=%d\n", fib(6));
    printf("一共调用了 %d 次函数\n", calls);
    return 0;
}
```

```text
fib(6)=8
一共调用了 25 次函数
```

才算出 7 个数，函数被调用了 **25 次**。因为 `fib(4)` 会被算好几遍、`fib(3)` 更多遍 —— 同一道小题被反反复复重算，越往大数字越夸张。

这不是「写法错了」，是这套好看写法的**脾气**：省了代码，费了功夫。往后学到更省事的写法时，你会想起今天这 25 次。

## 六、函数得先打过招呼才能用

编译器是从上往下读代码的。它在 `main` 里见到一个名字，如果**上面还没见过这个名字**，就会当场停下：

```c
#include <stdio.h>

int main(void) {
    printf("%d\n", sum(3));
    return 0;
}

int sum(int n) {
    if (n == 0) {
        return 0;
    }
    return n + sum(n - 1);
}
```

```text
main.c:4:20: error: implicit declaration of function 'sum' [-Wimplicit-function-declaration]
```

编译器的原话是「`sum` 这个函数我们没见过就先用上了」。**注意它不是说 `sum` 不能调用自身** —— 函数在自己的身体里调用自身，名字早就登记好了，不算没见过。它卡住的是 `main` 称呼它这一次。

改法很朴素：把函数整个搬到 `main` 前面去，或者只在 `main` 前面先写一行「招牌」（我们在「写在门口的大缸」那一课讲过它）。**递归调用，和「先打招呼」是两件事，别混。**

## 七、把一整排元素交给自己

递归函数，常常拿来收拾「一排元素」：

```c
#include <stdio.h>

int sum(int a[], int n) {
    if (n == 0) {
        return 0;
    }
    return a[n - 1] + sum(a, n - 1);
}

int main(void) {
    int nums[] = {3, 5, 7, 9};
    printf("%d\n", sum(nums, 4));
    return 0;
}
```

```text
24
```

读法：**「前 4 个元素加起来」= 第 4 个元素里的数 + 「前 3 个元素加起来」**；刹车是「前 0 个元素加起来等于 0」。`a`（那排元素）和 `n`（还剩几个）一起往下递，`n` 每次减一，总会减到 0。

同一件事绕圈也能干（几个元素挨个走一遍，边走边加），而且绕圈往往更快、更省地方。那为什么还要有这套写法？因为有些题**用「小一圈的同一道题」讲起来最顺** —— 像斐波那契那样一句话就说清了。两种写法都收在工具箱里，用哪把看你顺手。

::: tip 提示
今天收五句话：

1. **递归函数 = 在自己的身体里再调用一次自己。**
2. **基线条件就是刹车**，而且必须「轮得到」并且「每步都更靠近它」。
3. **每一位都有自己的一套变量**，回来之后变量中的东西还在。
4. **一次可以调用好几个自己**，但要注意重复计算（`fib(6)` 被调用了 25 次那件事）。
5. **函数要先打过招呼才能被别人调用** —— 这和它能不能调用自身是两码事。
:::

## 小任务

1. 把第一节的倒计时改成「从 `n` 一直数到 1，然后再数回 `n`」—— 提示：一句 `printf` 写在调用自身**之前**，另一句写在**之后**。
2. 写一个函数，算出「第 `n` 摞元素有几个」：仿照我们钩子里那个数法，一摞元素的数量减一，刹车的条件是「一个都不剩」。
