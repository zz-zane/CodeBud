## 学习目标

本课学习指针与数组。重点包括数组名即首地址、指针遍历数组、下标与偏移。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、排的名字，就是第一个元素的地址

先别信我们，自己看一眼：

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {10, 20, 30};

    printf("%d\n", bowls == &bowls[0]);
    printf("%d\n", *bowls);
    return 0;
}
```

```text
1
10
```

- **`bowls == &bowls[0]`** 印出 `1` —— 「这一排的名字」和「第一个元素的地址」**是同一个东西**。不是像，是**就是**。
- **`*bowls`** 印出 `10` —— 既然名字就是地址，那前面挂一颗星，当然就顺着走到了第一个元素前面。

所以上一课那个「整排元素交出去的是原件」的谜团，谜底特别朴素：**交出去的压根不是「一整排」，是一块名称** —— 指着第一个元素的名称。函数顺着它当然能改到你本人的元素。

## 二、报编号的真身：`*(bowls + i)`

现在把两件事拼起来：名称能**挪**（上一课），排的名字**就是名称**（刚讲完）。那 `bowls[1]` 到底是什么？

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {10, 20, 30};

    printf("%d\n", bowls[1]);
    printf("%d\n", *(bowls + 1));
    return 0;
}
```

```text
20
20
```

两行印出来一模一样，因为**这两句本来就是同一件事**：

> **`bowls[i]` 就是 `*(bowls + i)` 的甜写法。**

拆开念一遍：**先把地址往后挪 `i` 只元素，再顺着拿。** 方括号里的编号，干的活儿正是「挪几步」。这也顺手解释了从前的两条怪规矩：

- **为什么编号从 0 开始？** 因为挪 `0` 步就是第一个元素。要是从 1 开始数，第一个元素反而要写成「往后挪一步」，那才别扭。
- **为什么最大编号是元素数减一？** 三个元素，你想拿第三个，得挪 `2` 步 —— `bowls[2]`。挪三步就跨到整排外面去了。

所以「报编号」这个名字其实是我们偷懒的叫法，它的真身是**偏移**：偏移 0 是第一个，偏移 1 是第二只，偏移 2 是第三个。

## 三、名称也能报编号

既然方括号只是「挪 + 顺着拿」的甜写法，那**任何一块名称**都该能用它：

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {10, 20, 30};
    int *p = bowls;

    printf("%d\n", p[0]);
    printf("%d\n", p[2]);
    printf("%d\n", *(p + 1));
    return 0;
}
```

```text
10
30
20
```

- **`p[0]`** —— 挪 0 步，第一个元素，`10`。
- **`p[2]`** —— 挪 2 步，第三个元素，`30`。
- **`*(p + 1)`** —— 这就是上一课的写法，和 `p[1]` 是同一件事。

看出来了吗：**方括号不是「一排元素」的特权，它是「名称」的特权。** 名字能用，是因为名字本来就是一块名称；名称能用，是因为它就是名称。一家人不说两家话。

## 四、用名称走一遍整排

把这个新认识拿去跑圈，遍历一排元素就有了另一种写法：

```c
#include <stdio.h>

int main(void) {
    int bowls[4] = {10, 20, 30, 40};

    for (int *p = bowls; p < bowls + 4; p++) {
        printf("%d\n", *p);
    }
    return 0;
}
```

```text
10
20
30
40
```

读法是：「**名称从第一个元素初始化；只要它还落在整排里面就进圈；每圈把名称往后挪一个元素。**」圈里那句 `*p` 拿到的，就是名称当下指着的那个元素里的数。

眼色那句 `p < bowls + 4` 值得拆一下：

- `bowls` 是第一个元素的位置，`bowls + 4` 是**第四个元素再往后挪一个**的位置 —— 也就是「整排之外」的第一格。所以「小于它」正好把这**四个元素**都走一遍，一个不多一个不少。
- 要是写成 `p <= bowls + 4`，名称就会挪到整排外面去一格 —— 而**C 不会拦你**（上一课那口「注意」说的就是这个）。

## 五、函数拿到的，只有「从哪儿开始」

现在回头看一个更要紧的问题：把一排元素交进函数，函数手里究竟有什么？

```c
#include <stdio.h>

void show(int *p) {
    printf("%d\n", *p);
    printf("%d\n", *(p + 1));
}

int main(void) {
    int bowls[4] = {10, 20, 30, 40};
    show(bowls);
    return 0;
}
```

```text
10
20
```

函数头上写着 `int *p`，说明它收的是**一块名称**。所以函数里能干的，只有「顺着名称拿」和「挪名称再拿」。它能印出 `10` 和 `20`，是因为我们告诉它「往后挪一格」。

可它**不知道这一排有几个元素**。它手里的全部信息，就是「第一个元素在哪儿」加上「每个元素多大」。这是一排元素和名称的**唯一区别**：整排元素的「长度」是写在声明里的（`bowls[4]` 那个 `4`），而名称身上没有这个数。

所以想让函数照顾整排元素，得**额外把长度传入**：

```c
#include <stdio.h>

void fill(int *p, int n) {
    for (int i = 0; i < n; i++) {
        p[i] = (i + 1) * 10;
    }
}

int main(void) {
    int bowls[3] = {0};
    fill(bowls, 3);
    printf("%d %d %d\n", bowls[0], bowls[1], bowls[2]);
    return 0;
}
```

```text
10 20 30
```

胃口不错的一块名称：它收下地址 `p`，又收下「有几个」这个数 `n`，然后自己用 `p[i]` 挨个填进去。回到 `main` 一印，你本人的元素**真的变了** —— 函数改的是原件，这一点和上一课一模一样。

::: warn 注意
函数不知道有几个元素，这件事有两副面孔：

- 你**喂**进去的长度比这排元素实际有的只数还大（一排只有 3 只元素，你却调用了 `fill(bowls, 5)`），函数不知道这件事，它会**从第一个元素一路往外写**。编译器一个字都不说（我们真跑过，连一次嘀咕都没有），元素架外面的东西会被一个只写坏 —— 而且我们那一次压根没等到「写坏别处」，程序当场就断气了，屏幕上一个字都没印出来。
- 你自己在函数里**挪过了头**也一样：`p + 9` 在一排只有三个元素的地方，照样算得出来、照样能顺着拿 —— 拿回来的是哪一格，谁也说不准（我们拿 `bowls + 5` 试过：编译器一次不吭，印出来一个垃圾数 `828372976`，还可能是别的）。

所以「有几个元素」这个数，从今往后你走到哪儿带到哪儿。它不是给编译器看的，是给你自己当刹车用的。
:::

## 六、排的名字挪不动

最后讲一个今天最扎心的地方。既然名字就是名称，那名字能不能也像名称那样挪一挪？

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {1, 2, 3};

    bowls++;
    printf("%d\n", bowls[0]);
    return 0;
}
```

```text
main.c:6:10: error: lvalue required as increment operand
    6 |     bowls++;
```

编译器的原话意思是：**「`bowls` 这个名字，不能当成一个变量来改。」**

原因想想就通：一排元素是**实实在在摆在架子上的一整排**，它的名字是这排元素挂的那块**名称**（也就是第一个元素的位置），不是一个可以随手改的变量。你让这个名字往后挪，那这排元素的第一个到底还算不算第一个？C 干脆不让。

**这一条正好把两者分清楚了**：

| 谁 | 是什么 | 能不能挪 |
|---|---|---|
| 一排元素的名字 | 第一个元素的地址（写死的） | **不能**，`bowls++` 编不过去 |
| 一块名称 | 一个保存地址的变量 | **能**，`p++` 随便挪 |

想把一排元素从头走到尾，你得**备一块名称**（像第四节那样 `int *p = bowls;`）让它代你走 —— 那才是名称该干的活。

::: tip 提示
今天四句话：

1. **一排元素的名字 = 第一个元素的地址**，`bowls == &bowls[0]` 是真的。
2. **`bowls[i]` 就是 `*(bowls + i)` 的甜写法** —— 先挪 `i` 只元素，再顺着拿；它就是编号从 0 开始的原因。
3. **方括号是名称的特权**，`p[i]` 一样能用；用名称遍历整排就跑圈 + `p++`。
4. **函数只知道「从哪儿开始」**，不知道有几个元素 —— 长度得你亲手传入；名字挪不动，要挪就备一块名称。
:::
