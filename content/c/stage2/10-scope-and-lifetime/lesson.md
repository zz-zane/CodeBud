## 学习目标

本课学习作用域与生命周期。重点包括块作用域、static、extern、局部与全局。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、花括号画地盘：圈里摆的元素，出了圈就不认得

先看一段正常的。我们在圈**外面**摆一个攒数的元素，在圈**里面**摆一个临时的：

```c
#include <stdio.h>

int main(void) {
    int total = 0;

    for (int i = 1; i <= 3; i++) {
        int step = i;
        total = total + step;
        printf("第 %d 圈：这一圈 %d，一共 %d\n", i, step, total);
    }

    return 0;
}
```

```text
第 1 圈：这一圈 1，一共 1
第 2 圈：这一圈 2，一共 3
第 3 圈：这一圈 3，一共 6
```

看两个元素的下场：圈里那个 `step` 是**每转一圈新发的一个**（把这一圈的数赋值、印出来，这一圈过完它就没了）；外面那个 `total` 是**从头用到尾的同一个**，所以它能一直攒着。**第一行能印出 1、第二行印出 3、第三行印出 6**，靠的就是「外面的元素记得住」。

那要是把圈里的元素端到圈外面去用呢？这一种编译器**会**报错，报得还很直接：

```c
#include <stdio.h>

int main(void) {
    {
        int bonus = 7;
        printf("圈里 %d\n", bonus);
    }

    printf("出圈 %d\n", bonus);
    return 0;
}
```

```text
main.c:9:25: error: 'bonus' undeclared (first use in this function)
```

`undeclared` 就是「没宣告过 / 不认识这个名字」。花括号是一道**地盘线**：元素摆在圈里，就只有圈里看得见。那句话站在圈外面，当然不认得它。

::: tip 提示
**花括号画地盘，出了圈就不算数。**

想让两处都看得见，只有一个办法：**把元素摆到外面那层地盘上去**（本课第一节那个 `total` 就是这么摆的）。顺手记一句：**摆得越靠里，看得见它的地方越少** —— 这不是限制，是 C 帮你把「临时用一下」和「一直要用」分开的绳子。
:::

## 二、三个同名的元素：近的赢

地盘一多，就有个新问题：**同名怎么办？** 我们在三层地盘上各摆一个 `cap`：

```c
#include <stdio.h>

int cap = 100;

int main(void) {
    int cap = 30;
    printf("外面 %d\n", cap);

    {
        int cap = 7;
        printf("圈里 %d\n", cap);
    }

    printf("回到外面 %d\n", cap);
    return 0;
}
```

```text
外面 30
圈里 7
回到外面 30
```

规矩只有一条：**叫一个名字的时候，取「离你最近的那一层」**。

- 刚进 `main`，最近的 `cap` 是函数里那个 → 印 30（**里面这个把最外面那层挡在后面了**）；
- 进了圈，最近的换成了圈里那个 → 印 7；
- 出了圈，圈里那个已经没了，最近的又变回函数里的 → 印回 30。

这就是为什么它叫「**近的赢**」——**里层的元素把外层的挡在后面**，一直到里层那个消失为止。最外面那个 `cap = 100` 从头到尾一次都没轮到，它老老实实待着，等哪处都没有近的了才会出场。

::: warn 注意
同一个名字摆好几层，读代码的人**要一层一层往里数**才能知道这一句说的是哪只元素。所以老已有实现对象的规矩是：**能不同名就别同名**。

真要用同名，也要让「里面那个」跟「外面那个」是**同一件事**（比如都是「当前的仓容」），只是这一小段要按里面这个数来算。要是它们根本不是一件事，那就不是在遮蔽，是在给下一个人挖坑。
:::

## 三、`static`：函数自己的固定格子

现在换到函数里看。我们要一个方法「报编号」的：

```c
#include <stdio.h>

void next_id(void) {
    static int id = 0;
    id = id + 1;
    printf("序号 %d\n", id);
}

int main(void) {
    next_id();
    next_id();
    next_id();
    return 0;
}
```

```text
序号 1
序号 2
序号 3
```

**它记得住。** 而把那个 `static` 去掉，同一段就变成：

```c
#include <stdio.h>

void next_id(void) {
    int id = 0;
    id = id + 1;
    printf("序号 %d\n", id);
}

int main(void) {
    next_id();
    next_id();
    next_id();
    return 0;
}
```

```text
序号 1
序号 1
序号 1
```

调用三回都是 1 —— 因为**函数里普通的元素，每次进门都是新发的**：进门新摆一个保存 0 的元素，加一、印完、出门，那个元素就没了；下一回再来，又是一个新的 0。

加上 `static` 就换了性质：那个元素变成**这一个方法自己的固定格子**，只在**第一次**调用到这一行的时候准备一次，之后每一回进门用的都还是它。所以「装的数是 0」这件事只发创建一遍，后面就是 1、2、3…… 一路加下去。

那三声「序号 1、2、3」是怎么来的？我们拆成一步一步给你看：

**记住这个元素的脾气**：`static` 只在你**头一回**进门时摆一次，出了门它也不走 —— 所以第二回进门，元素里保存的是上回的数，不是 0。同一个方法调用三回能得 1、2、3，靠的就是这一条；而下面那个攒数的元素，会用同一个脾气给你一段看着莫名其妙的数。

::: warn 注意
`static` 是「记得住」的本事，也正是它最容易咬人的地方 —— **记错了东西，它一样记得住。**

我们真跑过这么一段：一个方法 `sumTo(n)` 里摆了一个 `static` 的攒数元素，调用两次：

```c
#include <stdio.h>

int sumTo(int n) {
    static int total = 0;

    for (int i = 1; i <= n; i++) {
        total = total + i;
    }

    return total;
}

int main(void) {
    printf("%d\n", sumTo(3));
    printf("%d\n", sumTo(5));
    return 0;
}
```

```text
6
21
```

第一次 `sumTo(3)` 报 6，第二次 `sumTo(5)` 报的**不是 15，是 21** —— 因为它把上一回那 6 也加进去了（21 = 6 + 15）。这个元素**跨着两次输出**活着：同一个函数被调用第二遍的时候，它从上一次的余数接着算。

把 `static` 去掉，同一段就老老实实报 `6` 和 `15` 了：

```c
#include <stdio.h>

int sumTo(int n) {
    int total = 0;

    for (int i = 1; i <= n; i++) {
        total = total + i;
    }

    return total;
}

int main(void) {
    printf("%d\n", sumTo(3));
    printf("%d\n", sumTo(5));
    return 0;
}
```

```text
6
15
```

**看出来了吗：这一个方法该「每次都从零算」的时候，攒数的元素千万别加 `static`。**
:::

## 四、`extern`：名称挂在前，缸摆在别处

最后一种：**缸不在这一层，这儿只挂一块名称。**

名称长这样：`extern int cap;` —— 「有这么一个叫 `cap` 的元素，**它的缸摆在别处的纸**上，我们这儿只借它的名字用一下」。挂完名称，只要**别处真的摆了那个缸**，用起来就跟自己的元素一样：

```c
#include <stdio.h>

extern int cap;

int cap = 20;

int main(void) {
    printf("仓容 %d 条\n", cap);
    return 0;
}
```

```text
仓容 20 条
```

注意 `extern` 那一行底下**没有等号、也没有值** —— 它只是「有这么一个元素」的一句话，缸是下面那一行摆的。

那要是**只挂了名称、缸一直没人摆**呢？编译器在翻译的时候一句话都不会说（名称本身写得没毛病），可到了最后**把几份东西拼起来**的那一步，它会发现这个名字谁的缸也对不上：

```c
#include <stdio.h>

extern int cap;

int main(void) {
    printf("仓容 %d 条\n", cap);
    return 0;
}
```

```text
collect2.exe: error: ld returned 1 exit status
```

最后那一句是它的收尾话，往前翻一行还能看到它念叨的名字 —— `undefined reference to`，后面跟着的就是 `cap`：**「我们只看到一块名称，缸呢？」**

::: tip 提示
`extern` 就是**第九课那种「只挂宣告、身子在别处」的老熟人**：

- 函数那一行宣告 = 招牌上写着「有这么一个方法」，身子在干活本里；
- `extern` 那一行 = 名称写着「有这么一个元素」，缸摆在别处的纸上。

**宣告和身子可以分家，但两样都得有人写。** 只写宣告，编译器最后那一步就要问你「缸呢」了。
:::

## 五、元素摆哪儿，生命周期多长

把今天的四种摆法排一排，这就是「变量的生命周期」表：

| 元素摆在哪儿 | 谁看得见 | 活多久 | 长什么样 |
|---|---|---|---|
| 花括号**里面** | 只有圈里 | 出了圈就没了 | `int step = i;` |
| 函数里**不加** `static` | 整个函数 | 每次进门新发一个 | `int total = 0;` |
| 函数里**加了** `static` | 整个函数 | 只发一次，一直留着 | `static int id = 0;` |
| 函数**外面**那层地盘 | 这一张纸上都看得见 | 从头活到尾 | `int cap = 100;` |
| 挂块名称、缸在别处 | 这一张纸上都看得见 | 缸在别处活着 | `extern int cap;` |

::: tip 提示
一句话收尾：**元素摆在哪一层，决定它能活多久、被谁看见。** 想「用完就扔」就往圈里摆；想「这一个方法自己记着」就加 `static`；想「整张纸一起用」就摆到外面去；实在要用的元素在别的纸上，就挂一块 `extern` 的名称。

**摆错地方不一定报错** —— 有的只是算错个数（比如那个 `static` 攒数元素），这才是它最阴的地方。
:::

下一课我们要教你一个方法更绕的本事：**一个方法调用自身**。听起来像自己咬递归调用链，可只要知道「什么时候该停」，它就能把一件大活拆成小一号的同款活，一层一层小下去 —— 那是很多算法的起手式。
