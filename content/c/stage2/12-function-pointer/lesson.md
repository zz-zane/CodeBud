## 学习目标

本课学习函数指针与回调。重点包括函数指针声明、作为参数传递、回调思想。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、先认清名称的长相

我们有一个方法「加」：

```c
int add(int a, int b) {
    return a + b;
}
```

现在我们想摆一个元素，里面装**这张「加」的名称**。写出来是这样：

`int (*op)(int, int) = add;`

这一行长得很怪，我们把它拆成三段念，你就不怕它了 —— **从里往外、从右往左念**：

1. **最右边那两个 `(int, int)`**：这招要传入什么？ —— 两个整数。
2. **最左边那个 `int`**：它返回值是什么？ —— 一个整数。
3. **中间那包 `(*op)`**：这个元素叫 `op`，里面保存的是一张名称。**包着 `*op` 的那对小括号一个都不能省** —— 第六节有个坑专门讲它。

摆好元素之后，用它跟用函数一模一样：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int sub(int a, int b) {
    return a - b;
}

int main(void) {
    int (*op)(int, int) = add;
    printf("%d\n", op(7, 2));
    op = sub;
    printf("%d\n", op(7, 2));
    return 0;
}
```

```text
9
5
```

头一句 `int (*op)(int, int) = add;` 把「加」的名称放进 `op`。第二句 `op(7, 2)` 就照着名称上写的去调用那招，得到 9。

然后 `op = sub;` —— **元素没换，名称换了**。再调用 `op(7, 2)`，这回照着新名称走，得到 5。

**同一个元素、同一个写法，换张名称就换了一套活。** 这就是今天所有本事的种子。

## 二、加不加 `&` 和 `*`，编译器都认得

刚学到这里的人常犯迷糊：名称到底是 `add` 还是 `&add`？引用的时候是 `op(...)` 还是 `(*op)(...)`？

我们把四种写法都写出来跑了一遍：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int (*p1)(int, int) = add;
    int (*p2)(int, int) = &add;
    printf("%d %d\n", p1(1, 2), p2(1, 2));
    printf("%d %d\n", (*p1)(3, 4), (*p2)(3, 4));
    return 0;
}
```

```text
3 3
7 7
```

四行四种写法，出来的数是同一对。原因很简单：

- **函数名单独写出来（`add`）的时候，它自己就等于那张名称**，所以 `add` 和 `&add` 是一回事；
- **拿着名称引用的时候（`op(...)`），编译器本来就按名称走**，所以你写不写那个 `*` 都一样。

我们的建议：**平时就写 `add` 和 `op(...)`**，最干净。看到别人写 `&add`、`(*op)(...)` 也别慌，那是同一件事的另外几种说法。

::: warn 注意
**唯一不能省的，是 `(*op)` 外面那对小括号。** 写成 `int *op(int, int)` 意思就完全变了 —— 那是「一个方法名叫 `op`、返回的是一张整数名称」，根本不是「一个装名称的元素」。第六节我们会把这个坑当场弄炸给你看。
:::

## 三、把名称当数据递出去

名称既然是「一个元素里的东西」，那它就能**当数据递进别的函数里**：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int mul(int a, int b) {
    return a * b;
}

int apply(int (*op)(int, int), int a, int b) {
    return op(a, b);
}

int main(void) {
    printf("%d\n", apply(add, 3, 4));
    printf("%d\n", apply(mul, 3, 4));
    return 0;
}
```

```text
7
12
```

看 `apply` 头上的第一样传入：`int (*op)(int, int)` —— 它要的不是一个数，**是一张名称**，而且名称的长相写清楚了（传入两个整数、返回一个整数）。

我们调用 `apply(add, 3, 4)`，就是把「加」的名称递进去。`apply` 内部那句 `return op(a, b);` 照着名称上写的去调用 —— 递「加」就加，递「乘」就乘。

**`apply` 自己完全不知道进来的是加还是乘。** 它只管照着名称干活。这就是牌的威力：**把「怎么干」从「什么时候干」里拆了出来。**

## 四、回调：回头调用你一次

再看一个更能看出味道的：

```c
#include <stdio.h>

void show(int x) {
    printf("元素里是 %d\n", x);
}

void show_double(int x) {
    printf("翻倍是 %d\n", x * 2);
}

void each(int a[], int n, void (*visit)(int)) {
    for (int i = 0; i < n; i++) {
        visit(a[i]);
    }
}

int main(void) {
    int bowl[3] = {3, 5, 7};
    each(bowl, 3, show);
    each(bowl, 3, show_double);
    return 0;
}
```

```text
元素里是 3
元素里是 5
元素里是 7
翻倍是 6
翻倍是 10
翻倍是 14
```

`each` 走到每个元素前面，就**回头调用一次那块名称上写的函数**，把元素里的数传给它。至于输出的是「印一遍」还是「印两遍」，`each` 不管 —— 那是名称的事。

这种「**先递一张名称过去，等合适的时机到了，再回头调用你一次**」的干法，我们管它叫**回调**：不是你追着称呼它，是它到了时候回来调用你。

回想一下上一课的倒计时：`countdown` 引用的是**自己**；今天的 `each` 引用的是**别人递进来的名称**。两件事长得像，劲头不一样。

::: tip 提示
回调的好处一句话说完：**同一段框架，配不同的名称，就能干不同的活。** `each` 只写一遍，想怎么处理每个数，就换一张名称 —— 不用把 `each` 抄成两份、三份。
:::

## 五、真实世界里最有名的一张名称：`qsort`

「给一排数据排排坐」是每门语言都自带的活。C 里负责这件事的函数叫 `qsort`，它住在头文件 `stdlib.h` 家里。

有意思的是：**它不知道怎么比大小** —— 整数、小数、名字，规矩都不一样。所以它让**你**把规矩写成一张名称递进去：

```c
#include <stdio.h>
#include <stdlib.h>

int cmp(const void *a, const void *b) {
    return (*(const int *)a) - (*(const int *)b);
}

int main(void) {
    int nums[5] = {5, 2, 9, 1, 7};
    qsort(nums, 5, sizeof(int), cmp);
    for (int i = 0; i < 5; i++) {
        printf("%d ", nums[i]);
    }
    printf("\n");
    return 0;
}
```

```text
1 2 5 7 9 
```

`qsort` 收到四样传入：

| 传入 | 是什么 |
|---|---|
| `nums` | 要排的那一排元素 |
| `5` | 一共几个元素 |
| `sizeof(int)` | 每个元素占多大 |
| `cmp` | **「谁该站前面」的规矩在哪张名称上** |

至于 `cmp` 头上那串 `const void *a`：`void *` 是「**不知道是什么的名称**」的意思 —— `qsort` 要能排整数、排小数、排名字，只好假装不知道里面是什么。所以轮到我们自己动手时，得先把它转回「指向整数的名称」（`(const int *)a`），再把数取出来（前面那个 `*`）。

这一段**今天只要眼熟**，不用背：记住那张名称是「比的规矩」，整段代码里唯一一张由你提供的名称，就是它。

## 六、括号丢了，意思就全变了

这是本课最容易摔的一跤。我们把它真跑了一遍：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int *p(int, int) = add;
    printf("%d\n", p(1, 2));
    return 0;
}
```

```text
main.c:8:5: error: function 'p' is initialized like a variable
```

编译器最上面那句原话是「**函数 `p` 怎么可以像一个元素那样给初值**」（底下还跟着一串抱怨，都是从这句牵出来的）。

道理在于：少了那对小括号，`int *p(int, int)` 读出来是「**一个方法名叫 `p`，返回的是一张指向整数的名称**」—— 它认为你在**定义一个方法**，可后面你又给了它一个等号加初值，函数是不能这样赋值的，于是当场翻脸。

补上括号 `int (*p)(int, int) = add;`，它就乖乖认了。**包着 `*p` 的那对小括号，是「这是只元素」和「这是一个方法」的分界线**。

## 七、名称上的长相，必须和函数对得上

还有一种错法：名称拿到了，可**名称上写的长相和函数不一样**。

```c
#include <stdio.h>

void hello(void) {
    printf("你好\n");
}

int main(void) {
    int (*p)(int) = hello;
    printf("%d\n", p(1));
    return 0;
}
```

```text
main.c:8:21: error: initialization of 'int (*)(int)' from incompatible pointer type 'void (*)(void)' [-Wincompatible-pointer-types]
```

编译器的原话是「**长相对不上**」：左边这个元素要保存的是「传入一个整数、返回一个整数」的名称；右边的 `hello` 是「不传入、也不返回」的函数。两边的长相不一样，它就不许你把它们放进同一个元素。

要修也好修：让函数长得和名称一致 —— 比如写一个方法「传入一个整数、印一句、再把那个数返回」的函数，赋值就对了。

**名称是「这招长什么样」的承诺。** 承诺和实物不一致，编译器在翻的阶段就拦下了 —— 这正是 C 让人安心的地方：这一类错**根本跑不起来**，你不可能带着它上考场。

::: tip 提示
今天收四句话：

1. **`int (*op)(int, int)`** 从里往外念：`op` 是装名称的元素，两头的 `int` 说的是「传入什么、返回什么」。
2. **函数名单独写出来就是那张名称**，`add` 和 `&add` 一样、`op(...)` 和 `(*op)(...)` 一样。
3. **名称能当数据递进别的函数**，于是「怎么干」和「什么时候干」就被拆开了 —— 这就是回调。
4. **包着 `*op` 的括号不能丢**，名称上的长相也必须和函数对得上。
:::
