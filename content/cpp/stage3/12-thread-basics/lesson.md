## 学习目标

本课学习多线程初步。重点包括thread、mutex、数据竞争、join。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、叫一个对象来干活

```cpp
#include <iostream>
#include <thread>
using namespace std;

void sayHi() {
    cout << "对象来了" << endl;
}

int main() {
    thread t(sayHi);
    t.join();
    cout << "两件事都干完了" << endl;
    return 0;
}
```

```text
对象来了
两件事都干完了
```

两句话就是全部：

- `thread t(sayHi);` 是**叫一个对象来干 `sayHi` 这件活**。名字写在圆括号里，它就认这个活儿。调用结束这一句，那个对象**立刻**就跑了 —— 主对象不等它，接着往下走。
- `t.join();` 念作「**在这儿等它回来**」。这一句站在哪儿，主对象就停在哪儿，等这个对象干完，才继续往下走。

顺序就是这么钉住的：第三行那个对象先印，等它回来了，主对象才印第四行。把 `join` 那一句挪到最后试试？那个对象什么时候印、主对象什么时候印，就**说不准了** —— 谁先抢到屏幕谁先印。

::: warn 注意
**调用来的对象，走之前必须有个交代。** 少写 `join()` 那一句，我们真跑过一遍：那个对象还在干活，主对象自己先收工走了，程序**当场摔下来**，编译器留下一句

`terminate called without an active exception`

念作「有件事还没收尾，我就被丢下了」。它没等你，也没等那个对象，直接了结。所以规矩是：**每一个调用来的对象，都得有一句 `join()` 接它回来**。
:::

::: tip 提示
对象多了以后，这段代码会变成一串 `thread t1(...)`、`thread t2(...)`、`thread t3(...)`，后面跟一串 `t1.join(); t2.join(); t3.join();`。看着啰嗦，但**一个对象配一句 `join`**，一个都不能漏 —— 漏掉的那个就是上面那句摔下来的话。
:::

## 二、各干各的，就不用排队

两个对象各数各的，谁也不碰谁的东西，井水不犯河水：

```cpp
#include <iostream>
#include <thread>
using namespace std;

int bowl1 = 0;
int bowl2 = 0;

void countFish() {
    int s = 0;
    for (int i = 1; i <= 4; i++) s = s + i;
    bowl1 = s;
}

void countKibble() {
    int s = 0;
    for (int i = 1; i <= 6; i++) s = s + i;
    bowl2 = s;
}

int main() {
    thread t1(countFish);
    thread t2(countKibble);
    t1.join();
    t2.join();
    cout << "数据 " << bowl1 << endl;
    cout << "商品 " << bowl2 << endl;
    cout << "一共 " << bowl1 + bowl2 << endl;
    return 0;
}
```

```text
数据 10
商品 21
一共 31
```

这里两个对象各数各的：一个把 1 到 4 加起来放进 `bowl1`，另一个把 1 到 6 加起来放进 `bowl2`。**两个对象谁也没碰对方的元素** —— 这种各干各的场面，什么额外的绳子都不用系。

第三行、第四行印出来的顺序也是钉死的：因为主对象**先 `join` 完了两个对象**才开口。要是让两个对象自己在状态里印，谁先抢到屏幕谁先印，那两行的先后就**每次都不一样**了。

## 三、共用一个元素，就得排队

现在来干开头那件正事：三个对象抢**同一个元素**，每个往里面加 900 次。

```cpp
#include <iostream>
#include <thread>
#include <mutex>
using namespace std;

int total = 0;
mutex mtx;

void addMany() {
    for (int i = 0; i < 900; i++) {
        lock_guard<mutex> guard(mtx);
        total = total + 1;
    }
}

int main() {
    thread t1(addMany);
    thread t2(addMany);
    thread t3(addMany);
    t1.join();
    t2.join();
    t3.join();
    cout << "一共 " << total << endl;
    return 0;
}
```

```text
一共 2700
```

三个对象各加了 900 次，加起来正好 2700 —— 一次都没丢。保住这个数的，是这么几件事：

- `#include <mutex>` 是把**锁**请进门。
- `mutex mtx;` 是造一把锁。注意它是**造在外面的、只有一把** —— 三个对象认的都是同一把锁。
- `lock_guard<mutex> guard(mtx);` 念作「**进门先锁上**」。它站在要护住的那句话前面，一出花括号就自动开锁 —— 中途摔了也照样给你开。所以**只要这一句写在加数前面，就不用自己记着开锁**。

::: warn 注意
**为啥要排队？** 两个对象同时伸手进同一个元素：都读到 `total` 是 `500`，各自加一写回去 —— 元素里还是 `501`，有一个手白加了。这就叫**抢元素**。

可我们得老实交代一件事：**这件坏事不是每次都露面**。抢元素只是**可能**丢，跑十遍说不定十遍都碰巧全对，也可能第一遍就少一个数 —— 跟当天几个对象的步子凑不凑巧有关。

所以加锁不是为了「让它算对」（不加锁它本来就常常碰巧对），而是为了**让对不对这件事由你说了算**：加了锁，2700 就是 2700，跑一百遍也是 2700；不加锁，你只能祈祷。想亲手见识一下，就把 `lock_guard` 那一句删掉，多跑几遍看看。
:::

::: warn 注意
**锁必须只有一把。** 要是每个对象都自己造一把锁（比如把 `mutex mtx;` 写在 `addMany` 里面），那就是三把锁各守各的门 —— 谁也不用等谁，跟没锁一模一样。判断方法很土但很准：**锁是不是造在大家都能看见的地方**，是就对了。
:::

## 四、分头干，回来再汇总

真实的活法是：把活**分成几份**，一个对象包一份，最后主对象把大家的结果合起来。

```cpp
#include <iostream>
#include <thread>
using namespace std;

int front = 0;
int back = 0;

void addFront() {
    int s = 0;
    for (int i = 1; i <= 3; i++) s = s + i;
    front = s;
}

void addBack() {
    int s = 0;
    for (int i = 4; i <= 6; i++) s = s + i;
    back = s;
}

int main() {
    thread t1(addFront);
    thread t2(addBack);
    t1.join();
    t2.join();
    cout << "前半 " << front << endl;
    cout << "后半 " << back << endl;
    cout << "一共 " << front + back << endl;
    return 0;
}
```

```text
前半 6
后半 15
一共 21
```

这段和第二节长得像，但多了一条规矩：**每一个对象算完，先把结果放进自己的元素，一次不吭**；等两个都回来了，主对象才开口印。这样印出来的三行，跑一百遍都是这三行，一个字都不会换位置。

要是让两个对象自己在状态里印呢？两个对象同时张嘴，谁的字先落到屏幕上**说不准**。所以这一课的口诀是：

> **对象可以乱跑，嘴不能乱开 —— 等大家都到齐，主对象统一开口。**

::: tip 提示
共用同一个元素要加锁；各用各的元素不用加锁。判断方法很直接：**这一段话里有几个对象的手同时伸进同一个元素** —— 一个都没有，就不用排队的绳子；有，就得找那把大家共用的锁。
:::

## 一句话对照表

| 想干什么 | 写什么 |
|---|---|
| 请几位帮手进门 | `#include <thread>` |
| 叫一个对象来干某件活 | `thread t(活儿);` |
| 在这儿等它回来 | `t.join();` |
| 请锁进门 | `#include <mutex>` |
| 造一把大家共用的锁 | `mutex mtx;`（造在外面，只造一把） |
| 进门先锁上、出门自动开 | `lock_guard<mutex> guard(mtx);` |
| 等大家都回来再统一印 | 先把每一个都 `join`，再 `cout` |
