## 学习目标

本课学习模板特化。重点包括全特化、偏特化、类型萃取直觉、特化与重载怎么选。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、先认一遍通用那份

（前情提要：这套东西的正式名字是 模板（模板），前面有一课讲的就是它。）

```cpp
#include <iostream>
using namespace std;

template <typename T>
void show(T x) {
    cout << "通用那一份：料是 " << x << endl;
}

int main() {
    show(7);
    show(2.5);
    show(true);
    return 0;
}
```

```text
通用那一份：料是 7
通用那一份：料是 2.5
通用那一份：料是 1
```

三次递料，编译器照这张类定义裁了三版，**三版都是同一套做法**，所以三行的开头一模一样。第三行那个 `1`，就是「对错料」被通用做法摊开之后的样子：它心里保存的是「真」，摊开却成了 `1`。

今天要动的手脚就在这儿：**让第三行走另一套做法，而前两行纹丝不动。**

## 二、给一款料单开一个小灶

小灶的写法，就是在通用那份**下面**再接一段。关键全在头上两行：`template <>` 和 `void show<bool>(bool x)`。

- **`template <>`** —— 这一对**空的尖括号**是本课第一件要记牢的东西。它的意思是：通用那份类定义头上那个空位，**这一份一个都不留**。空位有几个，这里就该填几个；通用那份只留了一个空位 `T`，填完就是空的。
- **`show<bool>`** —— 光说「不留空位」还不够，还得说清**是哪一款料**。`<bool>` 把料写死了：这一份只认对错料，别的料递进来它不管。

所以这一对是有分工的：**空的尖括号说「不留给别人填」，名字后面那对尖括号说「留给哪一款料」。** 少一个都不行 —— 少了 `template <>`，编译器以为我们在给空位另起一个名字；少了 `<bool>`，它根本不知道这个小灶是给谁的。

::: tip 提示
`template <>` 里那对尖括号**一个字都不能有**，连空格都不该有。

我们见过有人写成 `template <typename T>` 的 —— 那不是小灶，那是**又立了一个新空位**，编译器会以为我们把同一个类定义画了第二遍，然后大声抱怨重定义。
:::

接上小灶，整段就是我们真跑过的这一段：

```cpp
#include <iostream>
using namespace std;

template <typename T>
void show(T x) {
    cout << "通用那一份：料是 " << x << endl;
}

template <>
void show<bool>(bool x) {
    cout << "小灶那一份：料是 " << (x ? "对" : "错") << endl;
}

int main() {
    show(7);
    show(2.5);
    show(true);
    show(false);
    return 0;
}
```

```text
通用那一份：料是 7
通用那一份：料是 2.5
小灶那一份：料是 对
小灶那一份：料是 错
```

前两行走通用那份，后两行走小灶那份。**同一份模具、同一句话递进去，只有那一款料换了一套做法。** 上面这段代码一个字都没提到「对错料该怎么印」以外的任何东西，也没让整数和小数受到半点影响。

递料的时候我们**什么多余的话都没说**（引用的还是 `show(true)`，没写 `show<bool>(true)`）—— 编译器自己看出来递进来的是对错料，然后自己拐进了小灶。下面这段演示把「它拐进哪一份」摊开给你看。

## 三、会裁料的类定义那边：两种小灶都有

上面开小灶的是**会干活的类定义**（函数）。我们再带你看**会裁料的类定义** —— `struct` 那种，用来把一小包东西装在一起的。它那边的小灶有两种，分工不一样。

```cpp
#include <iostream>
using namespace std;

template <typename T>
struct Tag {
    static const char* name() { return "普通料"; }
};

template <typename T>
struct Tag<T*> {
    static const char* name() { return "指针"; }
};

template <>
struct Tag<bool> {
    static const char* name() { return "对错料"; }
};

int main() {
    cout << Tag<int>::name() << endl;
    cout << Tag<double>::name() << endl;
    cout << Tag<int*>::name() << endl;
    cout << Tag<bool*>::name() << endl;
    cout << Tag<bool>::name() << endl;
    return 0;
}
```

```text
普通料
普通料
指针
指针
对错料
```

这五行里，两种小灶的差别摆得清清楚楚：

**`struct Tag<bool>`** 头上挂的是 `template <>` —— 空位一个都不留，这是**全特化**：整款料写死，只有对错料能走这一份。所以第五行走它，前两行（整数、小数）还是通用那份。

**`struct Tag<T*>`** 头上挂的是 `template <typename T>` —— **空位还留着**，我们只填了一半。这句话输出是：「**凡是指针**，不管它指向的是什么料，都走这一份」。这是**偏特化**，也可以念「部分特化」。所以第三行（照着整数做的指针）和第四行（照着对错料做的指针）都走它 —— 「指针里保存的是什么」这个空位，照样留给别人填。

一张对照表：

| 小灶的写法 | 空位怎么办 | 管多宽 |
|---|---|---|
| `template <>` + `struct Tag<bool>` | 一个都不留 | 只认写死的那一款料 |
| `template <typename T>` + `struct Tag<T*>` | 留着一部分 | 所有指针都管，不管它指向什么 |
| `template <typename T>` + `struct Tag<T>` | 全留着 | 这就是通用那份 |

::: tip 提示：让小灶自己回答「我是什么形状的料」
`Tag<T*>` 这份小灶最值钱的地方，不是它能印出「指针」三个字，而是**一个类定义能自己回答「递进来的料是什么形状」**。

递一款料进去，问它一句 `Tag<...>::name()`：

- 是「指针」这一款形状 → 偏特化那份接住，回答「指针」；
- 是对错料 → 全特化那份接住，回答「对错料」；
- 别的 → 通用那份接住，回答「普通料」。

我们**从头到尾没碰过那块料本身**，只看它的款式就拿到了结论。标准库里那一整套 `std::is_pointer` 之类的家伙，就是这么写出来的 —— 先给通用那份一个「默认答案」，再给各种形状各开一个小灶。这就是**类型萃取的直觉**：不问料，只问款式。
:::

## 四、函数那边：只有全特化，没有偏特化

这是本课最容易记错的一条，我们先把结论摆出来：

- **会裁料的类定义**（`struct` 那种）：全特化、偏特化，**两种都能开**。
- **会干活的类定义**（函数）：**只有全特化**。想给「一整种形状」开小灶这件事，函数那边**办不到**。

我们真的试过。先画一张通用那份，再想给它补一份「凡是指针都走这一份」的小灶：

```cpp
#include <iostream>
using namespace std;

template <typename T>
void show(T x) {
    cout << "通用那一份" << endl;
}

template <typename T>
void show<T*>(T* x) {
    cout << "指针专用" << endl;
}

int main() {
    int n = 3;
    show(&n);
    return 0;
}
```

编译器当场就把我们拦下了：

```text
main.cpp:10:6: error: non-class, non-variable partial specialization 'show<T*>' is not allowed
```

念作：「**`show<T*>` 这种东西，我们只认会裁料的类定义，函数不许这么写。**」

它拦得有道理。函数的世界里，「递进去的料不一样」这件事**早就有一套自己的办法** —— 同名、不同料，就**再画一张**。这叫重载：名字一样，后面括号里收的料款式不同或者个数不同，编译器就当成两张不同的类定义。

那条路我们也真跑过：

```cpp
#include <iostream>
using namespace std;

template <typename T>
void show(T x) {
    cout << "通用那一份" << endl;
}

template <typename T>
void show(T* x) {
    cout << "指针那一份" << endl;
}

int main() {
    int n = 3;
    show(&n);
    show(n);
    return 0;
}
```

```text
指针那一份
通用那一份
```

两张类定义同名，编译器按递进去的料挑：`&n` 是指针那一款，第二张类定义正好接得住，就走它；`n` 本身是整数，第二张类定义收不了，退回第一张。

::: tip 提示
**函数为什么没有偏特化？** 因为这件事函数早就用自己的办法解决了 —— 再画一张同名类定义就行，而且挑起来比小灶更灵活（两张同名类定义可以靠「料的**个数**不同」分开，小灶只能靠款式）。

所以只记这一句：**「某款料写死」找小灶；「一整种形状」这件事，函数交给同名类定义，会裁料的类定义交给偏特化。**
:::

## 五、小灶和另一张同名类定义撞上了，编译器挑谁

现在两种「给一款料换一套做法」的手段都摆上桌了：**全特化**（小灶）和**再画一张同名类定义**（重载）。要是一张通用那份、一份全特化小灶、再一张同名类定义**三个同时在场**，编译器会挑谁？

我们真跑了这么一段，三张都在场，各自印一句自己的名号：

```cpp
#include <iostream>
using namespace std;

template <typename T>
void pick(T x) {
    cout << "类定义裁出来的那一份" << endl;
}

template <>
void pick<int>(int x) {
    cout << "整数小灶" << endl;
}

void pick(int x) {
    cout << "直接写的那一份" << endl;
}

int main() {
    pick(7);
    pick<>(7);
    pick(2.5);
    return 0;
}
```

```text
直接写的那一份
整数小灶
类定义裁出来的那一份
```

三行对应三次输出，我们一行一行说：

1. **`pick(7)`** —— 递的是整数。「直接写的那一份」和「整数小灶」两边都接得住，一样好。这时候编译器有一条定死的规矩：**一样好的时候，不是类定义裁出来的那位赢**。所以第一行走「直接写的那一份」。
2. **`pick<>(7)`** —— 尖括号里一个都不写，但**写了这对尖括号**，等于对我们说「这次就调用类定义裁出来的那份」。于是整数小灶上班了。
3. **`pick(2.5)`** —— 小数。小灶只认整数，直接写的那份也只收整数，两边都接不住，于是退回通用那份。

::: warn 注意
把这三行连起来读，是一条很实在的纪律：**同一款料，你既写了小灶、又写了同名类定义，那个小灶多半是白开的** —— 平时输出不会写那对空尖括号，赢的永远是直接写的那一份。

所以选路只走一条，别两头都占：

- 只想让这一款料有专属做法、也不打算点名 → **直接画一张同名类定义**，简单直接；
- 想让这一款料有专属做法、还要留着以后点名调用小灶的路 → **写全特化**，但记住**平时输出轮不到它**，得像 `pick<>(7)` 那样点名才轮得到。

两条都不做，就是让通用那份顶上去。那也是合法的，只是通用那份可能干不好 —— 本课开头那个 `1` 就是这么来的。
:::

## 六、小灶要摆在使用它之前，而且材料要对得上

小灶是**静静地生效**的：它不吵不闹，你不去核对，就不知道它到底上没上班。我们踩了两个坑，都真跑过。

### 坑一：小灶摆在使用它之后

```cpp
#include <iostream>
using namespace std;

template <typename T>
void label(T x) {
    cout << "通用那一份" << endl;
}

void callIt() {
    label(7);
}

template <>
void label<int>(int x) {
    cout << "小灶那一份" << endl;
}

int main() {
    label(7);
    callIt();
    return 0;
}
```

```text
main.cpp:14:22: error: specialization of 'void label(T) [with T = int]' after instantiation
```

念作：「**整数那一份，我们在上面已经照通用做法裁过一次了，你现在才把小灶递上来 —— 晚了。**」

这一条编译器拦得很干脆，反倒不吓人。**真正吓人的是它有时候不拦** —— 看下一个坑。

### 坑二：料的名字差一点点，小灶就静默不生效

```cpp
#include <iostream>
using namespace std;

template <typename T>
void label(T x) {
    cout << "通用那一份" << endl;
}

template <>
void label<char*>(char* x) {
    cout << "小灶那一份" << endl;
}

int main() {
    char name[] = "计算机";
    label(name);
    label("数据");
    return 0;
}
```

```text
小灶那一份
通用那一份
```

小灶明明写了，第二行为什么没走它？

因为我们给小灶写的是 `char*` —— 「**能改**的一条名字」；而第二条递进去的是**字面上的名字**，那东西的款式是 `const char*` —— 「**不能改**的一条名字」。款式差了一点点，小灶不认，编译器**一次不吭**地退回通用那份。

**这是本课最贵的坑**：小灶不生效的时候，屏幕上一点异样都没有 —— 跑得起来、印得出东西、编译器一句话都不说。只有你**对着答案一行行核对**，才发现不对劲。

::: warn 分成两份源文件写的时候，它更不吭声
上面那个坑，编译器至少还看得见两份东西都摆在同一份文件里。**分开写的时候它连看都看不见。**

编译器一次只翻**一份**源文件。小灶要是只写在 A 那份里，B 那份压根不知道有这么个小灶 —— 那边照通用那份编好、跑起来也照通用那份走。我们拿两份源文件试过：合到一起的时候**一句提示都没有**，两边都走了通用那份，屏幕上看着就像「小灶根本没写」。

所以本课最该带走的一条纪律：**小灶必须摆在「用它」的地方之前，而且要和用它的人看的是同一份 —— 通常是同一份头文件里。** 别把小灶藏在一份别人看不见的源文件里。
:::

## 一句话对照表

| 我们写下的 | 它的意思 |
|---|---|
| `template <typename T>` + `void show(T x)` | 通用那份：头上留一个空位 |
| `template <>` | 小灶那份：一个空位都不留 |
| `void show<bool>(bool x)` | 把料写死成对错料 —— 全特化 |
| `struct Tag<bool>` | 空位一个都不留 —— 全特化（会裁料的类定义、函数都能写） |
| `struct Tag<T*>` | 只填一半，空位还留着 —— 偏特化（**函数那边不许这么写**） |
| `pick(7)` 三张都在场时 | 一样好的时候，不是类定义裁出来的那位赢 |
| `pick<>(7)` | 点名调用类定义裁出来的那份 |
| `error: non-class, non-variable partial specialization 'show<T*>' is not allowed` | 函数不许偏特化 |
| `error: specialization of 'void label(T) [with T = int]' after instantiation` | 小灶摆在使用它之后 |
| 小灶静默不生效 | 料的名字差一点点（`char*` 和 `const char*`），或者小灶藏在别人看不见的地方 |
