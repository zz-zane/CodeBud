## 学习目标

本课学习g++ 编译与运行。重点包括g++ 是什么、编译流程、在软件里跑 C++ 代码。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 先说清三件后果

「编译型」这三个字只说了三件事，每一件你马上就能感受到。

**第一件：翻不过去，一行都不跑。**

这是最要紧的一条。源代码里只要有一处翻不通，编译器**不会**帮你把前面写对的几句先输出。它一份都不交，程序连一行都不许跑。所以往后你看到屏幕上「什么都没输出」时，第一个该想的是：**它到底翻过去了没有？**

**第二件：翻完再跑，跑起来快。**

因为交到你手里的那份东西，已经是电脑能直接照着念的了，中间不再需要谁替它转话。

**第三件：翻一次，能跑很多次。**

那叠誊好的源代码会**存成一份文件**躺在硬盘上。往后想跑几遍跑几遍，不用重新翻——这一条下面有个坑，我们要专门讲。

## 那位编译器叫 g++

我们称呼它编译器，可电脑不认自然语言，你在命令窗口里得称呼它的名字：**g++**。

这名字挺好认：C 那门语言的编译器叫 `gcc`，C++ 的编译器就是在名字后面挂了两个加号。这两个加号说的正是上一课那句话——**在 C 的底子上又加了几样东西**，编译器也跟着学了一手新的。要是你在别处见过那位不带加号的，往下照旧，调用方式一个样。

称呼它干活的写法，和上一课一个样子：**先说名字，再报上要翻的源代码，最后用 `-o` 指名把成品放哪儿**：

```text
g++ main.cpp -o prog.exe
```

`main.cpp` 是你的源代码（我们的软件里默认就叫这个名字），`prog.exe` 是你要它交出来的成品。

::: tip 提示
`.cpp` 是 C++ 源代码的门牌，`.exe` 是能跑起来的成品的门牌。

往后看到 `.cpp`，你就知道「这是一份还没翻的源代码」；看到 `.exe`，就是「这是一份翻好的成品」。两者长得完全不一样，别把它们弄混——**`.cpp` 不能跑，`.exe` 不用翻**。
:::

## 四道工序：一份源代码怎么变成能跑的东西

编译器抱着你的源代码回去，关起门来干的其实是**四道工序**。平时你不必管它们，但哪天程序出了怪毛病，知道是哪一道断的，能省下大把抓耳挠腮的时间。

拿下面这份源代码当例子，我们把四道工序一道道走给你看。源代码一共一百七十六字节，就是它：

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "编译器把整本翻完啦" << endl;
    cout << "现在轮到我们跑一遍" << endl;
    return 0;
}
```

```text
编译器把整本翻完啦
现在轮到我们跑一遍
```

### 第一道：预处理——把请来的管理员家里的东西抄进来

上一课那句 `#include` 是请管理员出场，对吧？这一道工序干的就是把管理员家里的内容**原样抄到你的源代码开头**。

```text
g++ -E main.cpp -o main.i
```

产出一份 `main.i`。我们真跑过：那份一百七十六字节的小源代码，抄出来变成了一百三十八万七千多字节——**大了将近八千倍**。你自己写的那几行原封没动，多出来的全是从管理员家里搬来的家当。

### 第二道：编译——把 C++ 翻成汇编

第二道工序才真的在「翻」：把 C++ 的句子翻成一种更接近机器、但还留着一行行人话的源代码。

```text
g++ -S main.i -o main.s
```

产出一份 `main.s`，我们这份是一千九百多字节。想看热闹可以打开它瞄一眼——我们劝你只看一眼就好，那里面的写法是给机器看的，不是给你看的。

### 第三道：汇编——翻成目标文件

```text
g++ -c main.s -o main.o
```

产出一份 `main.o`，叫**目标文件**，我们这份一千八百多字节。它里面已经是机器能读的东西了，可它**还不能跑**——它是一块缺了零件的半成品。

缺什么零件呢？你用了 `cout` 这一个方法，可这一个方法的**身子**（真正干活的那些机器码）并不在你的源代码里，它住在管理员家里。目标文件里只留了一张欠条：「这里缺一个 `cout`」。

### 第四道：链接——把零件拼上，才能跑

```text
g++ main.o -o prog.exe
```

这道工序叫**链接**：编译器拿着你的目标文件，把它欠的零件一件件找来、缝上去，最后交出一份**完整、能自己跑**的成品。我们这份成品六万两千多字节——比源代码大了三百多倍，里面装的全是给你兜底的家伙什。

到这一步才算真的翻完。

编译器关起门走的这四道工序，我们拆成一步一步，走给你看：

### 一条命令，四步全办

四道工序走完，你手上有 `.i`、`.s`、`.o`、`.exe` 四份文件。可平时我们从来不这么敲——**一条命令就够**：

```text
g++ main.cpp -o prog.exe
```

这一条命令，编译器会自己把四道工序跑一遍，中间那三份半成品它**用完就扔**，只把最后的成品留给你。我们试过：敲完这一条，目录里只剩 `prog.exe`，`.i`、`.s`、`.o` 一份都不见了。

所以你在软件里点「运行」之后看到的那一闪，背后就是这两件事：

```text
g++ main.cpp -o prog.exe
./prog.exe
```

先**翻**，再**跑**。这一步千万别记反：`.exe` 不会自己出现，`.cpp` 也不会自己跑起来。

还有一件事要提醒你：编译器翻完就收工，**一次不吭**。它不会念「翻译完成」「链接成功」这类话。所以「没反应」和「跑成功了」经常长得一模一样——想分清它们，看的不是它有没有说话，而是**屏幕上有没有出现你让它念的那句话**。

::: warn 注意
**不写 `-o` 会怎样？** 编译器会用一个默认的名字。我们真跑过：它会创建一份叫 `a.exe` 的东西，安安静静地躺在那儿。

问题是——**它也不报错**。你敲完命令看到光标回来了，会以为万事大吉，然后到处找 `prog.exe` 找不到。所以我们的规矩是：**每次都写 `-o`**，指名道姓，省得回头找文件。
:::

## 翻不过去的时候，屏幕上是什么样

现在来看那条最要紧的后果。我们把上面那份源代码的**第二句**弄坏——末尾漏了个分号，第一句是完好的：

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "编译器把整本翻完啦" << endl;
    cout << "现在轮到我们跑一遍" << endl
    return 0;
}
```

```text
main.cpp: In function 'int main()':
main.cpp:6:41: error: expected ';' before 'return'
```

请盯着这段报错看三秒，然后回答我们一个问题：**「编译器把整本翻完啦」输出了吗？**

**没有。一个字都没有。**

这就是编译型的脾气：第一句明明是对的，可编译器整本翻到第二句时卡住了，于是**整份源代码一份都不交**，程序根本没开跑，哪一句都轮不上。要是换成「边念边翻」的语言，屏幕上本该先出现第一句、然后才炸——C++ 不会给你这个机会。

报错里那句 `main.cpp:6:41` 是编译器在告诉你：它卡在第 6 行的第 41 个字符。顺着它指的地方看一眼，分号就补上了。

### 它连源代码本身都找不到的时候

还有一种更早的失败：源代码压根不在那儿。我们把文件名敲错一个字，编译器当场就急了：

```text
cc1plus.exe: fatal error: meiyou.cpp: No such file or directory
compilation terminated.
```

`No such file or directory`——「没有这份文件，也没有这个目录」。看到这一句，先去数一数文件名有没有敲错、源代码是不是和你在同一个目录里，别急着怀疑自己写的代码。

::: warn 注意
**改了源代码忘了重新翻，是新手最冤枉的一种「改了没用」。** 我们真跑过这么一遍：

1. 先把源代码改坏一点点，再敲一次 `g++ main.cpp -o prog.exe`——这次翻不过去，编译器报了错；
2. 可我们低头一看，**上一版留下的 `prog.exe` 还老老实实躺在原地**，一个字节都没变；
3. 我们顺手跑了一下 `./prog.exe`——屏幕上输出的**还是旧的那两句**。

编译器翻不动，是**它不给你新成品**，而不是**把旧的删掉**。你要是不看报错、直接跑，看到的就是旧成品的结果，怎么改都不变，越改越糊涂。

所以记住这条链子：**源代码改一个字，就得重新翻一次**；翻完先看有没有报错，再看屏幕。改动 → 重翻 → 跑，一步都不能跳。
:::

::: tip 提示
今天记住这条链子和它的两部：

**`main.cpp` --（g++ 四道工序）--> `prog.exe` --（跑）--> 屏幕上的字**

1. **命令的形状**：`g++ 稿子.cpp -o 成品.exe`，`-o` 是「指名成品放哪儿」，别省；
2. **先翻再跑**：`.cpp` 不能跑，`.exe` 不用翻，中间那一步不能跳。

再加一句：软件里点「运行」，做的就是这两步——先替你翻，再替你跑。你看到的报错，就是编译器在翻的那一步拦下来的。
:::
