## 学习目标

本课学习设计模式。重点包括单例、工厂、观察者、模式思想。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、套路一：全窝只有一个的那件东西

**麻烦长这样：** 我们的窝里其实只有**一个**数组元素。可谁想用元素，就在自己那一处写一句「造一个元素」—— 三处写了三句，就造出三个元素。三个元素各记各的存量：我们往自己这个里添了五条数据，另一处去看还是空的。

**摆法：** 让「拿这个元素」这件事**怎么调用都只给同一个**。

```java
public class Main {
    public static void main(String[] args) {
        数组元素 甲 = 数组元素.拿元素();
        数组元素 乙 = 数组元素.拿元素();
        甲.存量 = 甲.存量 + 5;
        System.out.println("是同一个元素吗：" + (甲 == 乙));
        System.out.println("乙 里看到的存量：" + 乙.存量);
    }
}

class 数组元素 {
    private static 数组元素 唯一的一个;

    int 存量;

    private 数组元素() {
    }

    static 数组元素 拿元素() {
        if (唯一的一个 == null) {
            唯一的一个 = new 数组元素();
        }
        return 唯一的一个;
    }
}
```

```text
是同一个元素吗：true
乙 里看到的存量：5
```

拆开看，这段摆法就三样东西：

- **`private static 数组元素 唯一的一个;`** 是写在**类定义上**的一格。`static` 那句的意思是「这一格归类定义自己，不归哪个实例」—— 所以它是全窝**共用**的那一格，我们把唯一那个是不是已经造出来了记在这儿。
- **`private 数组元素()`** 是把**产房锁上**。别人想自己造一个？编译器这一关就过不去：

```java
public class Main {
    public static void main(String[] args) {
        数组元素 元素 = new 数组元素();
        System.out.println("造出来了：" + 元素.存量);
    }
}

class 数组元素 {
    private static 数组元素 唯一的一个;

    int 存量;

    private 数组元素() {
    }

    static 数组元素 拿元素() {
        if (唯一的一个 == null) {
            唯一的一个 = new 数组元素();
        }
        return 唯一的一个;
    }
}
```

```text
Main.java:3: error: 数组元素() has private access in 数组元素
```

- **`static 数组元素 拿元素()`** 才是门口那个口子。它的心思只有一句：**类定义那一格还空着，就造一个、造完顺手记进去；已经记着了，就直接把那一个递出去。** 所以 `甲` 和 `乙` 拿到的是**同一个**元素 —— 往里添五条数据，两边看都是五条。`甲 == 乙` 那句问的就是「是不是同一个」，答 `true`。

> **对象在院里踩的坑：画在 `Main` 里面的类定义，锁不住自己人。**
> 我们头一回演示「不许自己造」，是把 `数组元素` 画在 `Main` **里面**的 —— 结果 `new 数组元素()` 居然**放行了**。原因跟第 16 课那个盖子是同一条：画在自己身上的类定义，自己人够得着。想演示「被拦下来」，得把两张类定义**平着摆**（像上面这样：一张 `Main`、一张 `数组元素`），谁都够不着谁的口袋。

还有第二种摆法：**一上来就造好**，不等谁来调用。

```java
public class Main {
    public static void main(String[] args) {
        数组元素 甲 = 数组元素.拿元素();
        数组元素 乙 = 数组元素.拿元素();
        System.out.println("是同一个元素吗：" + (甲 == 乙));
    }
}

class 数组元素 {
    private static final 数组元素 唯一的一个 = new 数组元素();

    int 存量;

    private 数组元素() {
    }

    static 数组元素 拿元素() {
        return 唯一的一个;
    }
}
```

```text
是同一个元素吗：true
```

那一格直接写死成 `new 数组元素()`，拿元素的时候连判都不用判，直接递出去。两种摆法都对：前一种是**用到才造**，后一种是**一上来就造好**。规矩少的窝用后一种更省事；那个元素造起来很贵（比如要连一趟远处工作区）的时候，用前一种更划算。

这个套路的正式名字叫**单例** —— 一组只留一例。什么时候值得这么摆：全窝**真的只有一份**的东西 —— 一份共用的设置、一个连远处工作区的口子、一本账。什么时候**别**这么摆：只要我们自己都说不清「为什么只能有一个」，那就别硬凑 —— 造两个元素不会塌天。

## 二、套路二：领养处

**麻烦长这样：** 来领对象的对象，其实**不关心**自己领的是学生甲还是学生乙 —— 她只想知道「我要一个对象」。可她得亲手写下品种的名字、还得知道新品种是怎么造出来的。哪天窝里多一个品种，她那段代码就得跟着改。

**摆法：** 开一间**领养处**。来领对象的只报一句「要什么样的」，剩下的事领养处自己掂量。

```java
public class Main {
    static abstract class 子对象 {
        abstract String 输出结果();
    }

    static class 学生甲 extends 子对象 {
        @Override
        String 输出结果() {
            return "";
        }
    }

    static class 学生乙 extends 子对象 {
        @Override
        String 输出结果() {
            return "嗷";
        }
    }

    static 子对象 领养一个(String 花色) {
        if (花色.equals("橘")) {
            return new 学生甲();
        }
        return new 学生乙();
    }

    public static void main(String[] args) {
        for (String 花色 : new String[]{"橘", "李四", "花"}) {
            System.out.println(花色 + " -> " + 领养一个(花色).输出结果());
        }
    }
}
```

```text
橘 -> 
李四 -> 嗷
花 -> 嗷
```

拆开看：

- **`领养一个(花色)`** 就是门口那间领养处。你报花色，它去后面挑一个递给你；你拿到手就能调用 `输出结果()`，**从头到尾不知道**它是照哪张类定义创建后的。递回来的东西写在上一代那张类定义的名字上（`static 子对象 领养一个(...)`）—— 所有品种都是它的后辈，所以哪个都装得下。
- 好处落在**改一处**上：将来窝里添一个品种，改动只发生在**领养处这一处**；所有来领对象的地方一个字都不用动。
- 上面第三行「花」拿到的是学生乙 —— 因为领养处只认「橘」这个字，别的都走最后那条兜底的路。**兜底给谁，你说了算**：想让它兜给学生甲，就把最后那句改成 `new 学生甲()`，别的都不用动。
- 这个套路的正式名字叫**工厂** —— 造东西的地方。别人不自己造，来这儿领。

## 三、套路三：摇铃与听众

**麻烦长这样：** 处理要通知全窝的对象。要是摇铃那位手上**攥着一份名单**、还得挨个知道「张三听见了会冲向元素、煤球听见了会先翻个身」，那每加一个对象，她手里那份名单和那一串「谁听见了会怎样」都得改。

**摆法：** 摇铃的**只管摇**，谁要听谁自己**订**上来。

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    interface 听众 {
        void 听见了(String 菜名);
    }

    static class 处理铃 {
        List<听众> 名单 = new ArrayList<>();

        void 订上(听众 一位) {
            名单.add(一位);
        }

        void 摇铃(String 菜名) {
            for (听众 一位 : 名单) {
                一位.听见了(菜名);
            }
        }
    }

    static class 对象 implements 听众 {
        String 名字;

        对象(String 名字) {
            this.名字 = 名字;
        }

        public void 听见了(String 菜名) {
            System.out.println(名字 + " 冲向 " + 菜名);
        }
    }

    static class 延迟执行 implements 听众 {
        String 名字;

        延迟执行(String 名字) {
            this.名字 = 名字;
        }

        public void 听见了(String 菜名) {
            System.out.println(名字 + " 翻了个身，继续睡");
        }
    }

    public static void main(String[] args) {
        处理铃 铃 = new 处理铃();
        铃.订上(new 对象("张三"));
        铃.订上(new 延迟执行("煤球"));
        铃.摇铃("数据");
        铃.摇铃("商品");
    }
}
```

```text
张三 冲向 数据
煤球 翻了个身，继续睡
张三 冲向 商品
煤球 翻了个身，继续睡
```

拆开看：

- **`听众` 是一份约定**：说好会这一个方法的都算数。铃的名单里收的就是「会这一个方法的对象」（`List<听众> 名单`），所以它**不知道**名单上坐着的到底是对象还是延迟执行。
- **`处理铃` 只管两件事**：谁能订上（`订上`）、摇的时候挨个通知（`摇铃`）。它**不知道**每个对象听见了会做什么 —— 它只负责挨个调用一句 `听见了`，剩下的是每个对象自己的事。
- 这正是已有实现对象那句「**多态调用**」：同一句 `听见了` 输出，`对象` 冲过来了、`延迟执行` 翻个身继续睡 —— **说好的那一个方法名字一样，各对象按自己的性子接**。你只管在每个对象自己的类定义上写它的接法（那两个 `implements 听众` 后面的写法，就是干这个的）。
- 好处还是**改一处**：明天要加一个学生丙，**铃那边一个字都不用改**，只要她自己也 `订上` 就行。
- 这个套路的正式名字叫**观察者** —— 一件东西动了，所有订上来的都跟着动。什么时候值得：一件事发生了，**有一个以上的地方要跟着动**，而且这些地方**将来还会增减**。人少又固定的时候，直接挨个引用名称反而更清楚。

## 四、套路怎么认、怎么用

三个套路长得差得远，可它们仨身上有个共同点：**都在把「改一处」变成现实。**

- 单例：想知道「哪儿有那个元素」，只有一处 —— 门口那个口子。
- 工厂：想添一个品种，只有一处 —— 领养处。
- 观察者：想加一个听众，只有一处 —— 她自己订上来那一下。

所以认套路的法子很简单：**看这段代码里，「将来要变的那件事」被关在了几个地方。** 关在一处，就是好摆法；散在七八处，就是我们开头那段账。

还有三句实话得说在前头：

- **别为了用套路而用套路。** 只有一份的东西才叫单例；只造一个品种的地方，直接 `new` 反而更清楚。已有实现对象记这些摆法，是为了**少疼几回**，不是为了让源代码看起来高级。
- **套路有名，但名字不是重点。** 我们这一课只说了三个；往后你会在别人的本子里撞见更多名字。撞见的时候别急着记名字，先看**谁手里攥着什么、谁不认识谁** —— 看懂了那一层，名字自己就挂上去了。
- **这一课学的三个摆法，都是用来「少改几处」的。** 第 17 课那张纸条也一样（「这招过时了」一句话，全窝的对象都看得见）—— 设计模式和纸条是一路的：**把话留在一个地方，让别的对象自己来读**。

## 一句话小抄

| 我们想干什么 | 摆法 |
| --- | --- |
| 全窝只留一个 | 类定义上留一格 `private static 数组元素 唯一的一个;` |
| 不许别人自己造 | 产房锁上：`private 数组元素()` |
| 用到才造 | `拿元素()` 里判一下空着没有，空着才 `new` |
| 一上来就造好 | 那一格直接写死 `private static final ... = new 数组元素();` |
| 别人不自己造、来领 | 一间 `static 子对象 领养一个(花色)`，报花色给东西 |
| 兜底给谁 | 领养处最后那一句 `return`，你说了算 |
| 谁要听谁自己订 | 铃里一个柜子 `List<听众> 名单`，`订上()` 塞进去 |
| 摇铃不知道细节 | 名单里只收「会那一个方法的对象」（那份约定），不写品种 |

::: tip 提示

- **套路不是代码，是摆法**：这一课要看的是「谁手里攥着什么、谁该不认识谁」，不是那几个字怎么写。
- **三个套路干的是同一件事**：把「将来要变的那件事」圈在一处 —— 单例圈在门口那个口子、工厂圈在领养处、观察者圈在「谁要听谁自己订」那一下。
- **摇铃的那位只管摇**：它不认识名单上坐的是谁，也不管各对象听见了会做什么。
- **别为了用套路而用套路**：只有一份的东西才叫单例，只造一个品种的地方直接造反而更清楚。
- **演示「不许自己造」的时候，两张类定义得平着摆** —— 画在自己身上的类定义，锁不住自己人。

:::

## 小任务

1. 给单例那口元素添一个方法 `void 添(int 几条)`，在两处各添一次，再清点一遍 —— 数对不对？再想想：要是我们偷偷把产房那把锁去了，会出什么事（我们试过：`new 数组元素()` 的画法在**平着摆**的类定义里是会被拦下的）。
2. 给领养处添一个品种（比如学生丙），数一数**总共改了几处**；再多调用几个花色去领，看看兜底那一支都给了谁。
3. 给观察者加一个「只记账、不出声」的听众（拿个柜子把菜名收着，摇完铃再一次性印出来），加完之后看**铃那一个类定义动没动**。
