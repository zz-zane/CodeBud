## 学习目标

本课学习递归。重点包括递归是什么、基线条件、一层层往下与往回、调用栈直觉、递归与循环怎么选。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、函数里调用自身：先倒着数一遍

```python
def countdown(n):
    if n == 0:
        print("到站")
        return
    print(n)
    countdown(n - 1)

countdown(3)
```

```text
3
2
1
到站
```

拆开看这一个方法：传入一个数据 `n` 进去，它干三件事 ——

1. **先看要不要停。** `if n == 0` 成立的时候，印一句「到站」就 `return` 收工，**不再调用自身**。
2. **干自己的那点活。** `print(n)` 把当前这个数印出来。
3. **调用自身，并且把传入的数目减一。** `countdown(n - 1)` —— 这就是「咬住自己末尾」的那一口。

走一遍就明白了：进去时 `n` 是 3，它印 3、调用 `countdown(2)`；那一位印 2、调用 `countdown(1)`；再一位印 1、调用 `countdown(0)`；最后一位看到 `n == 0`，印「到站」，收工。一共四位，一层层到底，再一层层结束。

## 二、基线条件：那句「什么时候停」

上面那句 `if n == 0`，我们管它叫**基线条件（刹车）**。

::: tip 提示
**基线条件（base case）** = 函数里那句「到这儿就不用再往下调用了」。它一成立，这一层直接收工。

在 Python 里，写法通常是一个 `if` 加一句 `return`：

- `return 1` / `return 0` 这种 —— 把「最小的那种情况」的答案交出去；
- `return` 后面什么都不跟 —— 只收工，不交东西。

判断它写没写对，只要问一句：**从任何一个合法的传入值出发，一直往下调用，够得着它吗？**
:::

那把刹车拆了会怎样？我们在跑台上真跑过这么一段（故意把刹车拿掉，所以只放在这儿给你看）：

```python
def countdown(n):
    print(n)
    countdown(n - 1)

countdown(3)
```

解释器**一句话都没说** —— 这份源代码它看得懂，翻得出来，于是程序就这么跑起来了。跑起来之后屏幕上先刷出 3、2、1、0、-1、-2……一路往下数，数到把那一摞元素摞爆，才「啪」地一下没了。我们这边收到的最后几行是这样的：

```text
Traceback (most recent call last):
  [Previous line repeated 996 more times]
RecursionError: maximum recursion depth exceeded
```

最后那句翻译过来是：「**往下引用的层数超过上限了。**」注意它**不是**「你的代码写错了」—— 语法上一点毛病都没有，解释器从头到尾没拦过。它是**跑到一半撞墙**才输出的。

**写递归函数，第一件事就是先想清楚「什么时候停」。** 这里还有两条硬要求：

1. **停的那一句，得真有可能轮到。** `if n == 0` 配 `countdown(n - 1)` 是好的；配 `countdown(n + 1)` 就永远轮不到。
2. **每一步都要离停更近一点。** 这里每次都把 `n` 减一，所以一定走得到 0。

::: warn 注意
**「忘了写刹车」是本课最贵的坑**，而且它在 Python 里有两种长相：

- **一次不响地停不下来。** 上面的例子就是：解释器翻得出来、程序跑得起来，屏幕上数字一路往下滚，最后才甩一句 `RecursionError`。**报错出现的时刻，离你写错的那一行已经很远了。**
- **刹车够不着。** 刹车写对了，但每一步都往反方向挪（`countdown(n + 1)` 那样）—— 同样收不了场，数字一路往上数，最后还是撑爆。

所以别指望「跑起来看看不就知道了」：这段程序**会真的跑起来**，跑很久，然后才失败。
:::

## 三、一层层往下，再一层层折回来

再看一段更能看出「往返」的：

```python
def down(n):
    mine = n * 10
    if n == 0:
        print(f"到底了，我们元素里是 {mine}")
        return
    print(f"往下走之前，我们元素里是 {mine}")
    down(n - 1)
    print(f"回来之后，我们元素里还是 {mine}")

down(2)
```

```text
往下走之前，我们元素里是 20
往下走之前，我们元素里是 10
到底了，我们元素里是 0
回来之后，我们元素里还是 10
回来之后，我们元素里还是 20
```

`mine` 是每一位自己的变量（`mine = n * 10`），**每一位都有新的一个**。所以：

- **往下走的那一趟**（在 `down(n - 1)` 之前）：印 20、印 10；
- **到底折回来之后**（在 `down(n - 1)` 之后）：印 10、印 20。

要紧的是这一句：`down(2)` 里那个元素保存的是 20，它调用结束 `down(1)`、等那一位全部收工回来之后，自己那个元素**还在，还是 20**。一层一层的元素不会互相覆盖 —— 「每个自己都有一套自己的变量」就是这套写法能立住的地基。

「往下走」和「折回来」这两趟，是这一课最看不见的东西 —— 屏幕上印出来的五行里面，藏着一次**没印出来**的下钻和一次**没印出来**的回程。下面这段把它俩摊开给你看。

看完这一段，阶乘的写法就是照着抄了：

```python
def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)

print(fact(5))
print(fact(10))
```

```text
120
3628800
```

`5!`（读作「5 的阶乘」）就是 `5 × 4 × 3 × 2 × 1`。换个角度念：**`5!` 就是 `5 × 4!`**，而 `4!` 就是 `4 × 3!` —— 又是同一道题、小一圈。什么时候停？**`0!` 规定等于 1**，那就是它的刹车。

看 `return n * fact(n - 1)` 这一行里的 `return`：它**不是**先算完再回来 —— 是「调用结束那一位、等它把结果返回，我们再拿它跟自己乘」。所以每一位都要**等**下一位，一层层等到底，再一层层把结果返回上来。上面那段演示演的就是这件事。

## 四、一摞元素：那一摞「记着待会儿回到哪儿」

上面从「第 1 层 · 调用下一位，然后停住等」到「第 1 层 · 醒来」这几步里，一直有一栏叫「停在半路的层」。那是这一课唯一一件**屏幕上看不见**的事：每一位调用结束下一位就停在那儿，而「停在哪」这件事得有个地方记着。

记着它的就是**一摞元素**（调用栈）：每调用一次自己，就往这一摞上再扣一个元素，元素里写着「我们刚才停在哪儿、手里攥着什么」；哪一位收工了，就把它那个元素拿走。

两个事实直接从这一摞元素里读出来：

- **摞得越高，占的地方越多。** 第二节那个没刹车的例子，就是把它摞爆了 —— `RecursionError` 说的正是这件事。
- **这摞元素是有高度上限的，而且这个上限是个能查的数。** Python 里查它只要一行：

```python
import sys

print(sys.getrecursionlimit())
```

```text
1000
```

**本机跑出来是 1000**（你自己机器上多半也是这个数）。意思就是：往下引用的层数一旦摸到 1000 上下，Python 就掀桌子了。

::: tip 提示
上面那个 1000 不是「能算出多深的题」，而是**总共能摞多高的元素** —— 你自己这段程序本身也占着一个元素，所以真正能往下钻的层数要**少几层**。

我们真跑过：像下面第五节那种「减到 0 就停」的形状，喂 `998` 还出得来结果，喂 `999` 就 `RecursionError` 了。**差一层就翻车**，这就是「贴着上限写」有多脆。

想调高它可以用 `sys.setrecursionlimit(20000)` —— 我们真跑过，调到两万、往下钻一万九千层，照样出得来结果。**可这不是解题**：这道上限拦的正是「钻得太深」这件事本身，把它往后挪只是让程序多钻一会儿，而钻下去的每一层都得实实在在占一份开销。真正省事的办法是下一节那句。
:::

## 五、自己递归调用，还是绕圈跑？

同一件事，绕圈跑（循环）往往也能干 —— 用 `for` 挨个走一遍就是了。而且**在 Python 里，这一节的结论比别的语言更硬** —— 我们把两段都真跑了一遍给你看。

先看绕圈跑的：从 1 加到 100000。

```python
total = 0
for i in range(1, 100001):
    total += i
print(total)
```

```text
5000050000
```

十万个数，一眨眼就完了，而且是**一圈一圈数过去的**，摞元素的高度始终只有一个。现在把同一件事改写成自己咬递归调用链：

```python
def total(n):
    if n == 0:
        return 0
    return n + total(n - 1)

print(total(100000))
```

```text
Traceback (most recent call last):
  [Previous line repeated 996 more times]
RecursionError: maximum recursion depth exceeded
```

一样的题目、一样的加法，**只是往下钻得太深了** —— 十万层，早就不止 1000 了。这不是写法写错了，是 Python 给这摞元素划的那条线。

那要是把「调用自身」换成整招的**最后一步**呢？有些语言看到这种写法会**把元素收掉**（术语叫尾调用优化），于是摞多高都不怕。Python **不做这件事**：

```python
def total(n, acc):
    if n == 0:
        return acc
    return total(n - 1, acc + n)

print(total(100000, 0))
```

```text
Traceback (most recent call last):
  [Previous line repeated 996 more times]
RecursionError: maximum recursion depth exceeded
```

还是爆。**Python 不做尾调用优化** —— 你把调用自身放到最后一步，它照样一层一层老老实实摞元素，一层都不省。

所以 Python 里「自己递归调用，还是绕圈跑」的实操结论是这三句：

1. **能绕圈跑就别把这招往深里咬。** 十万次累加，绕圈跑一眨眼，这招直接爆 —— 这不是风格问题，是**能不能跑出来**的问题。
2. **这一摞元素默认只有 1000 高。** 题目规模一大（几万个数），这招的写法就得先问一句「会不会钻得比 1000 还深」。
3. **那自己递归调用还有什么用？** 因为有些题**用「小一圈的同一道题」讲起来最顺**：阶乘、斐波那契、后面要学的树和分治，一句话就说清了它是什么。**深度可控的时候，这套写法读起来是真漂亮；深度不可控的时候，它是真会翻车。**

::: tip 提示
今天收五句话：

1. **递归函数 = 在自己的身体里再调用一次自己。**
2. **基线条件就是刹车**，而且必须「轮得到」并且「每步都更靠近它」。
3. **每一位都有自己的一份东西**，回来之后还在。
4. **往下调用和折回来是两趟** —— 写在调用自身之前的那句走「去程」，写在之后的走「回程」。
5. **Python 里这一摞元素默认只有 1000 高，而且不做尾调用优化** —— 所以能用绕圈跑解决的，就别把这招（递归）往深里咬。
:::
