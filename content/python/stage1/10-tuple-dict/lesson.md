本课学习元组与字典。重点包括tuple、dict 键值对、常用操作、选型。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、元组：焊死的小盒子

元组的写法是**一对圆括号**，里面的东西用逗号隔开：

```python
morning = (7, 0)
print(morning)
print(morning[0])
print(len(morning))
```

```text
(7, 0)
7
2
```

一行行看：

- `(7, 0)` 就是那个小盒子，里面保存两格：`7` 和 `0`。我们把它挂上了 `morning` 这块名称 —— 这种用一对圆括号和逗号围起来的东西，就叫**元组**。
- `print(morning)` 会把盒子**原样端出来**：屏幕上是 `(7, 0)`，圆括号和逗号都在。
- `morning[0]` 是**报编号取东西**：编号从 `0` 数起，第一个格子是 `7`。这一手和上一课的储物柜**一模一样**。
- `len(morning)` 数出盒子里有几个格子：两个。这个函数在储物柜身上也用过，元组照样处理。

### 「焊死」是什么意思

名字听着凶，道理其实很朴素：**元组里的格子，定下来就再也改不动了。**

假设我们想把早饭时间从 `7` 点改成 `9` 点，随手写了这么两行：

```text
morning = (7, 0)
morning[0] = 9
```

解释器跑完第一行，念到第二行时一头撞在墙上：

```text
Traceback (most recent call last):
  File "...\main.py", line 2, in <module>
    morning[0] = 9
TypeError: 'tuple' object does not support item assignment
```

最后一行那句翻译过来是：**这个东西不支持给格子重新赋值。** 用自然语言解释就是 —— **盒子上根本没有能打开的盖子，格子焊死了。**

那想改怎么办？**重做一个新盒子**：

```python
morning = (7, 0)
morning = (9, 0)
print(morning[0])
```

```text
9
```

看清楚这一步干的到底是什么：`morning = (9, 0)` **不是把旧盒子撬开**，而是**做了一个新盒子，再把 `morning` 这块名称从旧的上面揭下来、挂到新的上面**。旧盒子还在原地，只是没人再去理它了。

这正是元组的价值：我们要的就是一块**没人能偷偷改动**的值日牌。想改？那就得**重新写一块** —— 这么一折腾，你一定会注意到自己改了什么。

### 一次倒进两个变量：解包

元组的格子是排好队的，所以能一次倒给好几个变量：

```python
morning = (7, 0)
hour, minute = morning
print(hour)
print(minute)
```

```text
7
0
```

`hour, minute = morning` 这一手叫**解包**：盒子里的东西**按顺序**倒出来 —— 第一个格子 `7` 倒进 `hour`，第二个格子 `0` 倒进 `minute`。倒完之后，它俩就是普普通通的变量了，想怎么用就怎么用。

左边名字的个数**和格子数对不上时**，解释器才炸毛 —— 但「对上」这两个字的规矩，比我们原先以为的多一条：**逗号才是「倒出来」的信号**。我们四种写法都真跑过：

- **两个名字接两个格子**（`hour, minute = morning`）—— 对上，稳稳当当。
- **名字写多了**（`hour, minute, second = morning`）—— **炸**，原话是 `ValueError: not enough values to unpack (expected 3, got 2)`（念作「要 3 个，只给了 2 个」）。
- **只写一个、逗号还留着**（`hour, = morning`）—— 也**炸**，原话是 `ValueError: too many values to unpack (expected 1)`（两个格子要塞进一个名字，装不下）。
- **只写一个、连逗号都不写**（`hour = morning`）—— **不炸**：`hour` 把**整只盒子**接住，`print(hour)` 印出来是 `(7, 0)`。这不是解包，是把盒子整个搬过去，合法、而且经常正好是你想要的那种写法。

所以我们给自己记的死规矩是：**要么两边一样多，要么一个名字、不写逗号。** 一边一个名字、一边两个格子，还想要「倒出来」，那就只有炸这一条路。

::: tip 提示
元组的三件事，记住就够啦：

1. **写法**：一对圆括号，里面用逗号隔开 —— `(7, 0)`。
2. **取法**：和储物柜一样报编号 `morning[0]`；`len(morning)` 数格子。
3. **脾气**：格子**焊死**了，`morning[0] = 9` 会报错；想改就**重做一个新盒子**，再让名称挂过去。
:::

## 二、字典：贴了名牌的格子柜

第二种活来了。我们的账本是「名字 → 条数」这样**一对一对**记的：张三 3 条、李四 5 条。这一对一对的东西，术语里叫**键值对**；装它们的家伙，我们管它叫**名牌格子柜** —— 一整面柜子，每个格子外面钉着一块**名牌**，里面放着东西。

写法是**一对花括号**，每一对写成「名牌 : 东西」，对与对之间用逗号隔开：

```python
fish = {"张三": 3, "李四": 5}
print(fish["张三"])
print(fish["李四"])
```

```text
3
5
```

- **花括号 `{ }`** 是柜子的外框。别和元组那对圆括号搞混：**圆括号保存的是元组，花括号保存的是字典**。
- **冒号前面那半**（`"张三"`）是**名牌**，也叫**键**；**冒号后面那半**（`3`）是格子里装的东西，也叫**值**。
- **取东西要报名牌**，用**方括号**把名牌圈起来：`fish["张三"]`。注意不是圆括号 —— 写成 `fish("张三")` 那样，柜子根本不认。
- 名牌本身一般是一串字符串，所以**要带引号**；少了引号，解释器会把它当成一个名字去找，找不到又要炸毛。

### 名牌打错一个字，它就当场炸毛

这是字典最扎人的一个坑，我们单独拎出来讲。我们想查三花当前记录了几条，手一滑写成了这样：

```text
fish = {"张三": 3, "李四": 5}
print(fish["三花"])
```

解释器把整面柜子翻了个遍，也没找到叫「三花」的名牌：

```text
Traceback (most recent call last):
  File "...\main.py", line 2, in <module>
    print(fish["三花"])
KeyError: '三花'
```

`KeyError` 翻过来就是「**这个名字（键）我没有**」。它的脾气和元组那位不太一样：**元组是「能取的都给你，但改不动」；字典是「名牌对不上，当场断气」。**

### 先敲门：`in` 和 `get`

被炸过几回之后，我们学会了两招防身的：

```python
fish = {"张三": 3, "李四": 5}
print("张三" in fish)
print("三花" in fish)
print(fish.get("三花", 0))
```

```text
True
False
0
```

- **`"张三" in fish`** 是**问一句**「这块名牌挂着吗」，回你 `True`（挂着）或者 `False`（没挂）。它只管回答在不在，**不会把格子里的东西返回**。
- **`fish.get("三花", 0)`** 是**先敲门、再取**：名牌在，就把格子里的东西返回；名牌不在，就把你写在后头的那个**备胎**（这里是 `0`）返回。**它绝不会炸毛。**

所以「三花记录了几条」这个问题就有了两种稳当的问法：先用 `in` 问一句再决定，或者直接用 `get` 带一个备胎。两种都比直接写 `fish["三花"]` 安全。

### 一个等号，两种活：重新赋值和新开一格

柜子里的东西不是死的，随时能换：

```python
fish = {"张三": 3, "李四": 5}
fish["张三"] = 4
fish["三花"] = 2
print(fish)
del fish["李四"]
print(fish)
print(len(fish))
```

```text
{'张三': 4, '李四': 5, '三花': 2}
{'张三': 4, '三花': 2}
2
```

- **`fish["张三"] = 4`** —— 「张三」这块名牌**已经挂着**了，所以这一句是**重新赋值**：把格子里的 `3` 换成 `4`。
- **`fish["三花"] = 2`** —— 「三花」这块名牌**从来没挂过**，所以这一句是**新开一格**：柜子上多出一块名牌，里面放 `2`。

同样是 `柜子[名牌] = 东西` 这一句，**名牌在就是换，名牌不在就是加** —— 一个等号两种活，你不用多写任何东西去区分。

- **`print(fish)`** 把整面柜子端出来给你看：花括号、名牌、冒号、格子里的东西，一对一对都在。
- **`del fish["李四"]`** 是把**那块名牌连格子一起摘掉**（`del` 念「delete」，就是抹掉）。
- **`len(fish)`** 数出柜子里**有几对**名牌：三对摘掉一对，剩 `2` 对。

3. **元组不可改 ≠ 名称不能重挂**。`morning = (9, 0)` 是**换了一个新盒子**（允许）；`morning[0] = 9` 是**撬开旧盒子改格子**（报错）。
:::

### 名牌有讲究：能挂的必须「定得下来」

既然元组和字典今天一起出场，我们就把它俩之间的一条关键联系讲透：**字典的名牌，必须是改不动的东西。**

- **能挂**：字符串（`"张三"`）、数字（`1`）、元组（`(7, 0)`）—— 这些东西定下来就定下来了。
- **不能挂**：**列表**。因为柜子里的东西随时会变，名牌挂上去没过一会儿就对不上号了。

要是硬拿一个储物柜去当名牌，解释器当场翻脸：

```text
fish = {[1, 2]: 3}
```

```text
Traceback (most recent call last):
  File "...\main.py", line 1, in <module>
    fish = {[1, 2]: 3}
TypeError: unhashable type: 'list'
```

那句报错的意思是「**这个东西挂不上**」。**这正是元组存在的意义**：它把格子焊死了，所以**定得下来**，所以**能当名牌用**。储物柜当不了名牌，元组能 —— 这一条，就是元组和字典握手的暗号。

## 三、选型：什么时候请谁出场

三种装东西的家伙都认识了，最后一步是**选型**：拿到一件活，先想清楚该请谁出场。

问自己两个问题，按顺序问：

1. **我是按编号取，还是按名字取？** 按名字取 → **字典**（名牌格子柜）。
2. **按编号取的话，这排东西以后还会变吗？** 会变 → **列表**；定下来就不许别人动的 → **元组**。

排成一张表：

| 你的活长什么样 | 请谁出场 | 写法 |
|---|---|---|
| 一排东西按编号取，数量还会长大 | 列表 | `[10, 20, 30]` |
| 一组固定搭配，定下来就不许改 | 元组（焊死的小盒子） | `(7, 0)` |
| 名字和东西一对一对，要报名字取 | 字典（名牌格子柜） | `{"张三": 3}` |

再拿「张三 3 条」这个例子把三边走一遍，你就明白为什么只有字典合适：

- **为什么不用元组？** `(3,)` 里只有条数、没有名字，我们得自己记住「这是个位是……」，而且条数天天变，焊死了反而添乱。
- **为什么不用储物柜？** 硬塞成「一列名字、一列条数」的话，两列全靠编号对齐，中间删掉一个对象，后面全体错位 —— 报名字取东西的本事，它压根没有。
- **字典为什么合适？** 名字和条数天创建一对一对，报名字就取，添新对象就是新开一格。

再补三句用得上的话：

- **按什么取，是最粗的一条分界线。** 储物柜和元组都靠**编号**（`morning[0]`）；字典靠**名牌**（`fish["张三"]`）。
- **`len` 三边都处理**：数储物柜里几个、数小盒子里几个、数名牌柜里几对。
- **挑名牌只挑「定得下来」的**：字符串、数字、元组都行，储物柜不行。

::: tip 提示
一句话收口：**会变的、按编号取的，交给储物柜；定死的成对搭配，交给元组；要报名字取的东西，交给字典。** 拿不准的时候，先问自己那句「我是按编号取，还是按名字取」—— 八成就有答案了。
:::
