
## 一、叫一个对象来干活：`Thread`

Python 里叫对象的函数住在 `threading` 这个小变量中，先把它请进来：

```python
import threading

结果 = [""]

def 烤数据():
    结果[0] = "第 0 号数据"

t = threading.Thread(target=烤数据)
t.start()
t.join()

print(结果[0] + " 烤好啦")
```

```text
第 0 号数据 烤好啦
```

四句新话，一句一句拆开看：

- **`threading.Thread(target=烤数据)`** —— 叫一个对象来，交给它一张单子。`target=` 后面写的是**函数本身的名字**，也就是「要它施展哪一个方法」。
- **`t.start()`** —— 调用开工。这一次调用结束，我们**不等它**，扭头就走，对象自己在那儿烤。
- **`t.join()`** —— 我们在这儿**等它收工**。等到了，才往下走。
- **`结果[0]`** —— 对象干出来的东西没有直接印出来，而是**放进了我们给它留的格子里**。等它收工，我们自己去格子里拿。

最后这一条是本课的第一条规矩，请先记住：

> **对象只管把结果放进格子；要印、要算、要显示，都等 `join()` 之后再由我们统一来做。**

为什么？因为对象干活快慢**不由你定**，谁先谁后是电脑自己安排的。要是每个对象一干完就抢着 `print`，那印出来的行**每次跑都可能换个顺序**——你就再也说不清「这一行到底该不该在这儿」了。

### `target=` 后面为什么不加括号

这是零基础学员最容易摔的一跤，我们单独拎出来讲。

`烤数据` 和 `烤数据()` 在 Python 眼里是**两样东西**：

- 写 `烤数据`（不带括号）= 把**这张函数的单子**递过去，说「照这个干」。对象接过去，等自己开工时才施展。
- 写 `烤数据()`（带括号）= **当场**就把这招施展一遍！括号是「现在就动手」的意思。我们自己动手烤完了，`Thread` 接到的其实是函数干完活**返回值**，而不是函数本身。

这里最坑的一点必须说清：**带括号的写法通常不会报错**。本课的 `烤数据` 是只干活、不返回东西的函数，它返回的是「什么都没有」（Python 管这个叫 `None`）。`Thread(target=None)` 照样开工，只是**没函数可施展**，空跑一趟就回来了。程序一次不吭，数据也确实烤好了——因为那是**我们自己**烤的，对象从头到尾一点活都没干。

判据一句话：**括号一出现，函数当场就施展了**。所以 `target=` 后面要写名字，不带括号。

## 二、三个对象一起上

一个对象叫来了，那三个呢？我们先把三个都叫来、都开工，再挨个等它们收工：

```python
import threading

结果 = ["", "", ""]

def 烤数据(编号):
    结果[编号] = f"第 {编号} 号数据"

对象 = []
for i in range(3):
    t = threading.Thread(target=烤数据, args=(i,))
    对象.append(t)
    t.start()

for t in 对象:
    t.join()

for i in range(3):
    print(结果[i] + " 烤好啦")
```

```text
第 0 号数据 烤好啦
第 1 号数据 烤好啦
第 2 号数据 烤好啦
```

看起来和没对象的那版输出一模一样——**这正是我们想要的效果**：对象多了，结果一点没变。改动的地方有三处：

1. **先造一个空储物柜**（`对象 = []`），用来收留叫来的对象。叫一个就往里塞一个（`对象.append(t)`），这样我们手里始终有名单，不包含独立执行过程完就找不着了。
2. **第一个跑圈里，叫一个、开工一个，我们不等**。三个对象于是都在自己烤——这就是「一起干活」。
3. **第二个跑圈：我们挨个等它们收工**（`t.join()`）。三个全等到了，才走到最后的打印。

最后的打印值得多看两眼：我们是**按编号 0、1、2 挨个去格子里取**的。印出来的顺序是**我们定的**，跟哪个对象先烤完、后烤完**没有半点关系**。所以这段程序你跑一百遍，印出来都是一模一样的这三行。

### 参数：`args=`

上面那个对象的函数要收一个**编号**，我们是这么传入的：`args=(i,)`。

- **`args=`** 后面装的就是传入给这招的数据（参数）。喂几样，按**函数收的顺序**一样一样排好。
- **`(i,)` 末尾那个逗号千万别丢**。一对括号里只有一个东西的时候，`(i)` 在 Python 眼里只是「加了个壳的数字 i」，不是「一串只有一个的数据」。少了逗号，等对象开工时解释器会抱怨这串东西没法一个个拆开喂。

只有一样要喂的时候，末尾那个逗号就是它的护身符。

## 三、共用一个变量：要挂锁

前面三个对象各用**自己的格子**（`结果[0]`、`结果[1]`、`结果[2]`），互不打架。

现在换个场景：四个对象往**同一个变量**里加数据，每个捡 25 条，一共该有 100 条。

```python
import threading

总数 = 0
锁 = threading.Lock()

def 捡数据(只数):
    global 总数
    for _ in range(只数):
        with 锁:
            总数 = 总数 + 1

对象 = []
for i in range(4):
    t = threading.Thread(target=捡数据, args=(25,))
    对象.append(t)
    t.start()

for t in 对象:
    t.join()

print(f"一共捡到 {总数} 条数据")
```

```text
一共捡到 100 条数据
```

三个新面孔：

- **`global 总数`** —— 跟解释器打声招呼：这句里要改的 `总数`，是**外面那个变量**，不是我们在函数里新造的一个。少了这一句可**一点都不安静**：`总数 = 总数 + 1` 是先**读**后写，函数里那个小变量还没装东西就要被读，当场摔 `UnboundLocalError`。我们真跑过（四个对象、每个捡 25 条）：屏幕上**四片错误信息**，每片一句 `Exception in thread Thread-N (捡数据)` 打头，底下写着 `cannot access local variable '总数' where it is not associated with a value`；最后印出来的那一行是 `一共捡到 0 条数据` —— 外面那个变量确实**一动不动**，可不是悄悄不动，是四个对象**一个都没干成活**。⚠️ 而且**退出码还是 `0`**：摔的是那些子对象，正门（主程序）自己好好走完了。所以别拿退出码当体检结果，得看屏幕。
- **`锁 = threading.Lock()`** —— 领一把钥匙。
- **`with 锁:`** —— **进屋改数字之前先拿钥匙，出来时自动还回去**。（你在上一课见过的那对会自动收拾的 `with`，今天正好拿来管这把钥匙。）钥匙只有一把，所以同一时刻**只有一个对象能进屋**，别的对象在门口排队。

### 没有钥匙会怎样

这一条我们要讲得慢一点，因为它错得**特别安静**。

`总数 = 总数 + 1` 看着是一步，其实分成**三步**：① 读出变量上写的数 → ② 在心里加一 → ③ 把新数写回变量。

现在两个对象同时来加：

1. 对象甲读到变量上写着 **5**；
2. 对象甲还没来得及写回去，就被换下场了；
3. 对象乙上场，读到的还是 **5**，加一，写回 **6**；
4. 对象甲再上场，把它心里那个 **6** 写回去。

两个对象各捡了一条，变量上却只从 5 涨到 6——**凭空少了一条**。程序不会报错，也不会提醒你，只是数字对不上，而盯着代码看半天也看不出毛病。

⚠️ 但我们得说实话：**这个坑不是每次都能撞上**。我们把上面那段代码的 `with 锁:` 拆掉真跑了几种形状 ——

- 四个对象各捡 **25** 条（就是上面那段）：跑五遍，**五遍都是 `100`**，一条不差；
- 四个对象各捡 **2000** 条：跑五遍，还是 **`8000`**，一条不差。

对象干得太快了：从「读」到「写回」只要几微秒，一个对象还没轮到被换下场，它就已经写完了 —— **中间没有缝，就撞不上。**

缝从哪来？只要「读」和「写回」中间**夹了任何要等一等的事**（我们量过：多一句 `time.sleep(0)` 就算），同样四个对象、每个 2000 条，跑出来是 **2000 / 2192 / 2122**（该有 `8000`）—— 而且**每跑一次都不一样**。真实干活时这种缝遍地都是：读文件、上网、烤数据（本课前面那个对象就一直在 `time.sleep`）全算。

所以这个坑真正阴的地方是**时灵时不灵**：今天跑对了，不代表你写对了，只代表今天缝隙没凑巧对上。这就是我们非要你把钥匙挂上的原因 —— 挂上 `with 锁:`，跑多少次都是 `100`。

所以我们的规矩是：

> **只要是好几个对象改同一个格子、同一个数字，就把钥匙挂上（`with 锁:`）。**

各写各的格子（就像第二节那样）不用挂锁，那是唯一可以偷懒的情况。

::: tip 提示
本课三句话，抄在记录表上：

1. **叫对象**：`threading.Thread(target=函数名, args=(数据,))`——名字**不带括号**，传入只有一个时**逗号不能丢**。
2. **开工与等待**：称呼它 `t.start()`，等它 `t.join()`。我们要用的结果，**一定在 `join()` 之后才去取**。
3. **先后不定**：对象谁先干完由电脑安排，你说了不算。想让输出每次都一样，就让对象只往格子里放结果，**最后按固定顺序统一印**。
:::

::: warn 注意
三个对象一起干活时最容易摔的三跤：

- **`target` 后面带了括号**：`threading.Thread(target=烤数据(0))` 会**当场**把函数施展一遍（我们自己动手烤了），`Thread` 拿到的是函数返回值、不是函数。而这一个方法不返回东西，结果是 `None`——对象开工后**什么都不干**，**程序还不报错**，表面上结果甚至是对的（那是我们自己烤的）。你想要的「几个对象一起干活」，就这么悄悄变成了我们一个人排队干。判据：**括号一出现，函数当场就动手了**。
- **忘了 `join()`**：我们跑到打印那一句时，对象可能还在烤，格子里保存的是空的。**程序不报错**，只是印出来的东西不对——这种安安静静的错误最费眼神。
- **好几个对象改同一个数字却不挂锁**：数字会莫名其妙地少几条。看见「少了但没报错」，先想想是不是忘了 `with 锁:`。
:::

## 本课小抄

| 想干的事 | 写法 |
|---|---|
| 叫一个对象来干活 | `threading.Thread(target=函数名, args=(数据,))` |
| 称呼它开工 | `t.start()` |
| 等它收工 | `t.join()` |
| 一次叫好几个 | 每个都塞进储物柜：`对象.append(t)`，最后挨个 `t.join()` |
| 好几个对象改同一个格子 | 领钥匙 `锁 = threading.Lock()`，改动时 `with 锁:` |
| 看结果 | 等 `join()` 全部到齐，由我们按固定顺序统一印 |
| 函数里要改外面的变量 | 开头写 `global 变量名` |
