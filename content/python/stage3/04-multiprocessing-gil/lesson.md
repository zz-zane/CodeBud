## 学习目标

本课学习多进程与 GIL。重点包括GIL 直觉、multiprocessing、进程 vs 线程。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、金铃铛：同一时刻只有一个对象拿得到

Python 的代码不是直接传给电脑的，中间站着**解释器**：你写的每一句，都由它一句一句翻着往下执行。

这位解释器脖子上挂着一枚**金铃铛**，它有个死规矩：

> **同一时刻，只允许一个对象摇着铃铛执行 Python 代码。**

这枚铃铛的正式名字叫 **GIL**，我们平时就叫它「解释器脖子上的金铃铛」，更好记。

那么问题来了：上一课叫来的那好几个对象，岂不是白叫了？**不是的** —— 因为铃铛会**松手**：

| 对象正在干什么 | 手上有铃铛吗 | 叫上一队对象有用吗 |
|---|---|---|
| 算数据（纯 Python 的加加减减、拼字、循环） | 一直攥着不放 | 没用，只是排更长的队 |
| 等外面回话（等工作区回信、等文件读完、等你敲键盘） | 主动放下 | 有用，别的对象正好接手 |

所以一句话记住：**多线程执行，擅长「等」，不擅长「算」。** 你要下载十张图、要同时问十个网站，叫上一队对象正合适；你要把十亿条数据的重量加起来，叫再多对象也只是排更长的队。

::: tip 提示
铃铛只有一枚 = 同一时刻只有一个对象在跑 Python 代码。所以「叫了对象却还是在排队」**不是你写错了**，是规矩本来就长这样。真想同时算，得换一个方法 —— 多开几个对象。
:::

## 二、多开一个对象：进程是什么

「多开一个对象」的正式名字叫**进程**。它不是「叫原来那个对象多干一份活」，而是**重新养出一个全新的对象**：

- 它有**自己的变量**（内存）—— 你变量中的东西它看不见，它变量中的你也看不见；
- 它有**自己的解释器、自己的金铃铛** —— 所以两个对象能**真正同时**跑代码，谁也不用排队；
- 但它初始化**要花时间**：在 Windows 上，新对象是「照着你的剧本重新初始化一次」。

Python 给这招配了一整个工具箱：`multiprocessing`。最朴素的用法是 `Process`：把要干的活（函数）和要传入的数据（写在 `args` 里）交给它，再调用一次 `start()`，新对象就出发了。

### 先看一件事：新对象的变量是它自己的

```python
from multiprocessing import Process, Queue

fish = ["计算机"]


def add_one(queue):
    fish.append("数据")
    queue.put(len(fish))


if __name__ == '__main__':
    queue = Queue()
    p = Process(target=add_one, args=(queue,))
    p.start()
    p.join()
    print(f"新对象的变量中有 {queue.get()} 条")
    print(f"我们的变量中有 {len(fish)} 条")
```

```text
新对象的变量中有 2 条
我们的变量中有 1 条
```

新对象往它自己那个变量中塞了一条数据，塞完数出来是 2 条；而我们这边还是孤零零的 1 条计算机 —— **两间变量，各数各的**。

这就带出一个要紧的后果：新对象算出来的东西，父对象**拿不到**。想拿，就得让新对象**主动递出来**：这里用的是「队列」的那个筐（`Queue`）—— 新对象把成果 `put` 进筐里，父对象伸手 `get` 出来。这个筐，就是两个对象之间最常用的那条通道。

### 保护罩：`if __name__ == '__main__':`

上面那段代码里，开对象的台词被关在一层保护罩里。**这层保护罩在 Windows 上是必须的**：

新对象是「照着你的剧本重新初始化」的 —— 它一初始化，会**把剧本从头念一遍**。要是「开一个新对象」的台词留在保护罩**外面**，新对象念到那一句，就会**再开一个**；解释器只好当场拦住你，甩你一句 `RuntimeError`，告诉你「还没准备好就又要开新对象」。

::: warn 注意
凡是多开对象的代码，**开对象的台词一律放进 `if __name__ == '__main__':` 里面**。这不是客套话，是硬规矩 —— 漏了它，程序在 Windows 上一跑就翻脸。
:::

## 三、三个对象一起剥鱼，父对象统一报数

来把三个对象派出去干同一件活，再让父对象把成果收回来：

```python
from multiprocessing import Process, Queue


def peel(queue, index, count):
    queue.put((index, f"第 {index} 条鱼，剥了 {count} 片"))


if __name__ == '__main__':
    queue = Queue()
    jobs = []
    for i in range(1, 4):
        p = Process(target=peel, args=(queue, i, i * 2))
        jobs.append(p)
        p.start()
    for p in jobs:
        p.join()
    results = [queue.get() for _ in jobs]
    for index, line in sorted(results):
        print(line)
```

```text
第 1 条鱼，剥了 2 片
第 2 条鱼，剥了 4 片
第 3 条鱼，剥了 6 片
```

一句一句看：

- `jobs.append(p)`：把派出去的每个对象都记在名单上，等会儿好挨个等它回家；
- `p.start()`：新对象出发，去干自己的那一份；
- `p.join()`：父对象**在这里等**这个对象干完。名单上有几个，就等几次；
- `results = [queue.get() for _ in jobs]`：从筐里把三份成果挨个接出来；
- `sorted(results)` 再 `print`：**最要紧的一句**。三个对象谁先剥完谁先扔筐，**到达的先后每次都不一样**；父对象把它们按编号排好队再统一印，所以这段程序**跑到哪儿都是这三行**。

::: tip 提示
多开对象的程序，**让父对象负责印**：新对象只把成果递出来，别让它们自己 `print`。谁先印谁后印，是对象手快慢的运气；而你想要的，是一份**每次都一样**的输出。
:::

## 四、一池子对象：`Pool` 更省事

每个对象都亲手 `start`、再亲手 `join`，养十只就要写十条，累不累？`multiprocessing` 里有个更省事的家伙：**对象池 `Pool`**。你先告诉它「我们要几个对象」，它一次养好，有活就派一个去，派完回来接着用。

```python
from multiprocessing import Pool


def square(n):
    return n * n


if __name__ == '__main__':
    pool = Pool(3)
    results = pool.map(square, [1, 2, 3, 4])
    pool.close()
    pool.join()
    for value in results:
        print(value)
```

```text
1
4
9
16
```

`pool.map(函数, 一筐活)` 的意思是：把筐里的东西挨个传给这个函数跑一遍，**结果按你给进去的顺序原样还给你**。哪怕池子里三个对象是同时开工的，交回来照样整整齐齐 —— 第 1 个进去的，永远是第 1 个出来。

最后那两句是收工：`close()` 告诉池子「活派完了，不再接新活」，`join()` 等所有对象回窝。**别漏了它们** —— 不过漏了的下场，和我们原先写的不一样，真量过才知道：

- 父对象**不会一直等**。把这两句删掉跑这段，程序 **435 毫秒**就收工了（现代解释器给池子挂了个「收摊」的钩子，程序一结束就把池子整个掀掉）。那要是活儿正干到一半呢？我们又量了一遍：派一个对象去干两秒的活、不等结果、也不写这两句 —— 进程 **286 毫秒**就走人，那个对象**被一起带走**，干的活全白费（我们让它把结果写进一个文件，跑完去看，**文件压根没出现**）。
- 所以真正该记的是：**不写 `close()` / `join()`，程序不会等你，它是把正干活的对象连窝一起端走。** 眼下这段看不出毛病，只因为 `pool.map(...)` 那一句自己会等到结果齐了才往下走；等哪天你不等结果、让对象在后台慢慢干，这笔账就找上来了。

## 五、进程 vs 多线程执行（线程）

把两种「多叫帮手」的路子摆在一起看个明白：

| 比一比 | 多线程执行（线程） | 多开几个对象（进程） |
|---|---|---|
| 变量 | 挤在同一间，谁都能伸手（要抢，得加锁） | 每个一间，互不打扰 |
| 能真同时算吗 | 不能，金铃铛只有一枚 | 能，每个对象有自己的铃铛 |
| 初始化开销 | 轻，调用输出方法就来 | 重，得照着剧本重新养一个 |
| 成果怎么回去 | 不用递，同一个变量中放着就行 | 得打包递（用筐 `Queue`，或写进结果里返回） |
| 一个对象栽了 | 整屋都遭殃 | 只倒那一个 |
| 最擅长 | 等回信：下载、问网站、读文件 | 算数据：一大坨纯计算 |

一句话选法：**等得多 → 多叫对象；算得多 → 多开对象。** 看你的活儿是「等」还是「算」，就知道该调用哪一路帮手了。
