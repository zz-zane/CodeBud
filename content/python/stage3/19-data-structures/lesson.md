## 学习目标

本课学习栈、队列与链表。重点包括为什么要有数据结构、栈：后进先出、队列：先进先出、链表：一环牵一环、各自适合什么活。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、栈（栈）：同一头进，同一头出

先看最老实的那摞元素。往里放叫「压上去」，往外拿叫「从顶上揭」，两头是**同一头**：

```python
一摞元素 = []
一摞元素.append("三文鱼")
一摞元素.append("秋刀鱼")
一摞元素.append("鳕鱼")
print("元素里从下到上：", 一摞元素)
print("先拿出来的是：", 一摞元素.pop())
print("再拿出来的是：", 一摞元素.pop())
print("元素里还剩：", 一摞元素)
```

```text
元素里从下到上： ['三文鱼', '秋刀鱼', '鳕鱼']
先拿出来的是： 鳕鱼
再拿出来的是： 秋刀鱼
元素里还剩： ['三文鱼']
```

看仔细了：三文鱼**最先**放进去，却是**最后**才轮得到它。这一摞元素的规矩叫**后进先出** —— 最后放上去的，最先被拿走。

要紧的是：这里**一个新函数都没学**。用的还是储物柜那两招 ——

- `一摞元素.append("鳕鱼")`：往**末尾**压一格；
- `一摞元素.pop()`：从**末尾**揭一格，顺手把揭下来的返回。

::: tip 提示
**「末尾」这两个字就是这一摞元素的全部秘密。**

`append` 和 `pop()` 都在末尾动手，所以往里放、往外拿都**只碰最上面那一格** —— 元素里摞着 3 条还是 100 万条，这一次动作的代价都是**一格**。第 1 课的数圈数思路套过来：**一次进或出，圈数就是 1，跟元素里有多少条无关**，也就是 `O(1)`。往后看到「只在末尾动手」的写法，就可以放心地说它是 `O(1)` 。
:::

还有一件小事要提前打招呼：**元素空着的时候还去揭，是会被当场拦下的。**

```python

print("元素里有：", 一摞元素.pop())
print("还想再拿一条：", 一摞元素.pop())
```

解释器当场就掀桌子了：

```text

    print("还想再拿一条：", 一摞元素.pop())
IndexError: pop from empty list
```

最后那句原话的意思是「**从一个空元素里揭东西**」。它稳得很，跟你有几条数据无关 —— 元素里一条都没有的时候去揭，必然是这一句。所以往后写「一直揭到元素空」这种绕圈，脑子里要一直挂着「**什么时候该停**」：用 `while 一摞元素:` 这种写法，让元素一空就自己停手，是最省心的做法。

一摞元素适合干那些「**回头先办最近那件事**」的活：文字的撤销、浏览器的后退、算括号有没有配对，全是这个形状。

## 二、队列（队列）：末尾进，头上出

再看排队。它和一摞元素正好反过来：**进走一头，出走另一头**。

Python 里现成的「两头都能进出的绳子」是 `collections.deque`（念作「deck」）。排队只是它的一种用法：

```python
from collections import deque

排队 = deque()
排队.append("三文鱼")
排队.append("秋刀鱼")
排队.append("鳕鱼")
print("队伍从头到尾：", list(排队))
print("先领走的是：", 排队.popleft())
print("再领走的是：", 排队.popleft())
print("队伍里还剩：", list(排队))
排队.append("计算机")
print("计算机排到末尾上：", list(排队))
print("从末尾上领走：", 排队.pop())
print("队伍里还剩：", list(排队))
```

```text
队伍从头到尾： ['三文鱼', '秋刀鱼', '鳕鱼']
先领走的是： 三文鱼
再领走的是： 秋刀鱼
队伍里还剩： ['鳕鱼']
计算机排到末尾上： ['鳕鱼', '计算机']
从末尾上领走： 计算机
队伍里还剩： ['鳕鱼']
```

三件事一起记下来：

1. **`排队.append(东西)`** —— 排到**末尾**上（和储物柜的 `append` 名字一样，脾气也一样）；
2. **`排队.popleft()`** —— 从**头上**领走，顺手把领到的返回；
3. 它叫「两头都能进出的绳子」，不是白叫的：`appendleft` / `pop` 另外两头也都在（上面最后两行就是从左边的**末尾**上领走了一条）。排队只是「只往末尾上排、只从头上领」这一种**用法**。

**先来的先领到**，这条规矩叫**先进先出**。它跟一摞元素的区别就一句话：**进出是不是同一头**。

::: tip 提示
第 5 行那个 `list(排队)` 为什么要套一层？因为 `deque` 打印出来长这样：`deque(['三文鱼', ...])` —— 一整个 `deque(...)` 包在外面，看着累。套一层 `list(...)` 就是在说「把它摊成一排元素给我看」。
:::

## 三、拿一排元素当队伍用，是个坑

有同学要问了：队伍不就是「一排元素，从头拿」吗？一排元素也有报编号的函数，那我们拿 `一排元素.pop(0)` 从头上拿，不也一样？

一样「能跑」，**但代价天差地别**。这句话不能靠我们一张嘴说，得数给你看。

一排元素从头上拿走一格的时候，**里面干的是一件很费劲的事**：把后面每一条都往前挪一格，不然中间就空出一个洞了。我们把这件事自己写了一遍，好让每一步都能**记上账** —— 每挪一格就加 1：

```python
def 从头领走要搬几次(几条):
    一排元素 = list(range(1, 几条 + 1))
    搬了几次 = 0
    while 一排元素:
        for i in range(len(一排元素) - 1):
            一排元素[i] = 一排元素[i + 1]
            搬了几次 = 搬了几次 + 1
        一排元素.pop()
    return 搬了几次


def 从末尾领走要搬几次(几条):
    一排元素 = list(range(1, 几条 + 1))
    搬了几次 = 0
    while 一排元素:
        一排元素.pop()
    return 搬了几次


for 几条 in (6, 1000):
    print(几条, "条数据一条条从头上领走，一共搬了", 从头领走要搬几次(几条), "次")
print("同样 1000 条，从末尾上领走，一共搬了", 从末尾领走要搬几次(1000), "次")
```

```text
6 条数据一条条从头上领走，一共搬了 15 次
1000 条数据一条条从头上领走，一共搬了 499500 次
同样 1000 条，从末尾上领走，一共搬了 0 次
```

三个数摆在一起，故事就全出来了：

- **6 条**：第 1 条要走的时候后面 5 条挪，第 2 条走的时候 4 条挪……一路加到 1，就是 `5 + 4 + 3 + 2 + 1 = 15`；
- **1000 条**：同样的加法，`999 + 998 + … + 1 = 499500`。**每领走一条，平均要搬 500 格** —— 这就是「从头拿」的真实价钱，每一次都是 `O(n)`；
- **从末尾上领走，1000 条一共搬 0 次**。末尾那一格后面没有人，谁都不用让位 —— 每次都只碰一格，`O(1)`。

::: warn 注意
**「能跑」和「跑得起」是两件事**，这里正是最典型的一处：`一排元素.pop(0)` 一行写得出来、跑得通、不报错，小数据上你也根本感觉不到。

我们还拿表掐过：把 **5 万条**数据一条条从头上领完，一排元素那版跑了三次，分别是 **1.77 秒、1.85 秒、1.87 秒**；同样 5 万条，`deque` 的 `popleft()` 三次是 **0.001 秒、0.001 秒、0.002 秒**。**差了一千倍以上。**

⚠️ 秒数这东西会飘 —— 换台机器、换一次运行都不是这几个数，别把它当尺子（第 1 课刚讲过这件事）。**只有当它摆在 499500 和 0 旁边的时候，它才说明问题**：一边是「搬了 49 万次」，一边是「一次都没搬」。
:::

所以拿一排元素当队伍用，问题**不在写法，在选材**：

- **从头进、从头出**（`insert(0, x)` / `pop(0)`）—— 每一下都要**搬一大片**，`O(n)`；
- **末尾进、末尾出**（`append` / `pop()`）—— 每一下只碰一格，`O(1)`；
- 想要「末尾进、头上出」还想两头都快 —— 那就换个**两头都留着一截空位**的家什：`collections.deque`。它的 `popleft()` 后面谁都不用动，也是 `O(1)`。

::: tip 提示
两句要提前说清的话：

1. **`deque` 不等于「排队的唯一做法」。** 拿一排元素 + `pop(0)` 也能排出先来先到，只是慢；自己拿两条链子搭一个也行；甚至拿两个储物柜对倒也能凑出来。我们推荐它，是因为**两头进出的价钱都是 `O(1)`**，写起来还只有一行 —— 是「顺手又快」，不是「只能用这个」。
2. **`deque` 本身不是为排队造的**：它是**两头都能进出的绳子（双端队列）**，排队、一摞元素、两头都要动的窗口，全是它的用法。
:::

## 四、链表（链表）：只动线，不搬家

最后一样家什，是自己搭的：**每个盒子末尾上挂一根线，拉着下一个**。盒子本身待在原地不动，靠线把它们串成一串。

前面那张类定义（`class 盒子`）我们在真跑里用过：每个盒子装两样 —— **自己的名字**，和**指向下一个的线**（没有下一个就是 `None`）。

先看**插一个**要花多少力气。我们两边都数了一遍：

```python
class 盒子:
    def __init__(self, 名字):
        self.名字 = 名字
        self.下一个 = None


第一个 = 盒子("一")
第一个.下一个 = 盒子("二")
第一个.下一个.下一个 = 盒子("三")

新来的 = 盒子("新")
动线次数 = 0
新来的.下一个 = 第一个
动线次数 = 动线次数 + 1
第一个 = 新来的
动线次数 = 动线次数 + 1
print("链子往最前面插一个：动了", 动线次数, "根线")

一排元素 = ["一", "二", "三"]
搬了几次 = 0
一排元素.append(None)
for i in range(len(一排元素) - 1, 0, -1):
    一排元素[i] = 一排元素[i - 1]
    搬了几次 = 搬了几次 + 1
一排元素[0] = "新"
print("一排元素往最前面插一格：搬了", 搬了几次, "次")
```

```text
链子往最前面插一个：动了 2 根线
一排元素往最前面插一格：搬了 3 次
```

- **链子：2 根线** —— 第一根让新来的拉住原来头一个，第二根把头换成新来的。**一个盒子都没挪窝**；
- **一排元素：3 次** —— 因为要往最前面插，原本那 3 格**每一格都得往后挪一格**，不然没地方放。

这里的 3 和上面的 15、499500 是同一回事：**往前插一格，就得搬动它后面所有格**。元素里 3 格就搬 3 次，1000 格就搬 1000 次 —— 又是 `O(n)`。而链子呢：**插在最前面、插在中间、链子有 3 只还是 100 万只，都只动那 2 根线**，`O(1)`。

::: warn 注意
**插线有个顺序，反了就把后面的盒子全弄丢了。**

要往「一」和「二」中间插一个「新」，必须**先接后面那根，再动前面那根**：

```python
class 盒子:
    def __init__(self, 名字):
        self.名字 = 名字
        self.下一个 = None


第一个 = 盒子("一")
第一个.下一个 = 盒子("二")

新来的 = 盒子("新")
新来的.下一个 = 第一个.下一个      # 第一根：先接后面
第一个.下一个 = 新来的              # 第二根：再动前面

走 = 第一个
while 走:
    print(走.名字)
    走 = 走.下一个
```

```text
一
新
二
```

要是急着先把前面那根线改了（`第一个.下一个 = 新来的`），原来那根线就被**覆盖**掉了 —— 「二」和它后面的一整串，从此谁也够不着。而且它**不报错、不崩**：走一遍的时候少印几个，你还以为链子本来就那么长。**越是安静的错，越要靠「先接后、再动前」这个顺序去躲。**
:::

链子插进去便宜，那它是不是处处都比一排元素强？**不是。**两头各有代价，看另一半：

```python
class 盒子:
    def __init__(self, 名字):
        self.名字 = 名字
        self.下一个 = None


第一个 = 盒子("一")
第一个.下一个 = 盒子("二")
第一个.下一个.下一个 = 盒子("三")
第一个.下一个.下一个.下一个 = 盒子("四")

走 = 第一个
跳了几次 = 0
while 走.下一个:
    走 = 走.下一个
    跳了几次 = 跳了几次 + 1

一排元素 = ["一", "二", "三", "四"]
print("链子上最后一个：顺着线跳了", 跳了几次, "次，它是", 走.名字)
print("一排元素里最后一样：报编号直接取，它是", 一排元素[len(一排元素) - 1])
```

```text
链子上最后一个：顺着线跳了 3 次，它是 四
一排元素里最后一样：报编号直接取，它是 四
```

- **链子：跳了 3 次** —— 它手里只有「第一个」这根线头，想知道最后一个叫什么，只能**一个一个顺着线数过去**。4 只要跳 3 次，1000 只就要跳 999 次 —— `O(n)`；
- **一排元素：报编号直接取** —— 不管 4 格还是 100 万格，`一排元素[len(一排元素) - 1]` 一步就到，`O(1)`。

一句话收拢这一节：**链子的便宜在「改」，一排元素的便宜在「找」。**

- 常常要在中间插、往中间摘（而且是站在那儿就地改）→ 链子省事；
- 常常要「报个编号就要那一样」、或者从末尾上进出 → 一排元素省事。

**没有谁全面赢，只有谁更配这活。**

## 五、三样摆一起看

| 家什 | 进出的规矩 | 进 / 出一次的代价 | 报编号找第 k 个 | 适合的活 |
|---|---|---|---|---|
| 一摞元素（栈） | 同一头进、同一头出（后进先出） | `O(1)`：只碰最上面一格 | 中间要 `O(n)` | 撤销、后退、括号配对 |
| 排队绳（队列） | 末尾进、头上出（先进先出） | `O(1)`：两头都留着一截空位 | 中间要 `O(n)` | 按先来后到办事 |
| 一排元素 | 排成一排，报编号取 | 末尾 `O(1)`；**头上 `O(n)`** | `O(1)` | 想报编号就取的那排元素 |
| 链子（链表） | 一环牵一环 | 站在口子上插 / 摘 `O(1)`（只动线） | `O(n)`：得一个只数过去 | 频繁在中间插、摘 |

这张表里每一格的代价，我们这一课都**真跑数过**：末尾进出搬 **0** 次、一排元素从头领 1000 条搬 **499500** 次、链子插一个动 **2** 根线、链子找第 4 只跳 **3** 次。**圈数是确定的，秒数会飘** —— 所以要紧的判断都用圈数说，秒数只在旁边当个旁证。

::: tip 提示
今天收五句话：

1. **进出的「规矩」就是选家什的第一条**：同一头进出 = 一摞元素（后进先出），一头进一头出 = 排队（先进先出）。
2. **一摞元素不用新函数**：`append` 和 `pop()` 都在**末尾**动手，所以都是 `O(1)`。
3. **拿一排元素从头拿（`pop(0)`）是坑**：1000 条要搬 499500 次，`insert(0, x)` 也一样 —— 想两头都快就换 `collections.deque` 的 `popleft()`。但 `deque` 不是排队的唯一做法，它本身是「两头都能进出的绳子」。
4. **链子插得便宜、找得贵**：插一个只动 2 根线，但找第 k 只要跳 k-1 次线。能不能换，看你的活是「改得多」还是「找得多」。
5. **判断一律用圈数**：`O(1)` 是「跟有多少条无关」，`O(n)` 是「有几条就搬几条」—— 一个数说了算，不看机器心情。
:::
