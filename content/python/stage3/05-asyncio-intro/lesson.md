## 学习目标

本课学习异步编程 asyncio 初步。重点包括async/await、事件循环直觉、asyncio.run。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 协程与事件循环

`async def` 定义协程函数，调用它得到协程对象。`await` 等待可等待对象完成，并在需要等待时把控制权交回事件循环。事件循环调度已就绪的任务；`asyncio.gather` 可组织多个协程的并发执行，`asyncio.run` 管理顶层事件循环并运行入口协程。

异步函数中的阻塞调用仍会阻塞事件循环。网络等待可以受益于异步 I/O；持续占用 CPU 的计算通常需要其他并行方案。下面对照同步等待和异步等待，观察执行顺序与总耗时。

```python
import asyncio

async def 打招呼():
    print("我们来啦")

asyncio.run(打招呼())
```

```text
我们来啦
```

逐句拆开看：

- **`import asyncio`** —— 把事件循环这套家伙什请进屋。`asyncio` 是 Python 自带的一盒工具，不用另外装。
- **`async def 打招呼():`** —— 定义一个方法**不着急的函数**。`async` 写在 `def` 前面，意思是「这一个方法什么时候跑，由事件循环说了算」。
- **`asyncio.run(打招呼())`** —— **请出事件循环**，让它把这一个方法跑完，跑完就收工。

中间那一句最要紧：**`打招呼()` 继续调用，函数里一行都不会跑**。它只返回一张「**待办小纸条**」，上头写着「我们想干这件事」。真正把活儿交到事件循环变量里的，是外面的 `asyncio.run(...)`。

所以你要是只写了 `打招呼()`、忘了外面的 `asyncio.run(...)`，程序**一个字都不会印**。它不是坏了，是事件循环压根没被请出来。

⚠️ 不过屏幕也不是全干净的：收尾的时候角落里会冒出一句 `RuntimeWarning: coroutine '打招呼' was never awaited`。那是**警告**，不是报错 —— 我们真跑过：退出码 `0`、函数里那行 `print` 一个字没出，屏幕上只有这一句警告（197 字节）躺着。看见它别当装饰，它就是「**有张纸条没人接**」的告示。

## `await`：等的时候，把变量让出来

现在让锅真的「等一等」：

```python
import asyncio

async def 烧水():
    print("架上水壶")
    await asyncio.sleep(0.2)
    print("水开啦")

asyncio.run(烧水())
```

```text
架上水壶
水开啦
```

- **`await`** 读作「**等它**」。它后面跟的那一样，就是我们要等的那口锅。
- **`asyncio.sleep(0.2)`** 就是「等 0.2 秒」这口锅。
- `await` 的妙处全在这个「让」字：**我们把变量让出来**，先去看其他任务；等这口到点了，再回来接着走下面那行 `print("水开啦")`。

对照一下以前的等法：要是用 `time.sleep(0.2)`，那是「**抱着变量死等**」——这 0.2 秒里谁也别想动，旁边的锅只能干瞪眼。`asyncio.sleep` 是**不占变量的等**，差别就在这里。

还有一条规矩：`await` **只能住在 `async def` 的函数里面**。写到外面去，解释器会当场拦下来，跟你说这里不许写 `await`。

## 一口气架上好几口锅：`asyncio.gather`

刚才只架了一个异步任务。真要事件循环的本事，得**一次架好几口**：

```python
import asyncio

async def 拿数据(名字, 秒数):
    await asyncio.sleep(秒数)
    return f"{名字}的数据"

async def 主函数():
    结果 = await asyncio.gather(
        拿数据("张三", 0.3),
        拿数据("李四", 0.1),
    )
    for 一条 in 结果:
        print(一条)

asyncio.run(主函数())
```

```text
张三的数据
李四的数据
```

拆开看：

- **`拿数据`** 也是一个方法不着急的函数。它名字后面括号里那两样，是**传入给它的**：要谁的数据、要等多久。
- **`asyncio.gather(...)`** —— 「**这几口锅一起架上**」。括号里可以塞好几张待办小纸条，它会等**全部**都好了再一起回来。
- 前面那个 `await` 还是它：我们在等**所有的锅**，等的这段时个变量全让出去了。
- 回来之后，**`结果` 是一个排好队的储物柜**：`结果[0]` 是第一条，`结果[1]` 是第二条，后面的按这个规矩一条条排下去。

**现在盯住输出的顺序。** 李四那条路线只要 0.1 秒，比张三的 0.3 秒**先回来**；可印出来的第一行还是**张三**。

因为 `gather` 有个规矩：**谁先回来不重要，结果一律按你投放的顺序摆好**。你写的是「先张三、后李四」，名单上就永远是这个次序，一条都不会乱。

这条规矩对你特别友好：**不用去猜谁快谁慢**，只要顺序写清楚，结果就永远是那个顺序。

还有一件事值得体会：两个任务一起架着等，花掉的时间是**最慢那一口的时长**，不是两段时长加起来。省下来的全是干等的时间——这正是事件循环最值钱的地方。

## 事件循环只管「等」，不管「算」

有一件事必须说清楚，不然你会用错它。

事件循环的拿手好戏是**等**：等水开、等鱼出炉、等远处的对象回话。可要是某口锅的活是「**我们抱着铲子拼命翻炒三分钟**」，那变量就**一直占着**，让不出来。这种时候你架几口锅都没用，事件循环只能一口一口挨着炒。

所以：

- **大段大段都在等的活儿** —— 事件循环的主场：等回话、等文件读完、等定时器到点；
- **变量一直占着的活儿**（拼命算数、反复搬运）—— 事件循环帮不上忙，得请别的帮手。

下一课，我们要带你**隔着好几个工作区，把数据送给远处的对象**——那正是事件循环最出风头的地方。

::: tip 提示
今天记住四个口令就够啦：

- **`async def`** —— 定义一个方法**不着急的函数**；称呼它**不会马上跑**，只返回一张待办小纸条。
- **`await`** —— 把活儿交给事件循环看着，我们先把变量让出来；好了再回来接着往下走。
- **`asyncio.run(函数())`** —— 请出事件循环，把主函数跑完。**少了它，一张纸条都不会动**。
- **`asyncio.gather(好几张纸条)`** —— 一口气全架上，全好了再一起返回，**按你投放的顺序**摆好。
:::

::: warn 注意
三个最容易踩的坑：

- **忘了 `await`**：写成 `结果 = 拿数据("张三", 0.3)`，我们拿到的**不是数据**，而是一张待办小纸条。它躺在那儿什么都不干——要 `await` 才会真的跑起来。⚠️ 别以为它**一点动静都没有**：这张没人接的纸条被收走的时候，屏幕上会嘀咕一句 `RuntimeWarning: coroutine '拿数据' was never awaited`（我们真跑过：正文照印、退出码 `0`，那句警告 266 字节）。是警告不是报错，所以最容易看漏。
- **忘了 `asyncio.run(...)`**：函数写得再漂亮，程序跑完也**一个字都不印**（屏幕上剩下的，只有角落里那句 `RuntimeWarning`）。不是函数坏了，是事件循环没被请出来。
- **把 `await` 写到函数外面**：`await` 只能住在 `async def` 里面，写到外面解释器会拦下来报错。
:::

| 写下的这一句 | 它干了什么 |
|---|---|
| `import asyncio` | 把事件循环这套家伙什请进屋 |
| `async def 函数():` | 定义一个方法「不着急的函数」 |
| `asyncio.run(函数())` | 请出事件循环，把主函数跑完，收工 |
| `await 一样东西` | 把活儿交出去看着，我们先让出变量，好了再回来 |
| `await asyncio.sleep(秒数)` | 不占变量的等一等（不是抱着变量死等） |

| `结果[0]`、`结果[1]` | 从排好队的储物柜里按位置取结果 |

## 小任务

我们把三个异步任务一起架上了，你照着敲一遍跑跑看：

```python
import asyncio

async def 拿数据(名字, 秒数):
    await asyncio.sleep(秒数)
    return f"{名字}的数据"

async def 主函数():
    结果 = await asyncio.gather(
        拿数据("张三", 0.3),
        拿数据("李四", 0.1),
        拿数据("三花", 0.2),
    )
    print(结果)

asyncio.run(主函数())
```

```text
['张三的数据', '李四的数据', '三花的数据']
```

**试着改一改**：

1. 把 `三花` 那一条挪到最前面，再跑一遍——印出来的储物柜里，它排第几？为什么？
2. 把 `三花` 的秒数改成 `0.5`，让它变成最慢的那一位。再跑——输出的**顺序**会变吗？（提示：先别急着改，猜一猜再跑。）
3. 把 `gather` 那一整段换掉，改成一句一句地 `await`（先 `await 拿数据("张三", 0.3)`，再 `await 拿数据("李四", 0.1)`）。印出来的东西**一模一样**，可我们花掉的等待时间变成多少了？
