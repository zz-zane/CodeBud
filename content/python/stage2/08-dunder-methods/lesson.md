## 学习目标

本课学习魔法方法与运算符重载。重点包括__str__、__add__、常用魔法方法。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 魔法方法的三条规矩

1. **名字前后各是两条下划线**：`__str__`、`__add__`、`__len__`、`__eq__`。少一条都不行 —— 写成 `_str_` 就只是个普通名字，Python 永远不会替你称呼它。
2. **写在类定义里面**，缩进照旧，和别的函数一起排好队。
3. **你不主动称呼它们**，是 Python 在特定时刻替你调用。我们写代码时从来不写 `a.__add__(b)`，只写 `a + b`，剩下的是 Python 的事。

下面我们把四个最常用的时刻挨个走一遍。

## `__str__`：这个元素被打印的时候，该长什么样

我们直接用 `print(a)` 打印一个元素，屏幕上冒出来的是一串谁也不认识的怪字（里面夹着类定义名和一串十六进制地址）。那是给电脑看的**住址**，不是给对象看的名字。

想让 `print(a)` 印出我们想要的样子，就在类定义里加一个方法 `__str__`：

```python
class Bowl:
    def __init__(self, n):
        self.n = n

    def __str__(self):
        return f"保存了 {self.n} 条数据"

a = Bowl(3)
print(a)
```

```text
保存了 3 条数据
```

- **时刻**：`print(a)` 的时候，Python 会先悄悄调用一遍 `a.__str__()`，拿它返回的那句话去印。
- **必须用 `return` 把话返回**，不能只在里面 `print`。要是写成 `print(f"...")` 而不返回，Python 拿不到话，会当场翻脸说「返回的不是一句话」。
- 名字里那个 `str` 是「**话**」的意思：这一个方法回答的问题是「**这个元素该被说成什么样**」。

## `__add__`：`+` 遇上这个元素的时候，该干什么

```python
class Bowl:
    def __init__(self, n):
        self.n = n

    def __str__(self):
        return f"保存了 {self.n} 条数据"

    def __add__(self, other):
        return Bowl(self.n + other.n)

a = Bowl(3)
b = Bowl(4)
print(a + b)
```

```text
保存了 7 条数据
```

- **时刻**：`+` 的**左边**摆着这个元素的时候。我们写 `a + b`，Python 背地里引用的是 `a.__add__(b)`。
- **`self` 是 `+` 左边那个**（`a`），**`other` 是右边那个**（`b`）。记不住就把这两个名字念一遍：自己、另一个。
- **它返回的是一个新元素**：`Bowl(self.n + other.n)` 照着类定义**新生成**一个保存了 7 条的。原来那两个元素**一点没被动过** —— 这和数字的加法一个脾气，`3 + 4` 也不会把 3 改成 7。
- 少了这一个方法会怎样？`a + b` 上一课那种「翻遍规矩册没这一条」的错就会冒出来。**`__add__` 就是我们给 `+` 补的那条规矩。**

## `__len__` 和 `__eq__`：`len(...)` 和 `==` 的时刻

```python
class Bowl:
    def __init__(self, n):
        self.n = n

    def __len__(self):
        return self.n

    def __eq__(self, other):
        return self.n == other.n

print(len(Bowl(5)))
print(Bowl(5) == Bowl(5))
```

```text
5
True
```

- **`__len__` 的时刻**是 `len(...)` 套在这个元素上的时候。它返回的必须是**一个不小于 0 的整数**（Python 拿这个数去数「有几样」），返回别的东西它会翻脸。
- **`__eq__` 的时刻**是 `==` 两边摆着两个元素的时候。它得返回 `True` 或 `False`。
- **不写 `__eq__` 会怎样？** Python 默认只比「**是不是同一个元素**」。两个元素是分别创建后的，哪怕装的都是 3 条，`Bowl(3) == Bowl(3)` 也会是 `False` —— 这个结果常常不是我们想要的，所以想让「装的数一样就算相等」，就得自己把 `__eq__` 写上。
- `__eq__` 里的 `self.n == other.n` 比的是**两个数字**，不是两个元素 —— 数字的 `==` Python 天生就认，不会再回头去调用 `__eq__`，所以这里不会转圈圈。

::: tip 提示
魔法方法就记一句话：**名字被两条下划线夹住，Python 在特定时刻替你调用**。

| 时刻 | 被引用的函数 |
|---|---|
| 根据类创建一个实例 | `__init__` |
| 这个对象被 `print` | `__str__` |
| `+` 的左边摆着这个对象 | `__add__` |
| `len(这个对象)` | `__len__` |
| `==` 两边摆着两个对象 | `__eq__` |

写的时候只管写 `a + b`、`len(a)`、`print(a)` —— **我们从来不手写 `a.__add__(b)`**，那是 Python 的活。
:::

::: warn 注意
三个最容易踩的坑：

- **数错下划线**。前后**各两条**，一共四条。写成 `_str_`、`__str_`、`_str__` 都不算数 —— 那个是一个普通名字，Python 永远不会替你调用，而程序**不报错**，我们只会百思不得其解「怎么没生效」。
- **`__str__` 里忘了 `return`**。它的任务是**把话返回**，不是自己印。只印不返回，Python 拿不到话，当场翻脸。
- **以为 `__add__` 会改原来那个元素**。它返回的是**一个新元素**，原来那两个好好的。想让 `a` 自己变，得自己写 `a = a + b` 重新接住。
:::

## 一句话对照表

| 写下的这一个方法 | Python 什么时候替你称呼它 | 它得返回什么 |
|---|---|---|
| `def __init__(self, n):` | 根据类创建一个实例的时候 | 不用返回（它只管把变量建好） |
| `def __str__(self):` | 这个对象被 `print` 的时候 | 一句话 |
| `def __add__(self, other):` | `+` 的左边摆着这个对象的时候 | 一个新对象（或一个结果） |
| `def __len__(self):` | `len(这个对象)` 的时候 | 一个不小于 0 的整数 |
| `def __eq__(self, other):` | `==` 两边摆着两个的时候 | `True` 或 `False` |
