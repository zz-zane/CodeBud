## 学习目标

本课学习迭代器与生成器深入。重点包括iter/next、yield、惰性计算。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## `iter` 和 `next`：一个会「下一条」的手

```python
bowls = ["数据", "商品", "商品"]

it = iter(bowls)
print(next(it))
print(next(it))
print(next(it))
```

```text
数据
商品
商品
```

- **`iter(一排东西)`** —— 从这一排里请出**一个会「下一条」的手**。这个手自己揣着一个记录表，记着「我们夹到第几格了」。
- **`next(手)`** —— 「**把下一格的东西返回**」。调用一次，它往前走一格。
- 注意 `iter(bowls)` **没有**把元素里的东西复制一份出来，只是请了只手指着这排元素。手走过的地方，**元素还在原地**——所以走完之后 `bowls` 本身一点没变。

跟上一课接上了：`for x in 一排东西:` 之所以能一行行取出来，就是因为 Python 在背地里**先 `iter` 请出手，再一遍遍 `next`**。今天我们只是把背后那几步搬到台面上来。

## 拿完了还调用，会怎么样

```python
bowls = ["数据", "商品"]

it = iter(bowls)
print(next(it))
print(next(it))
try:
    print(next(it))
except StopIteration:
    print("元素空啦")
```

```text
数据
商品
元素空啦
```

- 只手一共有两格，前两次 `next` 把东西都取走了。**第三次**再调用，它没东西可给了，会**当场翻脸**，甩出一个叫 `StopIteration` 的东西出来。
- `StopIteration` 是这套机制**故意**留的信号，意思就一句：「**我们这儿没有下一条了**」。
- `try` / `except` 是前面学过的「**先试一手，翻脸了就走另一条路**」的写法。这里的意思：先试着再要一条，要是它扔出 `StopIteration`，我们就印一句「元素空啦」，不跟它吵。
- 这也正是 `for` 为什么能安安静静把一排东西走完、也不翻脸 —— 因为 `for` **背后悄悄接住了这个信号**。收到 `StopIteration`，它就当作「走完了」，收工。

## 函数里开个口子：`yield`

```python
def 数数据():
    yield 1
    yield 2
    yield 3

it = iter(数数据())
print(next(it))
print(next(it))
print(next(it))
```

```text
1
2
3
```

- 函数里一出现 `yield`，这一个方法就**变了性质**：称呼它的时候它**不马上跑**，而是返回一个「**会下一条的手**」——和上一课不写括号的函数那种「函数也是东西」是一个脾气，只是它还多带了一个手。
- 每调用一次 `next`，它才**从上次停下的地方接着往下跑**，跑到下一个 `yield` 就停住，把 `yield` 后面的东西递出来。
- 停住的时候，函数里那些变量（比如数到几了）**原样留着**，下次接着用。所以三次 `next` 才能依次拿到 1、2、3。
- **`yield` 和 `return` 的区别**：`return` 是「我们干完收摊，整招就这一回」；`yield` 是「我们先递一样东西出去，**待会儿还回来接着干**」。一个是一次性的，一个是能来回好几趟的。

「**停住**」这件事在屏幕上是看不见的 —— 它既没有印出来，也没有报错。我们把它拆成一步一步，走给你看：

## 惰性：你不调用，它就不动

```python
def 数数据():
    print("我们开始数啦")
    yield 1
    yield 2

print("先把函数放好")
it = iter(数数据())
print("现在开始数")
print(next(it))
```

```text
先把函数放好
现在开始数
我们开始数啦
1
```

盯住输出的**顺序**：「我们开始数啦」居然**排到了最后**，比 `print("现在开始数")` 还晚！

因为调用 `数数据()` 的那一刻，函数里**一行都没跑**，只是把手准备好了。直到 `next(it)` 继续调用，它才真的开演。这就叫**惰性**：「**你不称呼它就不动**」。

## 用不完的数据

```python
def 无限数据():
    n = 0
    while True:
        n = n + 1
        yield n

it = iter(无限数据())
print(next(it))
print(next(it))
print(next(it))
```

```text
1
2
3
```

这一个方法**永远数不完**：`while True` 让它一头扎进去，一直转下去。可我们只取了三条，程序**一点都没卡住** —— 换成一个储物柜试试，早撑爆了。

为什么它不卡？还是那条惰性：它**不会傻乎乎地先把东西全算出来摆好**，而是你要一条、它算一条。这就是生成器最值钱的地方：**要多少给多少，不提前囤**。

## 手走过就走过了，回头没有第二条

```python
def 数数据():
    yield "数据"
    yield "商品"
    yield "商品"

it = iter(数数据())
print(next(it))
print(list(it))
```

```text
数据
['商品', '商品']
```

- `next(it)` 先取走第一条「数据」。
- `list(it)` 读作「**把剩下的全都装进一个储物柜里**」。它顺着这个手继续往前走，把手上的东西一样不落全收进去 —— 所以拿到的是**剩下来的两条**，第一条早被取走了。
- 再加上前面那个「拿完了会翻脸」的例子，就推出一个要紧的规矩：**一个手只能走一遍**。走过去了就回不来了，想再来一次得重新 `iter(数数据())` 请一个新的手。

::: tip 提示
- **`iter(一排东西)`** —— 请出一个记着「夹到第几格了」的手。
- **`next(手)`** —— 把下一格返回；没东西了会扔出 `StopIteration`。
- **`for`** —— 背后就是「先 `iter` 请手，再反复 `next`，接住 `StopIteration` 收工」，我们不用自己写。
- **`yield x`** —— 函数里开个口子：递出 `x`，停在这儿，下次接着往下跑；函数里的变量原样留着。
- **惰性** —— 你不称呼它就不动。这一点让它能对付「永远数不完」的东西，也不怕东西多得装不下。
- **一个手只能走一遍**，走完就空了，想重来就再 `iter` 一个新的。
:::

::: warn 注意
三个最容易踩的坑：

- **`yield` 写成了 `return`**。写成 `return 1`，这一个方法跑一次就收摊了，后面那两行 `yield` 再也轮不到，我们会以为「怎么只拿到一条」。
- **拿完了还接着 `next`**。它会甩 `StopIteration` 出来。用 `for` 走就没事 —— `for` 自己会接住它；自己手写 `next` 就得留个心。
- **把一个走空的手再走一遍**。走空了之后它**不会自己复原**，接着 `next` 只会继续翻脸，`list(...)` 也只会给一个空储物柜。想重来，得重新请一个手。
:::

## 一句话对照表

| 写下的这一句 | 它干了什么 |
|---|---|
| `it = iter(一排东西)` | 请出一个记着「夹到哪了」的手 |
| `next(it)` | 把下一格返回；没了就扔出 `StopIteration` |
| `try:` / `except StopIteration:` | 先试一手，翻脸了就换条路走 |
| `def 函数():` 里有 `yield` | 称呼它不马上跑，返回一个「会下一条的手」 |
| `yield n` | 递出 `n`，停在这儿；下次从这一行接着往下跑 |
| `while True:` + `yield` | 永远数不完的一串 —— 靠惰性才不会卡住 |
| `list(it)` | 把手上的东西全收进一个储物柜里 |
