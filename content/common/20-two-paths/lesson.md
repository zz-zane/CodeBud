## 学习目标

本课学习过程分解与对象分解。重点包括路一：一条流水线、路二：几个角色各干各的、四位编译器或解释器的两条路、谁负责的差别。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 路一：把事拆成一条流水线

我们先走熟路。在 C 里，这件事写成这样：

```c
#include <stdio.h>

float rect_area(float w, float h) {
    return w * h;
}

int main(void) {
    float w = 3;
    float h = 4;
    float area = rect_area(w, h);
    printf("面积是 %.0f\n", area);
    return 0;
}
```

```text
面积是 12
```

拆开看：

- **`float w = 3;` 和 `float h = 4;`** —— 先把两样料摆在桌上：长和宽。
- **`float rect_area(float w, float h)`** —— 旁边单独摆一个方法「算面积」：谁把长和宽传入，它就把谁算一算。
- **`float area = rect_area(w, h);`** —— 调用一次，把桌上那两样料传入函数，算出的 12 返回，落进 `area` 这个元素。
- **`printf(...)`** —— 把元素里的结果印出去，交差。

看仔细一件事：**料和活是分开摆的**。长、宽、结果都是桌上的数；「相乘」是一个方法摆在外头的函数。函数头上只写着「要两样料」，**一个字都没写要谁家的料** —— 你喂什么，它就算什么。

这条路，是把一件事拆成一条**动作流水线**：一步接一步，谁先谁后排得明明白白，料在元素里递过来、递过去。

老已有实现对象把这条路总结成一句顺口溜：**程序 ＝ 数据结构 ＋ 算法** —— 一边是料，一边是活，两摞摆好，顺序排好。

## 路二：把事拆出几个角色

我们换个拆法。先别急着排步骤，先问一句：**这件事里有谁？**

有一块地垫。长和宽是**它自己带着的**；「算出自己的面积」是**它自己会的**。外头不用递料，只要点名调用一次就行：

```python
class Rect:
    def __init__(self, w, h):
        self.w = w
        self.h = h

    def area(self):
        return self.w * self.h

r = Rect(3, 4)
print(f"面积是 {r.area()}")
```

```text
面积是 12
```

一行一行看：

- **`class Rect:`** —— 摊开一张叫 `Rect` 的类定义，上面写清「照我创建后的每一块地垫，都长什么样、会什么」。
- **`def __init__(self, w, h):`** —— 对象初始化与资源释放：**照它创建一块的时候，先把长和宽传入**。
- **`self.w = w` / `self.h = h`** —— 传入的两样，装进**这一块自己**身上（`self` 读作「我们自己」）。
- **`def area(self):`** —— 类定义上写的本事：每一块照它创建后的，**自己会算自己的面积**。
- **`r = Rect(3, 4)`** —— 根据类创建出一块地垫，起名叫 `r`；3 和 4 装进**它自己**身上，不摆在公共桌上。
- **`r.area()`** —— **先点名 `r`，再调用本事**。用哪份长和宽？它自己知道，不用你递。

同一件事换到 Java，是这个样子：`Rect r = new Rect(3, 4);` 先创建一块 `r`，再 `r.area();` 点名让它算。

这条路，是把一件事拆出**几个角色**：每个角色带着自己那份料、自己会干的那件事，谁的事谁负责，互相输出把活办完。

老已有实现对象给这条路也配了句顺口溜：**程序 ＝ 一组互相协作的对象（一群角色）** —— 互相输出，把活办完。

## 等一下——这不就是把函数塞进结构体里吗？

我们猜你现在心里冒出一句：「路二……不就是**把函数塞进结构体里**吗？」

先别急着下这个结论。我们当场给你一句判据，先记下它 —— 往后有一课，咱俩把两种写法并排摆出来，我们再拿它一条一条跟你对账：

> **封装＝藏数据、露行为。**

「藏数据」：料收进角色自己身上，别摊在桌上让谁都能伸手乱改；「露行为」：它会干的事亮出来，一个名字就调用得动。只把函数挪个地方、数据还摊在外面 —— 那连这条判据的第一半都没走到。这条路长什么样，急不得，后面一课一课兑现给你看。

还有一句我们也替你先说了：**「可路二明明更长啊。」** 嗯，眼下确实更长 —— 多出来的那几行，是在摊一个类定义。先别急着比长短，我们给你埋个悬念：等哪天需求改了，要看的不是谁写得短，而是**谁不用改** —— 到那时候，你再来找我们算这笔账。

## 四位编译器或解释器，同一件小事两条路

同一条地垫，长 3、宽 4。我们把两条路都交给四位编译器或解释器走一遍 —— 你会看到**两条路都走得通**，也看到**写法差得有多远**：

```compare
c::
#include <stdio.h>

float rect_area(float w, float h) {
    return w * h;
}

int main(void) {
    float w = 3;
    float h = 4;
    float area = rect_area(w, h);
    printf("面积是 %.0f\n", area);
    return 0;
}

cpp::
#include <iostream>

class Rect {
public:
    double w;
    double h;

    Rect(double a, double b) {
        w = a;
        h = b;
    }

    double area() {
        return w * h;
    }
};

int main() {
    Rect r(3, 4);
    std::cout << "面积是 " << r.area() << std::endl;
    return 0;
}

java::
public class Main {
    static class Rect {
        int w;
        int h;

        Rect(int w, int h) {
            this.w = w;
            this.h = h;
        }

        int area() {
            return w * h;
        }
    }

    public static void main(String[] args) {
        Rect r = new Rect(3, 4);
        System.out.println("面积是 " + r.area());
    }
}

python::
class Rect:
    def __init__(self, w, h):
        self.w = w
        self.h = h

    def area(self):
        return self.w * self.h

r = Rect(3, 4)
print(f"面积是 {r.area()}")
```

```text
面积是 12
```

- **C**：走的是路一。C 里能画的最像类定义的东西叫**结构体（`struct`）**，可它只装得住料；会干活的函数得单独摆在外头。这一手以后有一课专门把它用到极限。
- **C++**：是一座**桥**。`class` 把料和活收到一起，创建一块写成 `Rect r(3, 4);`，再 `r.area();`；可路一那套「单独摆一个方法」的写法它一个字没扔 —— 两种拆法它都会。
- **Java**：走的是路二，根据类创建一块得调用 `new` 的口令：`Rect r = new Rect(3, 4);`，再点名 `r.area()`。
- **Python**：也是路二，创建一块就是调用一次 `Rect(3, 4)`，算面积写 `r.area()`。

四段屏幕上的数**一模一样**，都是 12 。

## 我们墙上的路线图

我们在墙上钉了一张路线图 —— 今天这两条路里，路二会越走越宽。往后一站一件事，先认个脸熟：

- **起名字**：给重复出现的模式起个名字 —— 这是路二上一切本事的引擎；
- **分楼层**：让「用的人」和「造的人」分开站，里面随便换，用的人不用管；
- **半个对象（差半张类定义）**：先在 C 的地盘上把结构体用到极限，看缺的那半自己怎么冒出来；
- **同一本账，两种写法**：结构体版和类定义版并排摆，亲手改一遍；
- 再往后是**指针的接班人**、**从租变量到请对象入住**、**对象初始化与资源释放**、**封装**……
- 最后把类定义一层层叠起来：**继承**、**一次处理各处理各的**，再穿过语法看清**「一切皆对象（连 3 都有身份）」**；
- 这条路走到最后，会回到我们最爱的那一课：**《类与对象》**。

现在一个都不用记 —— 知道「这条路有站、一站只拆一件」就够。

::: tip 提示
今天这四句话，一串就够：

1. **路一**：把事拆成一条**动作流水线** —— 料摆一摊、活摆一摊，一步接一步；
2. **路二**：把事拆出几个**角色** —— 料长在自己身上，会干的事也长在自己身上，调用谁谁动；
3. 两条路**都能把活干完**（今天的 12 一模一样），差别在「料和活摆在哪」；
4. 想验「真走上路二没有」，判据先记这一句：**封装＝藏数据、露行为**。

往后十四课，我们一站只拆一件，慢慢把路二摆到你面前。
:::

::: warn 注意
两个坑，提前打招呼：

- **输出一样，不等于两条路一样。** 别拿「都能印出 12」当证据说「那随便哪条都行」——「谁在负责」完全不同：路一里，是这条流水线在负责；路二里，是每一块地垫在负责自己的面积。这一点，等加需求的时候会狠狠显出来。
- **「把函数塞进结构体里」这句话，先别急着说。** 它只说了「函数挪了个地方」，压根没碰到路二的判据。要是数据还摊在外面谁都能改，那连一半都没走到 —— 记住判据：**封装＝藏数据、露行为**。
:::
