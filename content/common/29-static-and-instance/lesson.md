## 学习目标

本课学习静态成员与实例成员。重点包括程序入口与对象设计、static：静态成员、第一版：静态成员、第二版：让实例自己跑、一个类定义能造几个对象。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 程序入口与对象设计

程序入口决定从哪里开始执行；对象设计决定数据和操作属于哪个类或实例。入口代码通常负责初始化并调用业务逻辑，两者职责不同。

- **C 的入口**：`int main(void) { ... }`，整份程序从这儿开始；
- **C++ 的入口**：`int main() { ... }`，也是从这儿开始；
- **Java 的入口**：`public static void main(String[] args) { ... }`，挂在一个类定义上；
- **Python 的入口**：文件末尾上那句 `if __name__ == "__main__":` —— 意思是「只有本文件被直接跑起来，才从这儿进」。

程序入口应保持清晰。业务数据和操作可按职责组织为函数、类及实例成员，不必全部集中到入口函数中。

## `static`：静态成员

前几课立过一条规矩：类定义上写着「每个对象都有名字、都有账」，照它创建后的每一个，**各带各的变量** —— 改学生甲的名字，李四那份一动不动。

可有一类东西，不按这条规矩走。

我们拿「一共开过几局」这种数试了试：记在张三那局头上？那李四那局开局的时候，谁跑去把张三的数加一？张三那局先散了，数又该寄在哪儿？—— 记在哪一局头上都不对。

它**属于类，由该类的实例共享**。这种成员叫**静态成员**，声明时添加关键字 `static`。每个实例分别保存的字段及通过实例调用的方法，叫**实例成员**。

类定义描述一种类型的字段和方法；根据该类创建的具体对象称为实例。同一个类可以创建多个实例，每个实例分别保存自己的实例字段。

念法上也分了家：

- **画在类定义上的那份，拿类定义名去念**：Java 写 `Game.plays`，C++ 写 `Game::plays`；
- **每局自己那份，拿实例名去念**：`game.fish`。

`Game.plays` 读作「`Game` 这张类定义上的 `plays`」。多写那几个字母不是啰嗦 —— 它一眼就告诉读代码的人：**这一份不是哪一局自己的东西**。

## 第一版：使用静态字段与静态方法

光讲道理没意思，我们摆两份代码给你看。

第一版通过静态字段累计一局游戏的结果。示例输出开局提示、三轮结果（2、1、3），最后输出总数。

```java
public class Main {
    static int fish = 0;                        // 一局的账，挂在门口
    static void play(int round, int got) {      // 抓一圈
        fish = fish + got;
        System.out.println("第 " + round + " 圈：抓到 " + got + " 条");
    }

    public static void main(String[] args) {
        System.out.println("开局！");
        play(1, 2);
        play(2, 1);
        play(3, 3);
        System.out.println("收工！一共 " + fish + " 条");
    }
}
```

```text
开局！
第 1 圈：抓到 2 条
第 2 圈：抓到 1 条
第 3 圈：抓到 3 条
收工！一共 6 条
```

能跑，我们认账。可盯住看 —— 这一版里**每一件家当都挂着 `static`**：`static int fish`（账）、`static void play`（抓一圈的函数），连 `main` 自己也是 `static`。

拆开看，这三者性质并不一样：

- **本例的Java入口采用传统静态main签名**：启动器可以直接调用 `public static void main(String[] args)`，不需要先创建Game实例。这不意味着业务字段和方法都应声明为static。
- **业务成员应根据共享范围决定是否静态**：若fish与play表示某一局的状态和操作，可将它们设计为实例成员，分别保存每局的数据。

这正是把 C 那套原样搬进类定义的样子：**程序入口 + 一叠自由函数**，数据与动作分开住。这份写法在 C 的地盘上**不丢人** —— C 里本来就没有类定义这回事。可原样搬进类定义里还这么写，就是给过程式的程序**套了层壳**：外头像类定义，里头还是老样子。

## 第二版：创建一个实例，让它自己跑

同一局游戏、同一份输出，只换写法：

```java
class Game {
    int fish = 0;                       // 这一局自己的账

    void play(int round, int got) {
        fish = fish + got;
        System.out.println("第 " + round + " 圈：抓到 " + got + " 条");
    }

    void run() {
        System.out.println("开局！");
        play(1, 2);
        play(2, 1);
        play(3, 3);
        System.out.println("收工！一共 " + fish + " 条");
    }
}

public class Main {
    public static void main(String[] args) {    // 门：只剩两行
        Game game = new Game();                 // 创建一局
        game.run();                             // 称呼它自己跑
    }
}
```

```text
开局！
第 1 圈：抓到 2 条
第 2 圈：抓到 1 条
第 3 圈：抓到 3 条
收工！一共 6 条
```

同一份输出，差别不在「能不能用」，在**谁的活**：

- `int fish` 前面没有 `static` —— 账跟着每一局自己走；
- `play`、`run` 前面也没有 `static` —— 它们不是画在类定义上的，它们在**等一个实例来调用**；
- 入口函数中只剩两行：**创建一局，称呼它自己跑**。

第一版使用类级别的共享状态；第二版将每局状态封装到Game实例中，main只负责创建实例并调用run。

## 一个类（一个类定义）能造几个对象？

回到标题里那个问题。

第二版里我们只写了 `new Game()` 一次。想再开一局？**再调用一次就行**：

```java
Game a = new Game();
Game b = new Game();
```

一个类定义，两局游戏。调用三声三局，调用一百声一百局 —— 类定义一个字都不用改。每一局各带各的账（`a.fish` 是 a 的，`b.fish` 是 b 的），谁也碰不着谁。

而静态成员（比如「一共开过几局」那种数）**所有实例只有一份**：两局都念得到它、动得了它 —— 因为它本来就不属于任何一局。

所以边界的判据句可以立起来了：

> **它是不是每一个（每一局）自己都得有一份？**
> 是 → 跟着实例走（不加 `static`）；不是 → 画在类定义上（加 `static`）。

## 四位编译器或解释器，同一局游戏

同一件事：**开一局对象游戏** —— 报开局、抓三圈（2、1、3 条）、收工报总数。C 拿得出的只有「入口函数中全塞满」那一版；后三位都把设计放回了类定义，入口函数中只剩两三行。

```compare
c::
#include <stdio.h>

int fish = 0;                        /* 账飘在门厅里，谁都能碰 */

void play(int round, int got) {
    fish = fish + got;
    printf("第 %d 圈：抓到 %d 条\n", round, got);
}

int main(void) {
    printf("开局！\n");
    play(1, 2);
    play(2, 1);
    play(3, 3);
    printf("收工！一共 %d 条\n", fish);
    return 0;
}

cpp::
#include <iostream>
using namespace std;

class Game {
public:
    int fish;                        // 这一局自己的账

    Game() : fish(0) {}              // 初始化那一刻把账起成 0

    void play(int round, int got) {
        fish = fish + got;
        cout << "第 " << round << " 圈：抓到 " << got << " 条" << endl;
    }

    void run() {
        cout << "开局！" << endl;
        play(1, 2);
        play(2, 1);
        play(3, 3);
        cout << "收工！一共 " << fish << " 条" << endl;
    }
};

int main() {
    Game game;                       // 创建一局
    game.run();                      // 它自己跑
    return 0;
}

java::
class Game {
    int fish = 0;                    // 这一局自己的账

    void play(int round, int got) {
        fish = fish + got;
        System.out.println("第 " + round + " 圈：抓到 " + got + " 条");
    }

    void run() {
        System.out.println("开局！");
        play(1, 2);
        play(2, 1);
        play(3, 3);
        System.out.println("收工！一共 " + fish + " 条");
    }
}

public class Main {
    public static void main(String[] args) {    // 门：两行
        Game game = new Game();                 // 创建一局
        game.run();                             // 它自己跑
    }
}

python::
class Game:
    def __init__(self):
        self.fish = 0                # 这一局自己的账

    def play(self, r, got):
        self.fish = self.fish + got
        print(f"第 {r} 圈：抓到 {got} 条")

    def run(self):
        print("开局！")
        self.play(1, 2)
        self.play(2, 1)
        self.play(3, 3)
        print(f"收工！一共 {self.fish} 条")

if __name__ == "__main__":           # 门：只有直接跑本文件，才从这儿进
    Game().run()
```

```text
开局！
第 1 圈：抓到 2 条
第 2 圈：抓到 1 条
第 3 圈：抓到 3 条
收工！一共 6 条
```

看出来了吗：

- **C**：C 只有第一版 —— 入口函数中就是全部家当，账（`fish`）飘在外面谁都能碰。这份写法在 C 的地盘上不丢人；本课只提醒一句：**别把它原样搬进类定义里**。
- **C++**：创建一局写 `Game game;`，称呼它跑写 `game.run();`。C++ 里「画在类定义上」也有一模一样的正牌写法：函数前面写 `static`，之后拿类定义名调用 `Game::run()` —— 和 Java 的 `Game.run()` 是一个意思；那一门课里细讲。
- **Java**：入口那行的 `static` 这回彻底拆明白了 —— 起步时一局都没有，入口声明在类定义上；`new Game()` 创建一局，`game.run()` 由它自己跑。
- **Python**：文件末尾那句 `if __name__ == "__main__":` 就是 Python 的入口 —— 它管「从哪儿进」，不管设计。想在 Python 里写「挂在类定义上、不用哪一局自己」的函数，要在函数头上盖一个小戳 `@staticmethod` —— 今天点到为止，往后见到它认识就行。

四句话收拢：**程序入口，每种语言都有相应写法，负责启动执行；`static` 回答的是「这东西属于谁」；设计放回类定义上，入口函数中就只剩「创建一个、调用一次」**。

::: tip 提示
今天记住三句话：

1. **main是程序入口**：负责启动与初始化。可将业务状态和操作放在职责明确的函数、类或实例中，由入口调用。
2. **`static` ＝静态成员**：属于整张类定义、不属于任何一个实例；念它的时候拿类定义名去念（`Game.plays`、`Game::plays`），读代码的人一眼就分得清。
3. **一个类可以创建多个实例**：各实例分别保存自己的实例字段，静态字段则由同一个类的实例共享。
:::

::: warn 注意
三个坑，我们标出来：

- **别给「每一个自己都要有」的东西加 `static`**：名字、这一局自己的账，加上它就变成所有实例共用一份 —— 三局下来互相盖住，只剩最后动过的那个数。加之前先过一遍判据句：**它是不是每一个（每一局）自己都得有一份？**
- **「编译不过」不是加 `static` 的信号**：在 Java 里，类定义上的函数回头去碰某个实例自己的格子，编译器或解释器会当场拦下：`non-static variable fish cannot be referenced from a static context` —— 它说的是「你现在站的这招旁边没有实例，够不着人家的格子」。正解是**把这一个方法也交还给实例**（去掉 `static`、拿实例名调用），而不是给格子贴一个 `static` 了事。
- **`Game.run()` 和 `game.run()` 打在两个东西上**：前者引用的是画在类定义上的函数（得先画上 `static`）；后者引用的是一局真游戏自己会的函数。少看一个大小写，意思就跑到对面去了。
:::

## 一句话对照表

| 我们写下的 | 它的意思 |
|---|---|
| `public static void main(String[] args)` | Java 的入口：程序从这儿进；那个 `static` 是被逼的 —— 起步那一刻还没有任何一局 |
| `if __name__ == "__main__":` | Python 的入口：只有直接跑本文件，才从这儿进 |
| `static int plays = 0;`（画在类定义里） | 静态成员：整张类定义共用，不属于哪一局 |
| `Game.plays` / `Game::plays` | 拿类定义名念：这是类定义上的东西，不是哪一局自己的 |
| `game.fish` | 拿实例名念：每一局自己那本账 |
| `Game game = new Game();` | 根据类创建一局真游戏 |
| `game.run();` | 调用这一局自己会的那一个方法 |
| `Game.run()`（C++ 里写作 `Game::run()`） | 想拿类定义名调用函数：那函数得是先画上 `static` 的 |
