## 学习目标

本课学习常见错误类型与诊断。重点包括语法错误、运行时错误、逻辑错误、如何读报错。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 错误信息分三种，脾气各不同

新手最容易糊在一起的一件事：**「报错」不是一个东西，是三种完全不同的脾气。**

| 类型 | 你会在什么时候遇到 | 屏幕上是什么样 |
|---|---|---|
| **语法错误** | 源代码还没开演 | 错误信息，程序**一步都没跑** |
| **运行时错误** | 演到一半出事 | 错误信息，**前面几行已经跑过了** |
| **逻辑错误** | 演完了才发觉不对 | **没有错误信息**，程序正常结束，结果却不对 |

上一课我们把虫子分成了三窝（不让开工的、半路掀桌子的、不吭声的）—— 今天我们就给它们挨个点名：这三种脾气在编程里各有各的正式名字，出现的时候各有各的样子，**错误信息也各有各的读法**。

往后你看到任何错误信息，第一步都先问自己：**它是哪一种？** 三种错误的解法完全不一样。

## 先认一份健康的源代码

在看错误信息之前，先看清**没有错误信息**的源代码是什么样。同一个任务 —— 我们今天先处理了 3 条数据、又处理了 4 条，把它算出来、拼成一句话输出 —— 四种语言的写法：

```compare
c::
#include <stdio.h>

int main() {
    printf("当前记录了 %d 条数据\n", 3 + 4);
    return 0;
}

cpp::
#include <iostream>

int main() {
    std::cout << "当前记录了 " << 3 + 4 << " 条数据" << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        System.out.println("当前记录了 " + (3 + 4) + " 条数据");
    }
}

python::
print("当前记录了", 3 + 4, "条数据")
```

```text
当前记录了 7 条数据
```

四段都跑得好好的，输出一模一样。接下来我们就在这几段源代码上做手脚 —— 你只管看，编译器或解释器会怎么说。

## 语法错误：编译器或解释器连源代码都没读完

我们把上面 C 那一段里 `printf` 后面的分号偷偷拿掉：

```c
#include <stdio.h>

int main() {
    printf("当前记录了 %d 条数据\n", 3 + 4)
    return 0;
}
```

编译器或解释器当场拦下来：

```text
main.c: In function 'main':
main.c:4:44: error: expected ';' before 'return'
```

就两行，但每一小段都有用。我们带你一格一格拆：

- **`main.c`** —— 出事的是哪一份源代码。你手上有好几个文件的时候，它先告诉你是哪个。
- **`4:44`** —— **第 4 行、第 44 列**。行，是从上往下数第几行；列，是它在这一行的哪个位置停下的。**行号才是你要翻过去看的那一个**，列只是帮你在那一行里对得更准。
- **`error:`** —— 这一条是**错误**。要是写成 `warning:`，那是「提醒」，不拦你，程序照样跑完 —— 两者别混。
- **`expected ';' before 'return'`** —— 这句要翻译一下：**它想要一个 `;`，撞上的是 `return`**。编译器或解释器说话永远是这个形状：先说「我想要什么」，再说「我看到了什么」。翻成人话就是：**`return` 前面那个位置，少一个分号。**
  - 它为什么不直说「第 4 行末尾少分号」？因为它是**撞到 `return` 才发现**前面那句话没收尾的。所以以后再看到 `expected X before Y`，你就自己翻：**X 该补在 Y 前面。**

这一种错误的性子最干脆：**程序一步都没跑。** 编译器或解释器是把整份源代码读一遍（或者念一句翻一句），一遇到读不通的地方就停下来 —— 你的代码一行都没来得及执行。所以：**屏幕上什么输出都没有、只有错误信息**，基本就是它。

### Python 那个：`SyntaxError`

Python 的编译器或解释器也一样，念到读不通的地方就不念了。我们这次的跟头是 `x = 1 +` —— 加号后面忘了写东西：

```text
x = 1 +
```

它甩回来这几行：

```text
  File "...\main.py", line 1
    x = 1 +
           ^
SyntaxError: invalid syntax
```

- **`File "...\main.py", line 1`** —— 前面那一长串是你这个文件在硬盘上的位置（每个人的都不一样，不用管它），**要紧的是末尾上那句 `line 1`：第 1 行。**
- **下面那行 `x = 1 +`** —— 它把你写的那一行**抄回给你看**，怕你找不到地方。
- **`^`** —— 一根小箭头，**指着它读不下去的那个字符**（这儿是在说：`+` 后面怎么就没啦？）。
- **`SyntaxError: invalid syntax`** —— `SyntaxError` 是这类错误的名字（syntax 就是「语法」），`invalid syntax` 是「这句不合法」。**以后看到 `SyntaxError`，你就知道：源代码写错了，一行都没跑。**

新手最爱撞的几种手滑，全都落在语法错误里：**少一个分号、冒号、括号或引号**，**`if` 后面忘了写冒号**，**把中文的 `：` 当成英文的 `:` 用了**。最后这一种最冤 —— 中文标点和英文标点长得像，编译器或解释器一个都不认。

（顺带交代一句：C++ 那个跟 C 是同门师兄弟，引用的话几乎一模一样；Java 那个开头也写 `error:`；Python 那个则用 `SyntaxError` 这个名字。词不一样，意思都是同一句：「这句我们读不通。」）

::: warn 注意
两件小事，知道了能少慌一半：

1. **编译器或解释器一次只说第一处。** 你把这一处改好、再跑一次，它可能又冒出下一处 —— 这不是你越改越糟，是它一次只能说一句话：读完一处就停下，后面的它还没读到。
2. **`warning:` 不是错误。** 提醒的意思是「我们觉得你这样写有点悬」，程序照样跑完、照样出结果。
:::

## 运行时错误：跑到半路才炸

第二种错误的脾气完全不同：**源代码它读得懂，程序真的开跑了 —— 跑到某一句才出事。**

我们用了一个还没建起来的名字（`fsih` 是手滑，我们想写的是第一行那个 `fish`）：

```text
fish = 3
print(fsih)
```

编译器或解释器跑完第一行，念到第二行时一头撞在墙上：

```text
Traceback (most recent call last):
  File "...\main.py", line 2, in <module>
    print(fsih)
          ^^^^
NameError: name 'fsih' is not defined
```

这几行比刚才长，但读法有口诀 —— **从最后一行往上读**：

- **最后一行才是答案。** `NameError` 是「名字错误」，后面那半句 `name 'fsih' is not defined` 翻过来是：**`fsih` 这个名字，我们不认识（not defined ＝ 没建起来）。** 引号里那个名字，正是**你自己写的那个** —— 回第一行看一眼躺着的 `fish = 3`，就知道手滑敲错了哪个字母。
- **`Traceback (most recent call last)`** 在第一行，意思是「顺着痕迹往回追」。它是**开头**，不是答案。新手最爱犯的错就是从这一行开始逐字读，读完一大片英文，其实答案一直等在最后一行。
- **`line 2`** —— 第 2 行。运行时的报错指得很准：`fish = 3`（第 1 行）好好地跑完了，出事的就是第 2 行。
- **那根箭头 `^^^^`** —— 指着它撞上的那个词。

它和语法错误最要紧的区别，藏在一个细节里：**它是跑到一半才断的气。** 编译器或解释器是开跑之后才撞墙的，所以在这之前，该打印的已经打印了、该记住的已经记住了 —— 错误信息往往不是屏幕上唯一的东西，它上面还压着前面几行正常的输出。

跑起来之后才出事的花样不少：**用了没建起来的名字**（名字打错、或者忘了先赋值）、**除以 0**、**从数组里报了一个根本不存在的编号**（`IndexError`）。C 那个更野一点：有些「跑起来才不对」的情况它连错误信息都不给，直接把一串乱七八糟的数返回 —— 那种「不报错、可就是不对」的事，就轮到第三种错误了。

## 逻辑错误：它一次不吭，可结果是错的

三种错误里最难的就是它：**程序跑完了、一个错误信息都没有、平平安安结束 —— 可返回的结果不对。**

为什么最难？因为**编译器或解释器看不出你有错**。它管的是「这句合不合法」，管不了「这是不是你想要的」—— 它读得懂文法，读不懂你的心思。代码在它眼里完美无缺，它凭什么提醒你？

看个最小的例子。我们想问：**第二个对象比第一个多记录了几条数据？**

```python
cat1 = 3
cat2 = 5
print(cat1 - cat2)
```

```text
-2
```

我们想要的是 `2`，屏幕上却站着一个 `-2`。程序跑得完完整整、没有一个字是红的 —— 它只是老老实实照着我们写的算：3 减 5 。**我们把减数和被减数写反了。**

改一个字就对了：

```python
cat1 = 3
cat2 = 5
print(cat2 - cat1)
```

```text
2
```

**这就是逻辑错误的标准长相：没有错误信息，只有「不对劲」。** 你唯一的线索是**结果**：对象比对象多几条，怎么会是个负数？

怎么抓它？编译器或解释器帮不上忙 —— 这种错误**只能你自己上**。好在上一课学的两招正好用在这儿：把中间的东西**打印出来看一眼**（「`cat1` 到底是几？」），或者拿计算机当听众、从头到尾把代码念一遍（念到 `cat1 - cat2` 那一步，多半你自己就「啊」出来了）。我们把调试那一课放在这一课前面，就是为了今天。

::: tip 提示
三种错误，三张脸，记住三句就够：

- **语法错误**：错误信息 + 程序一步都没跑 → 去补那个写错的符号。
- **运行时错误**：错误信息 + 前面几行已经跑过了 → 它指的是**某一行干的事**，去那一行找。
- **逻辑错误**：**没有错误信息** + 结果不对 → 只能靠调试，从「你想要什么」倒着找。
:::

## 怎么读报错：三步走

错误信息不是给你背的，是给你**当线索用**的。我们读报错只有三步：

**第一步：先看最后一行。** Python 的 Traceback，答案在最后一行；C 的 `error:` 那一行，也是整段里最要紧的。**别从头逐字读。**

**第二步：把行号挑出来。** `line 2` 也好、`4:44` 也好，编译器或解释器已经替你圈好了位置 —— **直接翻到那一行去看**。别再从第一行重读一遍代码，那是它干的活儿。看到 `expected X before Y` 这种话，记得往上翻一眼：东西常常该补在 Y 的**前一行末尾**。

**第三步：抓那个关键词。** `SyntaxError`、`NameError`、`expected ';'`、`not defined`、`invalid syntax` —— 这些都是**固定的词**，全世界写代码的人看到的是同一句。你不需要看懂整段英文，只要认出那一个词，抄下来去搜、去问，就能找到一模一样的答案。**还有一条最值钱：报错里那对引号夹着的，常常是你自己起的名字**（`'fsih'`）—— 它说的就是你手滑写出来的那个东西。

我们带读一遍就懂了。还是开头那条 C 的报错：

```text
main.c:4:44: error: expected ';' before 'return'
```

照着三步走：① 看最后一行、看到 `error:` —— 是**语法错误**，程序一步都没跑；② 挑出行号 `4:44` —— 第 4 行；③ 抓关键词 `expected ';' before 'return'` —— 它想要 `;`、撞上了 `return`。合起来一句话：**第 4 行末尾，少了一个分号。** 翻回上面看一眼，是不是那儿？

::: warn 注意
三条用得上、又最容易被忽略的：

1. **报错不是骂你，也不是念给电脑听的** —— 它是编译器或解释器写给你的便条。它说得越具体，越是省你的力气。
2. **一次只说一处**（再说一遍，因为新手十有八九会在这儿慌）：改好一处、再跑一次，看下一句。
3. **别把整段错误信息背下来** —— 认得出那个关键词、找得到那个行号，就够了。
:::

## 小任务

来，自己动手抓一条：

1. 打开练习场，把下面这段源代码照抄进去（**它本来就跑不起来，照抄就好**）：

```text
fish = 3
print(fsih)
```

2. 点运行，看那段错误信息，读三样东西：**它说第几行？** **`NameError` 后面引号里是哪个名字？** **第一行写的又是哪个名字？**
3. 把 `fsih` 改成 `fish`，再跑一遍 —— 错误信息没了，屏幕上是一个 `3`。
4. 最后再把 `print("字")` 的右括号删掉，跑一次。这一次屏幕上**除了错误信息什么都没有** —— 想一想：它和上一次为什么不是同一种错误？

「通用知识」打基础这一段到这儿就通关啦。后面还有一段工具链与工程化的路 —— 走完那一段，再挑一门顺眼的语言；我们在练习场里等你真刀真枪写代码 —— 从今往后，错误信息就是你的路标
