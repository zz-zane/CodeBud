## 学习目标

本课学习多态与动态分派。重点包括第一幕：老写法先看个够、第二幕：回来改同一句 switch、第三幕：把处理交给每个动物、同一输出方法处理、父类上写不出的那一个方法。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 第一幕：老写法，先看个够

先照老习惯写一版。两格数据装进盒子，处理那一个方法站在盒子**外面**，靠编号分流：

```c
#include <stdio.h>
#include <string.h>

typedef struct {
    char name[20];
    int type;                 /* 0 = 对象，1 = 鸟 */
} Animal;

void feed(Animal *a) {        /* 处理这一个方法，站在盒子外面 */
    switch (a->type) {
        case 0:
            printf("%s：处理数据\n", a->name);
            break;
        case 1:
            printf("%s：啄谷子\n", a->name);
            break;
    }
}

int main(void) {
    Animal cat;
    strcpy(cat.name, "张三");
    cat.type = 0;

    Animal bird;
    strcpy(bird.name, "小啾");
    bird.type = 1;

    feed(&cat);
    feed(&bird);
    return 0;
}
```

```text
张三：处理数据
小啾：啄谷子
```

能跑，跑得还挺好。拆开看，这一版有三样东西值得盯住：

1. **盒子里保存一个编号** `type`：说好 0 是对象、1 是鸟 —— 这份「对照表」不写在任何类定义上，只活在写代码的人脑子里；
2. **处理那一个方法站在盒子外面**：它得同时知道「对象处理什么、鸟处理什么」—— 园里有多少种住户，这一个方法就得背下多少套处理法；
3. **谁来处理，靠一句 `switch` 分流**：编号是几，就走哪一支。

丑话说在前面：**这一版一点都不丢人**。前面那些课我们全是这么写的，它也是 C 世界里最常见的写法 —— C 里没有「每个动物自己会一个方法」这台现成的机器，招只能站在外面，靠编号认人。

## 第二幕：新住户上门，回来改同一句 switch

园里来了条狗「大黄」，它啃骨头。我们抄起家伙什，数一数要动几处：

- 脑子里那份对照表得补一句「2 = 狗」—— **一处**；
- `feed` 里再添一支 `case 2:` —— **两处**；
- 最要命的是第三样：这句 `switch` 一改，**原来那两支也得跟着重测一遍** —— 对象还处理数据吗？鸟还啄谷子吗？我们动的是两行字，「心里要过的账」却是一整段。

**改一处，惊动全城。** 而且这不是一次性的疼：园里每添一位新住户，就再来一轮。养到三十只，这句 `switch` 长成半屏，我们每回动它都手抖。

等一下 ——「改一处惊动全城」这句，我们听着耳熟。上一课把两张类定义的公共部分往上提，治的也是「同一件事写在两处」的病：一处改了、另一处忘了跟上，两处就打架。可那回治的是**重复**；这回这句 `switch` 一点都不重复 —— 它错在**把所有住户的饭量都塞进了同一个脑袋**。新住户跟它八竿子打不着，可它一到，我们就得动这句老代码。

新东西来了，老东西不该被惊动。有没有办法？

## 第三幕：把「处理」交给每个动物自己

办法是把「处理」这件事**从外面搬回家**：谁处理，谁自己会。就两句主心骨：

1. **父类上写下一个方法** `eat` —— 先把「住户都有这招」这层约定立在类定义上；
2. **每张子类把它换成自己那一版**：对象那版印「处理数据」，鸟那版印「啄谷子」。这一手就是上一课见过的**盖掉、换自己那版**。

搬完家，外面那句 `feed` 不见了，只剩一句话：轮到谁，调用谁的 `eat()`。

**这一句话凭什么就「各处理各的」？** 因为它不是照着纸面念的。我们把名单摆出来说：

- 名单的每一格，都是一个**引用**，引用上印的画，是「动物」；
- 可引用对着的那台**电视机**，一个是对象、一个是鸟；
- 按同一个键 `eat()` 的那一瞬，**电视机自己放自己那一版** —— 挑哪一版，看它**对着谁**（也就是真身是谁），不看引用上印的字。

（这个比喻前几课就立下了，本课要背着用：**写着名字的那张纸是引用，不是电视机本身。**）

「子类创建后的，装进印着父类的格子」这件事，行话里叫**向上转型** —— 一支印着「动物」的引用，对着的可以是一个对象，因为对象本来就是动物。

这一手，术语表里叫**多态（多态调用）**：同一句输出，各对象各样 —— 本课这声输出更实在：各处理各的。我们在《两条路》那课墙上钉过一张路线图 —— 上面这一站早就钉好了，就叫**一次处理各处理各的**，今天兑现。

「挑哪一版，跑起来那一瞬才定」这件事，行话里叫**动态绑定**。我们把两个时刻摆开看：

- **写代码那一关**：编译器或解释器只看得见引用上印的字 —— 它只查一件事：「动物这张类定义上有没有 `eat` 这招？」有，这行就放行；至于跑的是哪一版，这一关**根本不管**；
- **跑起来那一瞬**：电视机的真身是谁，就放哪一版。

于是那句让我们卡了半天的话 —— `Animal a = new Cat(); a.eat();` 凭什么出对象那一版 —— 谜底就在这一行里：**左边写的是引用的型号，右边 new 出来的是电视机的真身。** 按下去，看真身。

## 四位编译器或解释器，同一输出方法处理

同一件事：调用一次处理，让对象和鸟各处理各的。

```compare
c::
#include <stdio.h>
#include <string.h>

typedef struct {
    char name[20];
    int type;                 /* 0 = 对象，1 = 鸟 */
} Animal;

void feed(Animal *a) {        /* 招站在外面，靠编号分流 */
    switch (a->type) {
        case 0:
            printf("%s：处理数据\n", a->name);
            break;
        case 1:
            printf("%s：啄谷子\n", a->name);
            break;
    }
}

int main(void) {
    Animal cat;
    strcpy(cat.name, "张三");
    cat.type = 0;

    Animal bird;
    strcpy(bird.name, "小啾");
    bird.type = 1;

    feed(&cat);
    feed(&bird);

}

cpp::
#include <iostream>
#include <string>
using namespace std;

class Animal {
protected:
    string name;
public:
    Animal(string n) : name(n) {}
    virtual void eat() {          // virtual：子类那一版才盖得上
        cout << name << "：……" << endl;
    }
};

class Cat : public Animal {
public:
    Cat(string n) : Animal(n) {}
    void eat() {                  // 重写：对象自己那一版
        cout << name << "：处理数据" << endl;
    }
};

class Bird : public Animal {
public:
    Bird(string n) : Animal(n) {}
    void eat() {                  // 重写：鸟自己那一版
        cout << name << "：啄谷子" << endl;
    }
};

int main() {
    Cat cat("张三");
    Bird bird("小啾");
    Animal *pets[2] = { &cat, &bird };   // 印着「动物」的引用，对着两个真身
    for (int i = 0; i < 2; i++) {
        pets[i]->eat();                  // 一行字，各答各的
    }
    return 0;
}

java::
class Animal {
    protected String name;

    Animal(String name) {
        this.name = name;
    }

    void eat() {
        System.out.println(name + "：……");
    }
}

class Cat extends Animal {
    Cat(String name) {
        super(name);
    }

    @Override
    void eat() {
        System.out.println(name + "：处理数据");
    }
}

class Bird extends Animal {
    Bird(String name) {
        super(name);
    }

    @Override
    void eat() {
        System.out.println(name + "：啄谷子");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal[] pets = { new Cat("张三"), new Bird("小啾") };
        for (Animal pet : pets) {
            pet.eat();
        }
    }
}

python::
class Animal:
    def __init__(self, name):
        self.name = name

    def eat(self):
        print(f"{self.name}：……")

class Cat(Animal):
    def eat(self):
        print(f"{self.name}：处理数据")

class Bird(Animal):
    def eat(self):
        print(f"{self.name}：啄谷子")

pets = [Cat("张三"), Bird("小啾")]
for pet in pets:
    pet.eat()
```

```text
张三：处理数据
小啾：啄谷子
```

看出来了吗：**四段都在完成「调用一次、各处理各的」，可只有后三位不用回来改老代码。**

- **C**：还是第一幕那一版 —— 招站在外面，靠 `type` 分流。想添住户，就得回来改这句 `switch`。C 里没有「父类挂一个方法、子类自己写一版」这台现成的机器，想这么干得自己动手搭；
- **C++**：父类那一个方法前面挂上 `virtual`，子类那版才盖得住。**记住这个词：忘写，它就退回「照引用上印的字念」的老脾气，而且不报错** —— 详见下面的「注意」；
- **Java**：`@Override` 是给编译器或解释器看的记号：它帮我们盯着「名字有没有抄对、括号里那几样有没有抄歪」，抄错了当场拦下；不写也能跑，但写下它就是给自己请了个校对员；
- **Python**：直接写一个同名的 `def eat` 盖上，没有 `virtual` 这种开关 —— 调用 `pet.eat()` 能不能应、应哪一版，全看它自己。

四位编译器或解释器的共识一句话：**老世界把「各处理哪一口」收在一句 `switch` 里；新世界把它交还给每个动物自己。**

## 父类上写不出的那一个方法

刚才父类上那版 `eat`，印的是「……」。我们盯着它看了一会儿，越看越别扭：**「动物处理」这个动作，父类自己真会做吗？** 对象处理数据、鸟啄谷子 —— 一个「普普通通的动物」，该怎么处理？写不出来。

写不出来，就别硬装。干脆只留一张标签：父类那一个方法只写名字、不写身体。挂着这种标签的类定义，行话里叫**抽象类（写不出动作的类定义）**。

- **Java** 把标签写成 `abstract`，类定义名和招名上各挂一个：`abstract class Animal { abstract void eat(); }`（函数后面连花括号都省了）。这样的类定义**不能直接拿来生** —— `new Animal()` 会被编译器或解释器拦下：世上没有「纯粹的动物」这一个；
- **C++** 的写法是给那一个方法挂上 `virtual`、再补一句 `= 0`：`virtual void eat() = 0;`，同样生不出本体；
- **Python** 不管这道关：父类上那一个方法你不写内容（写个 `pass` 占位），它也不拦你创建对象 —— 想把「必须自己实现」立成规矩，得额外请一个工具（`abc`），往后学到那儿再细说。

再往上走一步：有时我们要的不是一个类定义，而是一份**约定** —— 不管你是对象、是鸟、还是机器人，只要「会打招呼」就能签。这份约定，术语表里叫**接口（接口约定）**。这两种写法要回答的问题不同，本课先记最要紧的一句对照：

- **`extends` 回答「你是**什么**」** —— 对象是动物，讲亲缘，白捡父类的设定；
- **`implements` 回答「你会**做**什么」** —— 会打招呼的都算数，讲的是一份行为契约，跟亲缘毫无关系。

::: tip 提示
今天记住三句话：

1. **一句话，各答各的**：调用处只留 `pet.eat()` —— 写的时候不用管手里是谁，跑起来那一瞬，由它**对着的那台电视机**（真身）决定应哪一版。这一手叫**多态（多态调用）**；
2. **`extends` 是「你是什么」，`implements` 是「你会做什么」**：前者讲亲缘（对象是动物），后者讲契约（会打招呼的都算数）；
3. **判据句**：新住户进门，老代码动没动？—— **一个字都不用改**，才算把这声处理请出去了。
:::

::: warn 注意
两个坑，我们提前标出来：

- **C++ 忘写 `virtual` = 安静地退回老脾气**：父类那一个方法不挂 `virtual`，`Animal* p = &cat; p->eat();` 就会跳出**父类兜底那版** —— 不报错、不崩溃，行话里叫静态绑定。这个坑的脾气是：错了不调用疼，只有盯着结果才能发现。解法就一个词，写上；
- **重写 ≠ 重载**：中文名长得像，机制是两码事。**重写（override）**是「子类把父类那一个方法换成自己一版」（名字、括号里那几样都一样）；**重载（overload）**是「同一个名字配好几副括号」，跟继承毫无关系 —— 往后学语言线会专门讲它。今天先立块界碑：**看它换掉的是不是父类上的那一个方法**。
:::

## 一句话对照表

| 我们写的 | 它的意思 |
| --- | --- |
| `void feed(Animal *a)` 里那句 `switch (a->type)` | 老世界：招站在外面按编号分流，添住户就得回来改它 |
| `virtual void eat();` | C++：父类那招挂上开关，子类那版才盖得住（忘写就退回兜底版） |
| `@Override` | Java：给编译器或解释器的记号，名字、括号抄歪了当场拦下 |
| `class Cat(Animal):` / `extends` / `: public` | 子类照着父类来，白捡全部设定 |
| 子类里再写一遍 `def eat(self):` | **盖掉、换自己那版**：把父类那一个方法换成自己一版 |
| `abstract class Animal` / `= 0` | 父类写不出动作的那一个方法：只留标签，类定义不能直接生 |
| `implements ...` | 签一份行为契约：你会做什么，跟亲缘无关 |
| `Animal a = new Cat(); a.eat();` | 引用印着「动物」，真身是对象 —— 按下去，对象应声 |
| `for pet in pets: pet.eat()` | 一行字走名单：轮到谁，谁自己那版应声 |
