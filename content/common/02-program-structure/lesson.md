## 学习目标

本课学习程序的基本结构。重点包括程序=指令序列、入口、语句、注释。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

程序就是一份写给电脑的指令清单。先看一份写给人的清单，比如泡一杯茶：

```text
1. 烧一壶开水
2. 把茶叶放进杯子
3. 把开水倒进杯子
4. 等三分钟再喝
```

## 第一块：指令得**排好队**

电脑读程序，是从上往下**一条都不跳**地读。所以指令排队的顺序，就是事情发生的顺序。

```python
print("拿起数据")
print("走到数组元素旁边")
print("把数据放进元素里")
print("处理完成！")
```

```text
拿起数据
走到数组元素旁边
把数据放进元素里
处理完成！
```

把第二行和第三行调个个儿，程序照样跑得起来——只是变成「人还没到元素边，数据就先飞过去了」。**电脑不会替你检查顺序合不合理，它只会照着做。**

这四条指令到底是怎么一条接一条走完的？我们把它拆成一步一步，走给你看：

```demo
title: 四条指令是怎么一条接一条走完的
code:
| print("拿起数据")
| print("走到数组元素旁边")
| print("把数据放进元素里")
| print("处理完成！")

step 开场：电脑站到第 1 条上，一条都还没做
at: 1
say: 电脑从上往下读，先站到第 1 条上。此刻屏幕上**一个字的影子都没有** —— 四条指令一条都还没做。
meow: 准备好了，从第 1 条开始。
pose: expect
电脑正读到 = 第 1 条（还没做）
清单上还没做 = 4 条
标准输出 = （还没印）

step 第 1 步
at: 1
say: 第 1 条执行完，屏幕上冒出「拿起数据」。**做完了才轮到第 2 条** —— 中间不跳步，也没有哪一条能抢到前面去。
meow: 第 1 条做完，接着往下。
pose: yay
电脑正读到 = 第 1 条（做完了）
清单上还没做 = 3 条
标准输出 = 拿起数据

step 顺着往下：第 2 条
at: 2
say: 电脑往下一格读第 2 条，屏幕上接着添第二行 —— 它添在**第一行的下面**。这就是「排好队」的样子：新的一行永远接在末尾。
meow: 第 2 行紧跟在第 1 行后面。
pose: busy
电脑正读到 = 第 2 条（做完了）
清单上还没做 = 2 条
标准输出 = 拿起数据 / 走到数组元素旁边

step 第 3 步
at: 3
say: 第 3 条做完，屏幕第三行。**这四行字和四条指令是一一对应的** —— 代码里谁排在前面，屏幕上谁就先出现。
meow: 一条指令对应一行输出。
pose: busy
电脑正读到 = 第 3 条（做完了）
清单上还没做 = 1 条
标准输出 = 拿起数据 / 走到数组元素旁边 / 把数据放进元素里

step 第 4 步
at: 4
say: 最后一条做完，屏幕上第四行「处理完成！」。到这儿四条指令一条不剩，屏幕上正好四行。
meow: 最后一条也做完了。
pose: yay
电脑正读到 = 第 4 条（做完了）
清单上还没做 = 0 条
标准输出 = 拿起数据 / 走到数组元素旁边 / 把数据放进元素里 / 处理完成！

step 收工：清单读到头了
at: 4
say: 清单读完，电脑收工。从头到尾**一条都没跳、一条都没重** —— 这就是课文里那四份代码跑出来一模一样的道理：门和分号各家不同，往下走的规矩是同一套。
meow: 四条全部执行，没有跳过。
pose: proud
电脑正读到 = （清单读完了，收工）
清单上还没做 = 0 条
标准输出 = 拿起数据 / 走到数组元素旁边 / 把数据放进元素里 / 处理完成！
```

**电脑的读法就这一条**：一条做完了才轮到下一条，中间不跳、不抢，也不回头。所以那四行代码换了顺序，屏幕上那四行字也跟着换顺序 —— 「指令排队的顺序，就是事情发生的顺序」，说的就是这件事。

## 第二块：总得有个门——**入口**

工作区不能没有门，程序也一样：得有一个明确的**入口**。电脑从这扇门进去，然后一条条往下做，做完就收工。

四门语言里，这扇门长得不太一样：

```text
C / C++    int main() { ... }                          门叫 main
Java       public static void main(String[] args) { ... }   门也叫 main，但裹得厚些
Python     从文件第一行开始跑，不用写门
```

Python 是个特例：它没有那扇明晃晃的门，**第一行就是入口**。别的语言都得先找到门，才肯开工——门写错了，编译器或解释器会直接说「找不到入口」，一行都不给你跑。

## 第三块：一条指令 = 一句**话**

清单里的每一条，写进代码就叫一条「语句」。语句和中文的句子一样，得有东西收尾：

- **C / C++ / Java**：每条语句结尾要写一个分号 `;`
- **Python**：每条语句独占一行，靠**换行**收尾

少写一个分号，编译器或解释器会当场拦下来，指着那一行告诉你「这里少了个东西」。这是新手最常见的第一个报错，撞上了不用慌。

## 第四块：写给对象看的便条——**注释**

有些话你并不想让电脑做，只是想写给自己看：这块是干嘛的、当时为什么这么写。那就写成**注释**。电脑读到注释**直接跳过**，当它不存在：

```python
# 这一行是注释，电脑看都不看
print("只有这行会被执行")   # 行尾也能挂一句注释
```

```text
只有这行会被执行
```

注释不干活，但它是最省事的备忘方式。三个月后你回来翻这段代码，全靠它救命

## 四种语言，同一个工作区

同一个「打印三行处理数据流程」的小程序，四种语言写出来长这样。这回留意两件事：**门在哪儿**、**每条语句怎么收尾**

```compare
c::
#include <stdio.h>

int main() {
    printf("拿起数据\n");
    printf("放进元素里\n");
    printf("处理完成！\n");
    return 0;
}

cpp::
#include <iostream>

int main() {
    std::cout << "拿起数据" << std::endl;
    std::cout << "放进元素里" << std::endl;
    std::cout << "处理完成！" << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        System.out.println("拿起数据");
        System.out.println("放进元素里");
        System.out.println("处理完成！");
    }
}

python::
print("拿起数据")
print("放进元素里")
print("处理完成！")
```

```text
拿起数据
放进元素里
处理完成！
```

四份代码长得差挺多，可干的是同一件事，打印出来的字**一模一样**。差别全在刚才那两块上：C 要写 `int main()` 才有门、Java 的门裹了三层、Python 连门都省了；至于收尾，C/C++/Java 条条带分号，Python 全靠换行。

::: tip 提示
今天记住四块就够：**指令要排队**、**程序要有入口**、**语句要有收尾**、**注释是写给对象看的**。四门语言的门和收尾写得不一样，但那四块骨头是一样的
:::

::: warn 注意
别急着背 `main` 外面那一圈括号和关键字！现在只要认得「**这行是门**」就够了。写多少遍自然会记住，死记硬背反而容易吓着自己。
:::
