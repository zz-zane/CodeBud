## 学习目标

本课学习算法操作次数与效率。重点包括别掐秒表：数动作次数、1024 只元素：523776 次 vs 10240 次、元素翻倍，次数涨几倍、小数据上看不出差别。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 为什么不掐秒表

掐秒表有个要命的毛病：**同一段活儿，在快的机器上跑得短、在慢的机器上跑得长——可它要做的动作，一次都没少。**

今天清理官在后台下东西，我们这台机器卡得像在泥里走；明天他出差了，机器快得飞起。两次掐表能差出十倍，于是得出「同一件事，今天比明天难十倍」这种傻结论。

所以我们不数时间，数**动作次数**：这件事一共要比多少次、要看多少只元素、要挪多少下。**这个数只跟「元素有多少只」有关，跟机器快慢没关系**——它才是衡量「这干法省不省力」的那把尺子。

## 两个对象的干法，各要动手多少次

**学生甲的干法：每两个都比一次。**

1024 只元素，每个都得跟其余 1023 只各比一次。可这么数会把每一对算两遍（甲跟乙比、乙跟甲比，是同一件事），所以要除以 2：

> 1024 × 1023 ÷ 2 = **523776** 次

**学生乙的干法：每次都把范围砍一半。**

1024 只元素先分成两半，各自排好再合起来；每一半再分成两半……一层一层砍下去，1024 → 512 → 256 → … → 2 → 1，**一共只砍 10 层**（2 连乘 10 次正好是 1024）。每个元素最多经历 10 层：

> 1024 × 10 = **10240** 次

523776 和 10240，差了 **50 多倍**。两个对象都能干完，可一个干的活是另一个的五十来倍——这就是「省力」两个字的真意思。

不信我们？让机器自己算一遍（数字是机器算的，不是我们拍脑袋）：

```python
n = 1024
print(n * (n - 1) // 2)
print(n * 10)
```

```text
523776
10240
```

## 元素再多一倍，会怎样

这才是最要命的一问：如果元素从 1024 只变成 2048 只——

```python
for n in [1024, 2048]:
    pairs = n * (n - 1) // 2
    print(f"{n} 只元素：笨办法要比 {pairs} 次")
```

```text
1024 只元素：笨办法要比 523776 次
2048 只元素：笨办法要比 2096128 次
```

元素只翻了一倍，笨办法的动作却从 523776 涨到 2096128——**变成 4 倍**。因为每个元素都要跟「也翻了倍」的所有元素比一遍：元素的数量翻倍，两两配对的数目就翻两番。

学生乙那边呢？元素翻倍，它只多砍一层：

```python
for total in [1024, 2048]:
    n = total
    layers = 0
    while n > 1:
        n = n // 2
        layers = layers + 1
    print(f"{total} 只元素：砍 {layers} 层，动手 {total * layers} 次")
```

```text
1024 只元素：砍 10 层，动手 10240 次
2048 只元素：砍 11 层，动手 22528 次
```

10240 涨到 22528，只涨了 2 倍多一点。**元素越堆越多，两套干法的差距就越拉越开**——这就是为什么我们说：数次数，还要再看一眼「元素翻倍时它会涨成几倍」。

## 四位编译器或解释器，同一笔账

同一个算式「4 只元素要比多少次」，四位编译器或解释器算出来的是同一笔账：

```compare
c::
#include <stdio.h>

int main() {
    int n = 4;
    printf("%d 只元素要比 %d 次\n", n, n * (n - 1) / 2);
    return 0;
}

cpp::
#include <iostream>

int main() {
    int n = 4;
    std::cout << n << " 只元素要比 " << n * (n - 1) / 2 << " 次" << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        int n = 4;
        System.out.println(n + " 只元素要比 " + n * (n - 1) / 2 + " 次");
    }
}

python::
n = 4
print(f"{n} 只元素要比 {n * (n - 1) // 2} 次")
```

```text
4 只元素要比 6 次
```

四段输出的**同一句话**。语言换了，算式没换；算式没换，次数就不会变。

::: tip 提示
拿到两套干法，别急着问「哪个快」，先问两句话：

1. **各要动手多少次？** —— 数元素数、数比较、数挪动，数出一个跟机器无关的数。
2. **元素多一倍时，这个次数会涨成几倍？** —— 这一问才真正分出高下。
:::

::: warn 注意
「47 毫秒」和「3 秒」这种数，换个机器、换个时辰就会变，**别拿它当判据**。次数不会变，时间会变。

还有一个更隐蔽的坑：**小数据上看不出差别**。4 只元素，笨办法 6 次，巧办法也才十来次——元素少的时候，谁都快。想看出一套干法的成色，得把元素堆起来再看。
:::
