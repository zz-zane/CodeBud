## 学习目标

本课学习伪代码与流程图。重点包括唠嗑版：自然语言、算法步骤版：伪代码、路线图版：流程图、三种说法怎么挑。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 说法一：唠嗑版

最省事的一套，就是我们刚才那样**唠嗑**。这套说法的学名叫**自然语言**——对象和对象平时说话用的那套字。

唠嗑版的好处写在脸上：**快**。我们调用输出方法，学生甲立刻动身，不用先听我们念一张单子。

可它有两个洞：

- **会漏**：我们没说水温，学生甲就可能倒一瓢凉水。
- **会歪**：我们说「搅一搅」，学生甲搅了一圈——而我们心里的「一搅」是十圈。

一句话：唠嗑版**说给人听够用，照着一步步做就不够**。听的人一边干一边猜，猜岔了就得返工。

## 说法二：算法步骤版

要照着做，就得换一套说法：把这件事写成**算法步骤**。它的学名叫**伪代码（伪代码）**——「伪」就是「假」：它长得像代码，却**不是**哪门语言的真代码，电脑一个字都读不懂，**它是写给别的对象看的**。

我们把泡商品写成算法步骤，差不多是这样：

```text
泡一元素商品：
    拿一个空元素
    倒进一元素温水
    撒进两把商品
    搅三圈
    等三分钟
    如果商品还硬：
        再等一分钟
    端给我们
```

这张算法步骤比唠嗑版强在哪儿：

- **一行一件事**：每行只写一个动作，不把两件事塞进同一行。
- **不挑语言**：不用管哪门语言要分号、哪门要点号，算法步骤只顾把事说清楚。
- **谁照着做都一样**：「搅三圈」就是三圈，「等三分钟」就是三分钟——猜不出第二种意思。

它是**对象和对象之间**的写法：我们写得出来，学生甲照着做得了，换个对象来照样做对。

## 说法三：路线图版

算法步骤是竖着一行行念下来的。可这件事里藏着一个「拐弯」：**如果商品还硬，就得再等一分钟**——等完还得回头看一眼还硬不硬。竖着念到这儿，容易念晕。

拐弯多的活儿，就得请出第三套说法：**路线图**。它的学名叫**流程图（流程图）**——把每一步画成一个框，框和框之间拉箭头，箭头指哪儿就往哪儿走：

```text
[ 拿一个空元素   ]
       ↓
[ 倒进一元素温水 ]
       ↓
[ 撒进两把商品 ]
       ↓
[ 搅三圈       ]
       ↓
[ 等三分钟     ]  ←────────────────┐
       ↓                            │
< 商品还硬吗？ >                    │
       ↓                            │
       ├── 是 ─> [ 再等一分钟   ] ┘
       ↓
       └── 否 ─> [ 端给我们     ]
```

（画得潦草，看懂意思就行。）

路线图最会画两件事：

- **分岔**：`< 商品还硬吗？ >` 这个框是个岔路口，先看一眼情况，再挑一条路走——是就再等一分钟，否就往下去端元素。
- **绕回头**：右边那条线，把「再等一分钟」送回「等三分钟」重新排一次队——**只要还硬，就一圈一圈绕下去**。这一手，正是上一课讲过的**循环**。

## 三种说法，说的是同一件事

把三套说法摆在一起看：

| 说法 | 学名 | 最擅长 | 什么时候挑它 |
|---|---|---|---|
| 唠嗑版 | 自然语言 | 快，随口就来 | 说给听得懂的对象听，不要求他一步不差 |
| 算法步骤版 | 伪代码 | 一行一件事，谁做都一样 | 要别人照着做，还要做得一模一样 |
| 路线图版 | 流程图 | 分岔、绕回头一眼看得见 | 这件事拐弯多、还要绕回去 |

三套说的是**同一件事**——泡一元素商品。挑哪一套，只看你要说给谁听、这件事拐不拐弯。

## 算法步骤落到代码上

算法步骤再清楚，电脑也读不懂它——电脑只认真正某门语言的代码。所以最后一步是：**照着自己写好的算法步骤，把它翻译成代码**。

算法步骤上那行「搅三圈」，换成 Python 就是这样，跑出来是四行字：

```python
bowl = "温水 + 商品"
for i in range(3):
    print(f"搅第 {i + 1} 圈：{bowl}")
print("端给我们")
```

```text
搅第 1 圈：温水 + 商品
搅第 2 圈：温水 + 商品
搅第 3 圈：温水 + 商品
端给我们
```

对着看就明白了：算法步骤的「搅三圈」是 `range(3)` 管的那三圈；算法步骤的「端给我们」是最后那一句。**代码看着吓人，其实只是把算法步骤一行一行念给编译器或解释器听。**

## 四位编译器或解释器，同一张算法步骤

同一张算法步骤，四位编译器或解释器输出的腔调各不相同，可做的事一模一样：

```compare
c::
#include <stdio.h>

int main() {
    char bowl[] = "温水 + 商品";
    for (int i = 0; i < 3; i++) {
        printf("搅第 %d 圈：%s\n", i + 1, bowl);
    }
    printf("端给我们\n");
    return 0;
}

cpp::
#include <iostream>
#include <string>

int main() {
    std::string bowl = "温水 + 商品";
    for (int i = 0; i < 3; i++) {
        std::cout << "搅第 " << i + 1 << " 圈：" << bowl << std::endl;
    }
    std::cout << "端给我们" << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        String bowl = "温水 + 商品";
        for (int i = 0; i < 3; i++) {
            System.out.println("搅第 " + (i + 1) + " 圈：" + bowl);
        }
        System.out.println("端给我们");
    }
}

python::
bowl = "温水 + 商品"
for i in range(3):
    print(f"搅第 {i + 1} 圈：{bowl}")
print("端给我们")
```

```text
搅第 1 圈：温水 + 商品
搅第 2 圈：温水 + 商品
搅第 3 圈：温水 + 商品
端给我们
```

四段输出的是**同样四行**。C 和 Java 写 `i + 1`，C++ 把它夹在箭头里拼，Python 干脆把算式塞进句子里——四种写法，同一张算法步骤。

::: tip 提示
拿到一件事，先问自己两句话：**这件事要拐弯吗？** 拐弯多就画成路线图，不拐弯就写成算法步骤。

给别的对象看的东西，**别停在唠嗑版**：「搅一搅」「等一会儿」「差不多就行」——这种话谁念谁猜。写成「搅三圈」「等三分钟」，才叫把话说死。
:::

::: warn 注意
算法步骤**不是代码**：它长得像代码，可你把它粘进练习场，编译器或解释器一个字都读不懂，会当场翻脸。它的用处是**先想清楚再动手**——算法步骤在脑子里跑通了，再照着它的意思写成真代码。

另一个坑是写得太细：算法步骤写到「拿元素」就够用了，写到「伸出左前字段、字段尖对准元素沿」就是白费力气。**细到别人不会做错就停手**，多一个字都是浪费。
:::

今天的小任务，第一件不用碰键盘也能做：

1. 挑一件家常事（比如「煮一包方便面」），先写**唠嗑版**，再把它改写成**算法步骤版**。改的时候数一数：唠嗑版里有多少个词是「别人只能猜」的？
