## 学习目标

本课学习结构体、函数与对象。重点包括类定义是真进步、函数住在类定义外面、交换生来了：数改动点、四位编译器或解释器站在哪儿。请结合示例观察程序状态、执行顺序和结果，并通过练习检查理解。

## 一、先定义类：这一步是真进步

我们摊开纸，画一张学员类定义，再把名册摆出来：

```c
typedef struct {
    char name[20];
    int score;
} Student;

Student list[100];
int count = 0;
```

一句话读完：**一个学员，有一格名字、一格分数**。拆开看：

- **开头那个 `typedef`** —— 给这张类定义登记一个学名。登记完，写 `Student` 就是指「照这张类定义的那一整样东西」，去哪都不用再带着 `struct` 那几个字母。
- **`char name[20];`** —— 名字那一格是一排字符元素（就是字符串的家），最多住得下 20 个；
- **`int score;`** —— 分数是一格普通的整数元素。

从前记三十个学员，我们得摆六十只变量：`p1name`、`p1score`、`p2name`……现在**一条记录就是一样东西**，还能整只搬（这一手，往后 C 线「类定义」那一课里会正式讲：整只可以整个搬）。这是真进步，我们一点不否认。

类定义下面那两行就是名册本身：

`list` 是一排 100 格的位置，`count` 记着现在保存了几个人。这两样站在所有函数都看得见的地方，谁都够得着。

## 二、函数住在类定义外面

接下来把要干的活写成函数。第一个方法：**收一个新学员**。

```c
void add_student(char name[], int score) {
    strcpy(list[count].name, name);
    list[count].score = score;
    count = count + 1;
}
```

读法三行：

- **`strcpy(list[count].name, name);`** —— 把名字一颗一颗搬进名册里下一个空位（`count` 正好指着那个空位）。名字是一排字符元素，不能整个换，得请档案管理员 `strcpy` 下手（这一手往后 C 线「类定义」那一课里也会正式讲）。
- **`list[count].score = score;`** —— 分数是普通整数元素，直接写。
- **`count = count + 1;`** —— 装好一个人，人数自己长一，下一位才排得上号。

第二招：**按名字找人**。

```c
int find_by_name(char name[]) {
    for (int i = 0; i < count; i++) {
        if (strcmp(list[i].name, name) == 0) {
            return i;
        }
    }
    return -1;
}
```

一排挨个比，比到了就把位置返回；一圈走完都没有，返回 `-1`（「没这个人」）。

第三个方法：**把名册印出来**。

```c
void print_all(void) {
    for (int i = 0; i < count; i++) {
        printf("%s %d\n", list[i].name, list[i].score);
    }
}
```

三个方法都写完了，都能用。**现在请你看一眼它们的站位**：这三个方法，一个都不在类定义的花括号里，全在类定义外面另起一段。它们干活时动的是谁？动的是全局那一排 `list`，还有那个 `count` —— 伸手去够。

也就是说：**类定义管「长什么样子」，函数管「干什么」，两样东西各站各的，中间没有一根线连着。** 它们能凑到一起干活，全靠我们记性好：记得名册摆在哪儿、记得每一个方法该喂什么。

再看一眼函数收东西的样子，这里有个很容易忘的坑：

```c
Student add_points(Student s, int n) {
    s.score = s.score + n;
    return s;
}
```

称呼它的时候得这么调用：

```c
a = add_points(a, 5);
```

函数收下的，是**整只抄的一份**（这一手往后 C 线「类定义」那一课里会正式讲：整只可以整个搬）。函数在抄件上加完分，得有人把改进过的那份**返回、重新赋给原处** —— 那个 `a =` 就是干这个的。忘了返回，名册上的数字纹丝不动：**数据不是函数的，函数只是中间那个搬货的。**

我们做那台数值计算器的时候，加减乘除也是这么散着站的 —— 那会儿没有数据要管，散着站一点不碍事。这回名册和函数得天天打照面，账就不一样了。

## 三、让改需求说话：来了几个交换生

名册用了一阵子，新需求来了：学堂要来几个**交换生**。交换生也是学员，只是——

1. 他们的记录要多记一样：**来自哪个学堂**；
2. 印名册的时候，交换生的名字后面**要多印一行小字**。

我们不打折扣，把要动的地方从头数一遍：

1. **类定义要加一格** —— 比如加一行 `char from[20];`，多出来的那样东西才有地方住。
2. **入住那一个方法要改** —— `add_student` 现在只收名字和分数，得把「从哪儿来」也收进来，再写进新格。
3. **印名册那一个方法要改** —— `print_all` 得先分辨：这一行是普通学员还是交换生；是交换生，就多印一行。

**三处。** 而且第三处会一直长下去：它本来只是印字的一句活，从今往后**里面长出一条岔路**。下次再来一种「旁听生」，还得回这儿再岔一次 —— 每多一种学员，这一个方法就胖一圈。

比「三处」更值得记住的，是**为什么得挨个找**：类定义和函数站在两边，谁也不知道对方改了没有。名册改一下，我们得凭记性把所有碰过它的函数都翻出来改；漏掉一处，一点红都不给你报 —— 名册就安安静静少印一行字。

这笔账我们先记着，往后有一课专门带你去收拾它。

## 四、四位编译器或解释器：函数都站在哪儿

同一件事，四位编译器或解释器各写一遍：**一个学员，名字和分数，加一次分，印出来**。

```compare
c::
#include <stdio.h>
#include <string.h>

typedef struct {
    char name[20];
    int score;
} Student;

Student add_points(Student s, int n) {
    s.score = s.score + n;
    return s;
}

void report(Student s) {
    printf("%s：%d 分\n", s.name, s.score);
}

int main(void) {
    Student a;
    strcpy(a.name, "张三");
    a.score = 60;
    a = add_points(a, 5);
    report(a);
    return 0;
}

cpp::
#include <iostream>
#include <string>
using namespace std;

class Student {
public:
    string name;
    int score;

    void add_points(int n) {
        score = score + n;
    }

    void report() {
        cout << name << "：" << score << " 分" << endl;
    }
};

int main() {
    Student a;
    a.name = "张三";
    a.score = 60;
    a.add_points(5);
    a.report();
    return 0;
}

java::
public class Main {
    static class Student {
        String name;
        int score;

        void addPoints(int n) {
            score = score + n;
        }

        void report() {
            System.out.println(name + "：" + score + " 分");
        }
    }

    public static void main(String[] args) {
        Student a = new Student();
        a.name = "张三";
        a.score = 60;
        a.addPoints(5);
        a.report();
    }
}

python::
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def add_points(self, n):
        self.score = self.score + n

    def report(self):
        print(f"{self.name}：{self.score} 分")

a = Student("张三", 60)
a.add_points(5)
a.report()
```

```text
张三：65 分
```

看出来了吗：四段干的是同一件事，**差别全在函数站在哪儿**：

- **C**：类定义里只有格子，函数站在外面；函数收东西收的是整只抄件，改完还得返回装好 —— 我们就是那个搬运工。
- **C++**：函数画进了类定义的大括号里，身子里写的 `score`，指的就是**这一个自己**那一格，谁都不用搬。
- **Java**：也是函数画在类定义里；调用函数之前，得先 `new` 出一个来。
- **Python**：一样画在类定义里，`self` 就是「这一个自己」。

**先别急着下结论。** 把函数搬进类定义，只是让「长什么样」和「会什么」住到了同一张纸上 —— **这算不算把差的那半补齐了，还得过我们在「两条路」那一课立下的判据句**：**封装＝藏数据、露行为**。下一课我们并排摆两版给你看的时候，咱俩拿它一条一条对。

::: tip 提示
今天的账，三句话：

1. **C 的类定义只画格子** —— `struct` 里摆的全是数据，函数一个都进不去，只能站在外面。
2. **函数站在外面，就得有人搬货** —— 每次出手都要把学员、名册传入，改完了还得把结果返回装好；两边之间没有一根线连着，全靠我们记性好。
3. **改需求最能说明问题** —— 加一样「来自」，就得挨个把碰过学员数据的函数翻出来改。这就是那半张类定义欠下的账。

术语表里，给「藏起数据、只露出口子」这一手起的名字叫**封装**；量它够不够格的判据句，就是「两条路」那一课立下的那句：**封装＝藏数据、露行为**。往后每往前一步，我们都拿它量一量。
:::

::: warn 注意
三个坑，标给你：

- **类定义加了新格，别的函数不会自己知道。** 谁碰过这张类定义，谁就得自己回去看一眼 —— 漏掉的那处不会报错，只会安安静静印错一行。
- **「函数收下的是整只抄的一份」这条别忘了。** `a = add_points(a, 5);` 里那个 `a =` 不是多余的，它就是「把改好的那份返回赋给原处」；写成 `add_points(a, 5);`，名册上那个数一动不动。
- **别急着把 C 的写法判死刑。** 数据少、函数少的时候它确实好用；我们这一课不是拆台，是让你亲眼看见**账是怎么一点一点欠下的**。
:::

## 一句话对照表

| 谁写的 | 函数住在哪儿 | 出手时，谁把学员交对函数 |
|---|---|---|
| C | 类定义外面 | 我们亲手搬：整只抄一份，改完返回 |
| C++ | 类定义里面 | 不用搬，先说哪一个、再调用函数 |
| Java | 类定义里面 | 不用搬，`new` 出一个来调用 |
| Python | 类定义里面 | 不用搬，调用哪一个、哪一个自己动手 |
